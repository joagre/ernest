# Ernest module Test

*Since 0.2.0.*

Tests that `ern test` runs (report Appendix E.24, §11.2). A test is a
top-level `let` of type `Case(m)`, exported or not: its name, and a
function that answers whether it passed, run in a process whose mailbox
type is `m`, so that a test may receive. The module declares the two
types and `equal`, the comparison a test most often makes.

## Examples

```ernest
{
    let adds = Test.Case(name = "adds", run = fn() = Test.equal(1 + 1, 2));
    (adds.run)()
}
// => Passed
```

## Test.Case

```ernest
type Case(m) = Case(name : String, run : () -> Result with m)
```

A test: its name, which `ern test` prints, and the function it runs, in
a process whose mailbox type is `m`; a test that receives nothing leaves
`m` open, and runs with `Never`.

### Examples

```ernest
Test.Case(name = "the empty list is empty",
          run = fn() = if List.isEmpty([]) then Test.Passed else Test.Failed("not empty"))
// => Case(name = "the empty list is empty", run = <function>)
```

## Test.Result

```ernest
type Result = Passed | Failed(String)
```

A test's answer: `Passed`, or `Failed` with what went wrong.

### Examples

```ernest
if 1 + 1 == 2 then Test.Passed else Test.Failed("1 + 1 is not 2")
// => Passed
```

## Test.equal

```ernest
Test.equal(actual : a=!, expected : a=!) : Result needs a.show
```

*Since 0.3.0.*

`Passed` where the actual value equals the expected one, and otherwise
`Failed` naming both as `Io.show` writes them, the expected first:
`expected 3, got 2`. It needs `a.show`, which a call at a known type
supplies without writing it (report §4.9, §9.4). A test that wants
another text writes its own comparison.

### Examples

```ernest
#(Test.equal(List.size([1, 2]), 2), Test.equal(1 + 1, 3))
// => #(Passed, Failed("expected 3, got 2"))
```
