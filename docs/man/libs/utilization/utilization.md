# Ernest module Utilization

*Since 0.4.0.*

How busy this node is, by the host's measures: the processes waiting to
run, the schedulers' time, and the processor, the memory and the disks
the host's services watch.

A program reads its own node's numbers here; how busy a peer is, it asks
with `Peer.utilization`, which each node answers as its own `ernest.conf`
measures it (report §8.7, Appendix E.27).

The library stands on every job's load path, so a program names it with
no option (report Appendix G).

**The host's services.** `cpu`, `memory` and `disk` read the host's
services `cpu_sup`, `memsup` and `disksup`, which a node starts where its
`ernest.conf` names `cpu`, `memory` and `disk` under `measures` (report
§8.7). Where the service does not run, as in a program that is no node,
each answers `None`. `runQueue` and `schedulers` read the runtime itself,
and answer in any program.

## Examples

The processes waiting to run, none or more:

```ernest
Utilization.runQueue() >= 0
// => true
```

A program that is no node runs none of the host's services:

```ernest
#(Utilization.cpu(), Utilization.memory(), Utilization.disk())
// => #(None, None, None)
```

## Utilization.runQueue

```ernest
Utilization.runQueue() : Int
```

The processes ready to run and waiting for a scheduler, over all of the
node's schedulers, as the host counts them at the call. The running ones
are left out, where the node's own `"run-queue"` measure, which
`Peer.utilization` answers by default, counts them too and leaves out the
one measuring (report §8.7).

### Examples

```ernest
Utilization.runQueue() >= 0
// => true
```

## Utilization.schedulers

```ernest
Utilization.schedulers(window : Int) : Float receiving m+
```

The fraction of the schedulers' time spent running processes over a
window of the next `window` milliseconds, from 0.0 to 1.0, which the call
waits for; a window below 1 is 1. The host keeps the schedulers' time
while this measures it, and as long as another process measures too.

### Examples

```ernest
{
    let busy = Utilization.schedulers(10);
    busy >= 0.0 && busy <= 1.0
}
// => true
```

## Utilization.cpu

```ernest
Utilization.cpu() : Optional(Float)
```

The fraction of the processor's time busy, from 0.0 to 1.0, since the
calling process's previous call, by the host's `cpu_sup`, which keeps the
time of each process's call; `None` where the node's `measures` do not run
it. At a process's first call, and its first since the service started
again, the host does not promise the value, which is on most systems the
fraction since the machine started.

### Examples

```ernest
Utilization.cpu()
// => None
```

## Utilization.memory

```ernest
Utilization.memory() : Optional(Float)
```

The fraction of the machine's memory in use, from 0.0 to 1.0, by the
host's `memsup`: what is not available, of the total; `None` where the
node's `measures` do not run it.

### Examples

```ernest
Utilization.memory()
// => None
```

## Utilization.disk

```ernest
Utilization.disk() : Optional(Float)
```

The fraction used of the fullest of the machine's disks, from 0.0 to
1.0, by the host's `disksup`, which reads them every half hour unless
`measures` says otherwise; `None` where the node's `measures` do not run
it.

### Examples

```ernest
Utilization.disk()
// => None
```
