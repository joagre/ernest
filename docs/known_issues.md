# Known issues

What is known to be wrong or missing and not planned: a corner that must be built on purpose to be met, one line each, with how it was met and when. A line becomes an item of [`plan.md`](plan.md) when the user takes it up, and goes when it is fixed. A defect of OTP's that Ernest meets is [`otp_bugs.md`](otp_bugs.md)'s, and what writing Ernest has felt is [`language_feedback.md`](language_feedback.md)'s.

- `ern unpack` removes no leftover of an earlier run where `lib` holds a name that is not UTF-8, since `Fs.list` answers `NotUtf8` for the whole directory (E.17): the job refuses `lib`, writing the error as `Io.show` writes it, and each package it would unpack waits for the name's removal. Read from `Ernest.Unpack` by its build, 2026-11-21 (the log's *An Archive Read by the Host*).
- A run of `ern unpack` ended while it waits for the lock leaves its helper waiting in the host until the first run lets the lock go, when it takes the lock for an instant and exits, since POSIX has no wait on a record lock that also watches the helper's input. Read from `ern_exec`'s `hold` by its build, 2026-11-21 (the log's *An Archive Read by the Host*).
- No test runs the shell at a node that answers an attach `NotLoaded`, which needs a release whose shell calls a module the node lacks; §11.2's line is read from `refusal`. 2026-11-21 (the log's *The Shell Says a Refusal in the Jobs' Words*).
- No test runs the shell where the history's trim fails at start, which needs a full disk or a read-only mount; a test of `Ernest.Shell.History` holds the answer, and the tests of a failed append hold the words. 2026-11-21 (the log's *The Shell Says a Refusal in the Jobs' Words*).
- In the shell, an input that holds a carriage return before a line feed has the two as one grapheme, which the keys that go by an input's lines do not take for a line's end, against §11.2. Only a history file written by hand gives one. Read from `Ernest.Shell.Editor` by its build and not shown, 2026-11-21 (the log's *An Input Edited by Its Lines*).
- In the shell, a window made narrower while an input that wraps stands can leave one stale row above the input, since each terminal wraps again in its own way. Shown in tmux 2026-11-21 (the log's *The Live Region Named Once*; was item 160).
- In the shell, a screen of one row shows nothing under the input, since the input's row takes it, and on a screen of one column the region's erase has no column to move right to, so where the region stands at the screen's top it erases from the corner, which tmux saves to its scrollback. Read from `Ernest.Shell.Region` by its build, 2026-11-21 (the log's *A Window onto the Input*; was item 161).
