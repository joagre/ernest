# Known issues

What is known to be wrong or missing and not planned: a corner that must be built on purpose to be met, one line each, with how it was met and when. A line becomes an item of [`plan.md`](plan.md) when the user takes it up, and goes when it is fixed. A defect of OTP's that Ernest meets is [`otp_bugs.md`](otp_bugs.md)'s, and what writing Ernest has felt is [`language_feedback.md`](language_feedback.md)'s.

- Two processes that close one socket at the same moment: the second `Tcp.close`, its request in the socket's mailbox when the first ends the socket, answers at the socket's end and before the bytes are sent. Read from `ern_tcp:socket_loop/1`, 2026-11-21.
- The host's `ssl:shutdown(Socket, write)` writes no record that ends the connection, so a strict far end reads the connection cut short. Ernest does not call it. Shown against Python's `ssl` and curl on OTP 29.1.2, 2026-11-21.
- `ssl`'s `internal_active_n` is set to 1 for the whole node (`ern_tcp.erl`), so a TLS client of the host's own run inside an Ernest node, as a test may, reads one packet at a time and can miss a close. Shown by a trace of `prim_inet:setopts`, 2026-11-21.
- `ern_os_tests:unopened_node_file_test` fails with `einval` where `TMPDIR` is so long that the test's own Unix socket path passes 108 bytes. Met in a scratch run, 2026-11-21.
- A foreign process on another node than a fault's sender takes the fault as a message, and the report gives that message no term; the code sends two shapes, the cause alone from a check and the whole fault from a fault in `f` (§6.5, §12.2). Shown 2026-11-19 (the log's *A Bad Message's Fault to a Foreign Target*; was MVP 4.5's item 134).
- A listener, and by a reading a socket, meets no fault: after a fault in an adapted address's function over it, or a bad message through its check, the fault stands unread in its mailbox and the run ends with status 0, against §6.5 and §8.4. Shown 2026-11-19 (*Item 135 Stands After the Launch*; was item 135, whose shape was that the resource ends at the fault).
- A wrap's fault in the process kept for an adapted address is lost: on two nodes `f` made a `monitor` whose wrap faults and waited in a call, the kept process ended `Returned` and neither node wrote a fault's line, against §6.9. Two runs, not diagnosed, 2026-11-19 (*Item 136 Stands After the Launch*; was item 136).
- With standard input a directory, or a descriptor not open for reading, `Io.readLine()` and `Io.read()` never answer, where §12.1 has the entry process fault. Shown 2026-11-20 (*A Node's End Waits for No Send*; was item 143).
- A peer that a reload removed is served as a peer until the host closes its connection, which §12.5 states: 2 ms for a sound one, about 84 s for one that stands still, and by a reading without limit for one that keeps sending and reads nothing. Shown 2026-11-20 (*The Disconnect Waits for Nothing*; was item 144).
- A sender held at the distribution buffer's limit, its connection's process idle for about 4.8 s with the rest unsent: 1 poll of 11, of the host alone, seen and not chased, 2026-11-20 (*The Disconnect Waits for Nothing*; was item 145).
- On a node, an `Os.exit` that a process kept for an adapted address calls once the end's wait is over, the flush stalled, is not read: the node ends with status 0, against §8.6. Shown 2026-11-19 (*Item 140 Stands After the Launch*; was item 140, where it was decided that the exit's status stands through a later termination).
- A pid that foreign code gives of a process it was not given: a check's pid is taken to the process behind it on the check's node and to nothing on another, and a check's pid carried to another node, or an invented pid of another node's process, is held as foreign where §8.4 has a bad value. Read from the code 2026-11-20 (*An Address Given Back, on Another Node*; was item 149).
- `Io.show` writes a `Process` that is a check's pid by the check's number, and a pid of a host that is no node of Ernest's by its host's name without its dots, where Appendix E.1 has a key's digest. Read from the code 2026-11-20 (was item 149).
- A `kill` of a `Process` that is a check's pid ends the check and leaves the process, and foreign code that links to a check's pid or exits it ends the check, after which what it sends is lost, a silence §6.2 does not list. Read from the code 2026-11-21 (*The Check Stays a Process*; was item 149).
- A function of the program's that foreign code gives back at another type keeps its check and faults the program's own call, and a `Reply` given back at another type is in no rule of §8.4. The first shown by a probe 2026-11-20 (*What the Boundary Trusts at a Type Variable*; was item 153).
- §8.4 does not say which type a message to a foreign address, or an answer to a foreign `Reply`, crosses at; in the code it is the type foreign code gave it at. Read 2026-11-20 (was item 153).
- An address given at a type variable and given back at an address's type has two outcomes in the code, a bad value for a process's address and the address as it is for an adapted one, against §8.4's promise. Read 2026-11-20 (was item 153).
- Wording: "its parameter's type" in §8.4's **Functions** reads two ways; the result of a function foreign code called is not among what crosses; no promise has foreign code call a function in the calling process; §12.2 does not say how foreign code sends to an address; §8.7's **Calls** names no request through a check. Read 2026-11-20 (was item 153).
- No test holds §8.4's sentence on a call's answer at a type variable; a probe showed a foreign `"text"` taken at `Int`, 2026-11-20 (was item 153).
- A peer's name in `ernest.conf` may hold a control character, which `Io.show` and §12.5's lines write to the terminal as it is. Shown 2026-11-20 (*A Process Printed with a Dot, Built*; was item 151, which recommended that the node refuses such a name where it is read).
- A worker that has taken a connection as a kill ends its listener opens the socket and answers an accept whose caller has faulted; where a restart keeps the caller the socket lives with no address to reach it. Read from the code 2026-11-20 (*The Two Closes Answer*; was item 155).
- `Process.current()` in an adapted address's function is the process kept for the address; sent on and killed, that process ends with the message it was handed. Read from `ern_gateway.erl` 2026-11-21 (*The Check Stays a Process*; was item 157).
- A sole subscriber's restart ends the end's wait, so its new run that subscribes again may not be told, where Appendix E.23 has a restarted run told as a new one. Read from `ern_rt.erl` 2026-11-21 (was item 157).
- Across nodes a `Restarted` can follow the `Down` of a death where the watcher monitors again at once, against §6.9. Read from `ern_rt.erl` 2026-11-21 (was item 157).
- `examples/lease_broker.ern`'s client acts on a call's answer from the broker's new run before it reads the `Restarted` in its mailbox; §6.9's order does not cover a call's answer. Read 2026-11-21 (was item 157).
- `ern_nodes_tests`' `reload_waits_on_no_stopped_peer` failed in one full run of four on 2026-11-21: the maker said the stopped third's loss before the asker's end (*The Close Follows the Last Byte*; was item 159).
- Two behaviors of OTP's that nothing of Ernest's meets and no report holds: `net_kernel:setopts/2` answers `{error, noconnection}` at once on a node's `nodeup`, 40 of 1,000 connections with OTP alone, and `net_kernel:setopts(new, ...)` answers `{error, enotsup}` under TLS distribution. Found 2026-11-17 (*A Connection That Cannot Drain*; was item 103).
- Four sites of the tests read `Peer.utilizations` in a loop with a sleep of the teller's interval, since no message shows that a telling came: `test/fixtures/peers/placing.ern` and three programs in `test/ern_nodes_tests.erl`. Feedback 264, 2026-11-17 (*What a Full Buffer Holds*; was item 5).
- A session typed into a shell in `test/ern_nodes_tests.erl` polls `Process.status` in a loop until another process waits in a call, a busy loop: nothing in the library waits for that. Feedback 269, 2026-11-21 (*A Busy Loop in a Test*; was item 156).
