## The Packages Proposal Swept, 2026-11-23

MVP 4.4's item 4, before its readers start: the proposal under `docs/proposals/package_manager/` read against its owners and removed, as *A Built Proposal's Sweep Is an Item* places it. One reader on Fable 5.2 at high read its four files, about 170 paragraphs, rows and items, of which about 100 agreed with an owner. Four smaller ones no entry named:

**A package's C library.** The rule stands in *A Package and Its Manifest*: a package's `.beam` files travel built, and its C library is built by its own `make`, which the author runs by name. The trial gave the release's shape: `ebin/` and `priv/` at the archive's top without the built library, the C source under `erl/`, and a `host` target that builds it in place. The plan's sentence that the manifests' write was the last to read the proposal held for everything but this, which is kept here.

**What only the proposal held**, kept here:
- A version before 1.0.0 promises nothing, as Go's does and as a release of Ernest before 1.0 does: a package cannot promise more than the language under it.
- No definition's hash is used in a build: a hash says what code is, between nodes, and a manifest says what a build loads.
- The manifest names no version of its own, since `make` reads `VERSION` with `cat` and cannot read JSON.
- §11.1's roots are of `src` alone, since giving every job in a package `src` and `build` would have had `ern build examples` look for `examples` under `src`.
- A package's `.beam` files are compiled on the earliest release of OTP it is meant for, since OTP loads compiled code on at least two later releases and on no earlier one.
- Appendix G's libraries stay in the toolchain: a node's start measured the same with four of them and without.

**What other systems do**, read on 2026-11-09, each from its own documents, so that the rule was chosen against them:
- **Go.** A requirement is a minimum, with no lockfile and no upper bound, a break takes a new path, and a version before 1 promises nothing. The proposal takes each. It differs in one thing: Go's tool walks the graph and takes the highest minimum, where Ernest's root writes each version itself and is refused where one is too early.
- **Elm.** An application names exact versions, and its file is its own lock, which the root's manifest is. Elm holds a version to the interface by comparing it; Ernest's checker refuses a broken interface where the root builds it, and a tool that numbered versions would be a second judge.
- **Cargo, Hex and npm.** A range, a resolver over an index and a lockfile, and several versions at once. None is taken: what they build depends on the day and on an index, a lockfile says again what a manifest could say, and a namespace of Ernest's has one module (§4.2).
- **A package's code at install.** Cargo runs a build script, and npm blocks a dependency's install scripts by default from version 12. No code of a package runs while it is unpacked or built.
- **Nix.** A fetched source is a URL and a hash, and another hash fails the build. An entry is that pair, the archive's URL and its SHA-256.
