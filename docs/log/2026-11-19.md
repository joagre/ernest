# The decisions log, 2026-11-19

## The Homepage Built, 2026-11-19

MVP 4.6's item 3, built ahead of its milestone by one agent, from the proposal [`proposals/homepage/`](../proposals/homepage/README.md). This entry holds what the build found. The page's reasons stay the proposal's until its milestone's release.

**Built as chosen.** The page measures within a pixel of the mock at every edge. At 1280 wide the claims end at 420, Try it at 716 and the doors at 977, and the figures are the same from 1200 to 2560. At 960 Try it ends at 854 and the doors at 1318.

**The first screen at 1536×730, a narrower promise.** The proposal has that screen hold "the example and Try it", and its own table ends the counter at 732. The built counter's block ends at 731.5, and its code 17 pixels above that. The spaces were tightened to bring the button onto that page (the proposal's reasons, *The tighter spaces*), and the button is on it. So the design note promises the counter's code, the session and Try it there, and the test holds those three. Two pixels were not looked for: a space set by a test's figure is chosen by no reader.

**The stacked parts stretch.** The mock's rule for the narrower page kept the grid's `align-items: start`. In a column that makes each part as wide as its longest line. On a page of 400 the counter's block was 480 wide, and the page scrolled sideways. The build stretches the parts, and the browser's test holds a phone's homepage to no sideways scroll. The mock's phone figures were not made again after the columns were shared, so the mock did not show it.

**The homepage's `main` without a class.** The proposal's `.home main` is written `main:has(> .home-intro)`. A class on `body` would stay behind when a page is put in place of another under the panel, since only `main` is swapped.

**The tools' measure.** A first line reaches the tools where its right edge passes their left edge in the corner. No margin is added, since any would be a chosen number. The script observes each block's `pre` and not the block, so setting the class sets off no new observation. The header beside the panel needed no script: `body.panel-beside` was set already.

**The test measures the page that ships.** The fixture's claims are short, so its homepage's height says nothing of the real one. `make test-browser` writes the repository's own site from the working tree, serves it beside the fixture's, and measures the homepage there. It needs the library's pages, so the target builds `make doc` first. A run takes 11 seconds.

**The read-back's two searches.** `Template.Markup(Html.body(...))` stands at 8 sites of the generator, 2 of them this item's. It stays as it is: the two names say what is made, one site appends to the body before it becomes markup, and a function for the pair would hold nothing. The item wrote no private function.

**A refusal's text.** The generator takes the example's two blocks apart, so a `site/example.md` that does not hold exactly two is refused: `site/example.md does not hold two blocks, the counter's and then the session's`.

**Found, and the user's to decide.** The rule that stacks the example reads the window and not the page's column. With the shell's panel beside the page the example therefore keeps its two columns: in a window of 1440 a block is 362 pixels wide and scrolls sideways, which the proposal had measured. A window of 1168 with a classic scrollbar shows a page of 1105 and not 1120, where the blocks still fit. A container query on the page's column would answer both, and would state the proposal's own sentence, "narrower than its full width", with no figure derived. It waits for the look at the real page, as the plan's item names it.
