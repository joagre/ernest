## A Regex Literal Weighed, 2026-10-26

Proposed, from outside: a literal form for a regular expression, which the compiler compiles as the host's `re` module does, its operations in a standard library module. Weighed apart as two things.

A library, `libs/regex` over the host's `re`, is a library's work by CLAUDE.md's rule for a pattern language, a shim exact by `re`'s page with the pattern language stated as the host has it, and is written when a program asks for one, as MVP 4.1 has every library written, ehttpd's routes the likely asker; nothing of it is a feature of the language.

The literal is refused, by principle 5. What it buys is a pattern's syntax error at build time in place of a `Left` at the first run; the compile-once it would also give, a top-level `let` gives already (§8.5). Against that it costs a token class, a prelude type and a rule of its own, for one library's value alone, which is a concept the language would carry for a library's convenience; Elixir's `~r` sigil pays exactly that, and Gleam, Rust, Erlang and Unison have none. Principle 1 agrees: a reader who knows that an `Int` has a literal and a `Date` does not predicts a `Regex` made as a `Date` is, by a function from a string.

Where a build-time check of a pattern ever matters, the general mechanism is a constant initializer the compiler evaluates, a design of its own that would check every constant and not one kind. Decided with the user, who asked that nothing enter for being good to have.
