**The carrier is Erlang's distribution, 2026-10-06.** This reversed the protocol of Ernest's own that the distribution notes of 2026-09-30 had, a node identity, an intermediate form and a frame checked by its type's hash, which a reader on Erlang's ecosystem had advised: it would give an address bound to its connection, a check before the mailbox, no atoms made by a peer and narrower rights, and it would mean writing the detector, the monitors, the fragmenting and the limits ourselves. An experiment of thirteen steps on OTP 29 showed the host carries Ernest with what hurts turned off: no port mapper, a table answering instead; no mesh; the certificate's name check replaced by a rule that accepts a listed key; the host's own reports of nodes off, but for the cookie's refusal, which happens inside the handshake before any rule of Ernest's runs and would otherwise be seen on neither side. What the host gives is the handshake, the detector, a loss both ends run, an address that outlives a loss, monitors and one-shot replies. Given up and stated: a connected peer can do anything on the node and make atoms, and nothing checks a message before the mailbox. Decided by the first of MVP 3.0's rules, Erlang's process semantics taken whole, principle 1, and by the cost rule, a message between nodes costing the host's send.

**A node is its key, 2026-10-07.** The carrier name is the key's digest and holds no network address, so every node computes the same name for a peer and a node that moves machines keeps its identity. A certificate's dates mean nothing, since the key is the identity and an expiry would stop every program on an anniversary; `ern config` writes the longest validity so that other tools do not complain. `listen` is an interface and `network-address` a destination, and a name is resolved at each dial, so a changed address under a stable name is followed. Port 0 exists so that tests running side by side collide on nothing. `./.ernest` never holds a key, since a key in a working tree is where a commit can take it. Two nodes with one key are one node: refusing a second connection from a name already held would refuse every restart within the detector's 45 to 75 seconds, and a copied directory is a twin neither node can refuse to start, so the limit is made visible, a line each time a connection is replaced, and the mistake made hard, one directory per machine, never copied.

**Peers are a table, read again on hangup, 2026-10-07.** A configuration read only at the start would restart the whole system for a change that touches no code. A signal needs no new channel, only the process's owner can send it, which is the right permission for a node with one owner, and `kill -HUP` works where `ern` is not at hand; the signal carries nothing back, so the node says what it did. `measures` is written in Ernest's words, since an operator's file names Erlang's modules no more than a program does.

**No delay before a dial, and a fixed detector, 2026-10-07.** A delay of Ernest's own would keep a returning peer out of reach for its length, take the dial from the host and need a clock per peer; it protects against hundreds of peers dialing at once, which a few listed nodes are not, and it changes when and not what, so it can come later without breaking a program. The detector is the host's, 60 seconds in four intervals, which counts intervals so that a node that was itself stalled does not lose every peer as it wakes, and a constant, since both ends must agree; the tick, the dial's seven seconds and the buffer are boot flags `ern` sets the same on every node and none is in `ernest.conf`. An adaptive detector, Akka's, keeps a history and a threshold for little gain, finding a failure in seconds with false alarms, where Orleans takes about fifteen. A program that must know sooner puts a time on its calls.

**A loss, 2026-10-07.** Weighed: an address that dies with its connection, E's rule that a broken reference stays broken, against Erlang's held pid, which reaches its process again after reconnecting. Taken: Erlang's, principle 1, so a program writes nothing for a loss; the price is a gap in delivery, stated, and a protocol that must have none numbers its messages or calls. Both ends run the loss, since otherwise one would wait on monitors and calls the other has dropped. The runtime sets no monitor again, which would either say nothing at the loss or give two messages for one call, and would need a dial in the background and every wrap kept; a monitor made while the peer is out of reach answers once the dial fails, so a loop that monitors again is paced by the dial. `Unreachable` is a reason of its own, since a watcher must tell an unreachable process from a fault, the process may live on and a replacement makes two; a one-node program pays a match clause for it, accepted, since a second kind of `Down` for remote processes would let a process know where an address leads. An election or a lease is an engine, a library's, principle 5: Orleans kills a live silo, Akka needs a downing resolver and Erlang's `global` guesses, each showing two owners after a guess. One connection carries both ways and the node that can dial reopens it; a peer with no address is never dialed, so no dial hangs; the host calls a node without a listener hidden, so the gateway watches nodes of every kind.

**An address is the permission to kill, across nodes too, 2026-10-07.** The capability systems give a send-only reference; Erlang's rule was kept, since a process need not know where an address leads, for `kill` as for `send`, since the carrier could keep no narrower promise, and since refusing a kill across nodes would take from a spawner the means to stop its worker. A send-only address is a process in front of the service, which a program writes today.

**A sender waits, as the host has it, 2026-10-07.** Rejected: Akka's queue that drops one message, which breaks "never dropped alone"; a send that never waits and ends the connection when the buffer is full, where one fast producer would end every monitor and call between two nodes; a buffer limit of Ernest's own. **A call's `None` has one meaning, 2026-10-07.** It already covers a timeout and a callee that ended on one node; "never sent" is knowable only where no connection opened at all; a request that may be sent again must be harmless anyway; splitting the cases would change `Address.call`'s type or give remote calls a call of their own, and reveal where an address leads; a monitor's `Down` gives the reason to a program that wants it. A spawn and a find answer a value and take a time, since a peer out of reach is no mistake of the program's and a process that faults can do nothing about it, and without a time a spawner would wait 45 to 75 seconds, or forever behind a gateway held up by a slow function; `NotLoaded` is a value though the mistake is the program's, since the spawner cannot know which entry point the peer runs and can choose another peer; a late answer kills the process it names, so that nothing runs that nobody can reach.

**A service is found by a typed key the node offers, 2026-10-07.** This reversed *A Peer's Service Is Found Through Its Binding*: shipping a function to read a binding made the client depend on the service's module, run its bindings and start a service of its own, crossed a function only to look something up, the first thing to break where builds differ, and opened every binding to every peer. Only a process of the offering node may be offered, since a third node's process may be on a node the finder does not list. Where a service lives is the configuration's, so that the operator moves a program by editing `ernest.conf` and a node name in the source would need a rebuild for a move that touched no code; the listed peers are asked in order, so that the list's order decides between two offering by mistake, and not the faster answer.

**What cannot cross is refused at compile time, and nothing is walked, 2026-10-07.** Every send across nodes is typed as a local one is, so a message carries no hash and bypasses the gateway; a hash would only catch a peer that lies, which can do anything else. Walking a value before a send would cost a multiple of the host's send and test at run time what the checker knows, which is why an adapted address's captures cross as an opaque payload. An encoding of Ernest's own, a constructor by its position and no atoms on the wire, was set aside, since it would be written in Erlang value by value; another host or a measured need would reopen it. One gateway per node, 2026-10-08: the frame that opens a connection arrives before the accepting node has seen the peer come up, and the host drops a message to a registered name that does not exist yet on a remote node, so a gateway per peer would miss that frame and the finder would wait out its time.

**The cookie, 2026-10-07 and 2026-10-08.** The check sits inside the handshake because a plain message goes straight to a mailbox and any check after the handshake would race it; the cookie keeps no secret, the key does; a refused handshake is `Unreachable` to the dialer, since the host reports every failed handshake as no connection. **A binding belongs to its node, 2026-10-07.** An initializer may spawn, send and call, and the types do not tell a constant from a service, so a node evaluates nothing because a peer asked; a value to carry from the spawner is bound to a local first and captured, so the text alone shows what crosses.
