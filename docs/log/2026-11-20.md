## A Literal Binary Grown in Place, 2026-11-20

The host's segmentation fault in the typed programs, watched for since 2026-11-08 (*The Items Left Read Again*), came with its core in a full run of item 147's close. The user left every decision on it to the session. It is found, worked around and written as `docs/otp_bugs.md`'s report 27, by one agent. The report is unchanged.

**The defect is OTP's.** Its compiler, 10.0.7 on OTP 29.1.2, rewrites a binary's append to the append in place, `private_append`, where the binary appended to is the `<<>>` of a literal tuple. Its destructive update pass means to replace such a literal by a writable binary, and has no clause for a literal tuple, so the literal stays. The emulator then reads the literal as a writable binary, checks it by an assertion alone, and ends on what follows it in memory: a segmentation fault, or a refused allocation of 21 terabytes.

**From the core to two lines.** The core named the function through OTP's `etp-commands`, `ern@generated:'$5'/0`. Nothing marks a module this defect reaches, since it compiles and ends the host only when it runs. A narrower promise was weighed first and is no answer: it would have the report say that a well-typed program may end its host, which surprises any reader (§0, principle 1).
