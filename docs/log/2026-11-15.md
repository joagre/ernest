## A Refusal Holds No Control Character, 2026-11-15

MVP 4.17's item 49, decided with the user. *The Trust Said Once* put the guard where a path is written, and the item first asked whether one function writes it.

**The survey.** None does. A path's text is made by `ern_build:shown/1` at some eighty sites and joined into a message at some twenty more, and thirteen routes carry it to the terminal, eleven of them raw. `shown/1` cannot hold the guard, since what it gives is what the job opens (§11).

**At the refusal, not at the path.** A guard at each path is a rule for each place, and each new refusal would have to remember it. Whoever names a file in a tree a user builds can most often ship its source too, so this is a robustness fix, one guard at the cause (*A Defense Names Its Attacker*). The cause is a refusal's finished text. So the rule is wider than a path: a refusal holds no control character, whether one came in a path, in a word of the command line or in a text read from a file. A reader who knows *No Control Character Reaches the Terminal Unasked* predicts it (principle 1). That entry did not take escaping every line the toolchain writes, for the shell's styling. This guard stands on the text before it is styled.

**Outside a refusal.** A diagnostic's lines after its first and the shell's screen hold line feeds and colors on purpose. There the path alone is guarded, and §11 names the places: a `--verbose` line, an error's first line, a line of `ern format --check`, and what the shell says. The sentence first said every line on standard output or standard error. It was narrowed to the four, since `ern doc` writes a page's last line there with the source's path as `\u{1B}`, and that line waits in the plan's item 54.

**The characters and the form.** Every control character of §2.1 is written, a tab and a line feed among them, the set a fault's cause is escaped by. Each byte of its UTF-8 is `\xHH`, so that `\xHH` names a byte wherever it stands, and a name that is not UTF-8 writes its control bytes so too, where it wrote them raw. A fault's cause keeps the escape a literal writes, since it is an Ernest value. A backslash stays itself, as it did in a name that is not UTF-8. So the promise is the narrow one: the text is safe to show, and is no spelling to read back.

**The build.** `ern_build:control_free/1` writes a text so. It stands where a refusal is made, in `fail/1`, `usage_fail/1`, `refuse/2` and the manifest's lines, and `verbose/2` writes its whole line through it. A path outside a refusal goes through `ern_build:path_text/1`, the file as `shown/1` names it written so: each caller that gives a diagnostic its file, the `--check` line, a doc example's lines and the shell's front end. The guard does not stand in `src/shared`, which is beneath every stage, so a diagnostic is given its file already written. The shell's Ernest writes its own strings through `controlFree`, beside `escaped`. No rule of E.0 admits it, since it is the toolchain's convention for its own lines.

**What the build found.** The shell's front end read a startup file's name as Latin-1, so a name past ASCII was written twice encoded and its source was looked for under another name. It is read as UTF-8. The attached shell's end wrote a fault's cause raw, against §11.2, and writes it through `escaped`; no test holds that line, since the one test that reaches it gives a cause of the shell's own. Base 16 is written at three sites of the repository's Ernest, each with a default or a fault for a `None` that does not come, feedback 253.

**The tests.** Ten were written with the code, and each failed with the guard taken out: a job's refusal, a usage refusal and the one before a job, a name that is not UTF-8, a manifest's refusal, an error's first line in directory mode, a `--verbose` line, the `--check` line, and in the shell the history's line at a terminal, `:load` and `:output`, and a startup file's lines. Not covered: a node's reload line, the attach refusal and a doc example's failure, which were probed.
