## Context Is the Cost, 2026-11-06

The way of working changed after seven weeks of this project's session logs were read, against published practice. CLAUDE.md's *The repository* holds the result. The figures and the models' names stay out of this repository.

Most of the cost was context, re-read and written back to the cache on each request, and output was the small part. Within a session, more effort cost little per request. So the savings were sought in shorter sessions and agents, and the thinking stays strong, which is what the work wants: an error that becomes a bug or a failed test costs more than the tokens.

For the same reason a stronger model cost well under what its token price suggests, and a cheaper tier would save little, since cache reads cost about the same on it. A rule it missed would then be redone by a stronger session. So no cheaper tier was adopted for builds, against the common advice, which assumes output is most of the bill. The smallest model is used only for a search that asks no judgment.

Strength goes where no test catches the error. A wrong line fails a test, while a wrong soundness argument or report sentence gets built on. Such work needs the discussion's context and the user, which an agent lacks, so the choice is made per session and not per agent.

Published measurements say an agent pays only where there is bulk to hand off, and that a dependent chain in one context costs more through one. So an agent is now started for a reason: the discussion goes on, the output is bulky, a reader must be independent, or work runs side by side.

The logs do not record whether a build was right, so this is unmeasured on quality. They are read again at the end of MVP 4.15. If item sessions start missing things they move to the stronger model, and only a measured gain moves anything down.

## A Wait Collects, 2026-11-06

MVP 4.15's item 2. A process that drops a binary and waits holds it until its next collection, which the host runs only as the process allocates (§10). The plan had the runtime ask the host for the process's counts before a `receive` waits, and collect where the binaries passed `min_bin_vheap_size`. Built and measured, that was wrong twice, and the item's purpose stands on another mechanism.

**Its reach.** The server's idle connection does not wait in a compiled `receive`. It waits in `Tcp.read`, a call in the runtime. The same response is also held by the socket's process, by its writer and, over TLS, by the host's own process of the connection. The check must stand at every wait that holds a program's bytes.

**Its cost.** The count is `process_info`'s `garbage_collection_info`, about 700 ns against a wait's 250 ns. A map server's round trip went from 516 to 1306 ns, and the plan's own fallback then sends the design away.

**The rule.** A wait first waits the host's shortest timer, a millisecond, since asking and waking cost about a microsecond. A receive that takes a message at once pays nothing, and a shorter wait pays the timer. A wait that reaches the millisecond counts, and collects whole where its mailbox is empty and the binaries it references, above the fewest counted since its last such collection, pass both `min_bin_vheap_size` and the words of its heap. Principle 5 decided: the host's timer and the host's collection, nothing kept beside them but one number in the process's dictionary.

**The gates.** The mailbox gate stands because a message that arrived as the timer fired counts as live, and it left 15% of the writers holding their bytes when it was missing. The heap gate stands because a collection costs in proportion to the heap. The floor stands so that a process that keeps its binaries pays once.

**TLS.** The host's process of a connection is not the runtime's to change, and it held 2 MiB a connection.
