## The Flake of `os_signal_after_an_unread_exit_test`, 2026-11-10

MVP 4.15's item 45, found by item 43's `make test-full` (*A Compiled Module the Host Cannot Load*). The test signals a program whose shell has exited once the shell's child says `gone`, which the child says on reading the end of a pipe the shell held. It held `Left(Io.Closed)`, and one full run in two saw `Right(Unit)`.

**The cause.** The host closes an exiting process's files before it reports the exit: Linux's `do_exit` closes them before `exit_notify` makes the process one its parent can wait for. So the child can read the pipe's end and say `gone` while the shell is still exiting. The helper's `waitid` then finds no exit, and sends the signal to a shell that takes none any longer.

A probe in C ran the test's shell and asked `waitid` on reading `gone`, as the helper asks. Idle, it found the exit not yet reported in none of 2,000 runs. Beside 48 busy loops on nike's 24 threads it did so in 3 of 3,000. The test itself failed none of 50 runs idle, and one of 2,000 beside the loops, with the flake's output.

**The runtime did what the report says, and the fault was the test's.** E.23 answers `Left(Closed)` once the program has exited, and the helper asks the host whether it has, as *The signal* (2026-11-07) has it. The test took the end of a pipe the program held for its exit.

**Decided: no sentence in the report.** "Has exited" is the host's exit, as the host reports it to the program's parent. A signal sent as a program exits races the exit on every host, and Ernest answers as the host does. Principle 1 decides: the report states a departure from what the reader predicts, and here Ernest departs from nothing.

**The fix.** The test sends the signal until it answers `Closed`. Each one sent before reaches the exiting shell, which takes none, and the shell's status of 0 shows it. No read asks for the exit meanwhile, so none takes it.

A copy that counts the signals before `Closed` ran 2,000 times beside the 48 loops, in four hosts, and passed every run with no signal before `Closed`. **Found: a write and a resize after the exit.** A probe of the same shape found that E.23's two other answers to an exited program are not built where a process the program started holds what they reach.
