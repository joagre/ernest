# The decisions log, 2026-10-27

## `<-` at the Prompt, 2026-10-27

The front page's transcript spawns the counter on `foo` and counts on it from the shell. `Peer.spawn` answers an `Either`, and the prompt refused `let far <- ...`, so the transcript took the address out with a `match` over four lines, the first thing a reader of the repository meets. A bare `Peer.spawn` would answer `Right(<address 7>)`, which nothing can be sent to, and the sends are the point.

**Decided with the user: the prompt takes `let p <- e`** (§11.2). It takes `e` apart as §5.5 does in a block, the session standing for the block's rest. On `Right(v)` or `Some(v)` the pattern binds `v`. On `Left(err)` or `None` it binds nothing, and the input shows the value as an expression's is shown; `it` is unchanged, since the input is a `let`.

**Why.** `<-` is the one way Ernest has to take the value out of a `Right` (principle 2). An unwrap that faults on `Left` stays out, by E.0 rule 4 and *`Int.pow` Keeps Its `Optional`*. A reader who knows `<-` in a block predicts it at the prompt, and the refusal of a statement a block takes was the surprise (principle 1). The refusal of 2026-09-24 had a technical reason, no block to end, and weighed no principle. The session goes on after a `Left` as it goes on after a `let` that faulted, a later use of the name finding nothing.

No type rule changes: the input is checked as a block's `let p <- e` is, its `e` an `Either` or an `Optional`, so the soundness argument's paragraph on the shell's sessions stands.

## The Shell Does Not Indent, 2026-10-27

Whether the shell should indent a line it takes after an unfinished input, as an editor does, was weighed after the front page's spawn was typed over four lines. Dropped.

**What it would be.** Three rules would give most of `ern format`'s layout. A new row would start four spaces in for each bracket left open. A closing bracket or a match's `|` typed first on a row would move back. A row ending unfinished outside brackets would indent the next one step. Tab would stay as §11.2 has it, completing a name and giving four spaces at the start of a row.

**Why not.** A long input reaches the shell mostly by paste, which keeps its own indentation, so the shell would have to stand aside for a paste or indent it twice. A `match` typed by hand is served by Tab at the start of a row. A longer program is written in a file, which the Emacs mode indents, and is loaded. The three rules would have to follow the layout as it changes, or the shell would indent almost as the formatter does and differ in a corner, which surprises more than no indentation (principle 1).

## Small Library Functions Stay Calls, 2026-10-27

MVP 3.96's item 10, decided by its first question, whether it was generic or a micro-optimization, measured by an agent on Opus 5.5 under OTP's `tprof` over the bench's programs, each built and run as the bench runs it.

**What a call costs.** A remote call of a small function costs about 5 to 7 ns more than its body written in place, in Erlang and in Ernest alike: `Int.max` 3.3 to 6.5 ns, `Char.isAsciiDigit` 5 to 7.5. A remote call against a local one costs well under a nanosecond, so only writing the body in place would save time.

**What the programs pay.** The counter calls the library 18 times and gains nothing. The parser makes about 530,000 calls of small library functions from its own code, `Char.isAsciiDigit` the most, about 3% of its time, which a hand-inlined copy did not lift above the noise; another 560,000 are `Char` predicates passed as values to `List.span`, which no call-site inlining reaches. The ray tracer makes about 1.46 million, `Float.sqrt`, `round`, `min`, `max` and `pow`, about 5%, which a hand-inlined copy confirmed. Only the mixer, built to stress these calls, gains 60 to 75%.

**Decided: dropped.** The gain on ordinary programs is a few percent, and an Erlang program pays the same, since OTP's compiler inlines nothing across modules. A design for which functions count as small, how a trace shows them and how a hash covers what it inlined would cost more than it buys, and a special case for the shifts stays refused. The plain form's cost, recorded: a small library function called from another unit, 5 to 7 ns a call, 3 to 5% of the parser and the ray tracer, nothing of the counter, and the mixer 2.6 times Erlang.

## The Emitter's Calls Against the Host's, Built, 2026-10-27

MVP 3.96's item 9, built by an agent on Opus 5.5 to the shape the entry below decided.

**What a call is now.** A call of a standard library shim, written or through a pipe, is the host's function at the call site, inside the `try` that names the foreign function, and the declaration's own function stays for a function value of it. The interface of a standard library module holds each exported foreign declaration's host module and function, its `shims`, which the link carries to the call site. An arrival links the library's names through the same environment, so a definition compiled on a peer calls the same host function. `compare` at `Int`, `Float`, `String` and `Char` is the host's comparison, written with the `<` and `>` the type modules' own `compare` uses. A program's foreign functions and a library's are untouched.

**The table.** Twelve host functions are called with no `try`, since none raises at the types the library declares it at: `band`, `bor`, `bxor`, `byte_size`, `map_size`, `length`, `trunc`, `floor`, `ceil`, `binary_to_list`, `integer_to_binary/1` and `iolist_to_binary/1`. A test holds the table to every declaration over one, so a declaration added at another type fails it. `bsr`, `list_to_binary`, `binary_to_atom` and `integer_to_binary/2` raise on values their types allow and keep the `try`.

**Two things the build found.** A `try` around the call took in its arguments, so a fault met evaluating one, a `Float` overflow in `Float.toString(x * y)`, was reported as the shim's raise; `float_fault_test` found it. An argument that is not a variable or a literal is now bound before the `try`.

A private foreign function of the library that its own unit calls only by name became a function nothing calls, which Dialyzer named in `make test-full`; the unit now leaves it out, and keeps one its code takes as a value.

The trace of a raise in a shim lost the library's frame, `Foreign.atom:143`, and shows the host's function above the frame of the program's that called it, at the call's line, a frame the `try` keeps even where the call was the caller's last. E.21 now says so. The deadlock look reads the top frame, which is the host's function whether the wrapper or the call site called it, so it reads what it read.

**The interface's format** goes from 10 to 11, since the interface's tuple gained a field: an older `.erc` reads as another compiler's and is built again, as §11.1 says. The floor does not change. The library's code agrees by it already, and a development build's digest changes with its code.

**Measured**, the old toolchain and the new built side by side and run in turn, the median of eleven. The mixer takes 749 to 751 ms against 1,278 to 1,284, and the Erlang mixer 293 on the same machine. The tree, which calls no shim, takes 864 to 873 against 872 to 876. A loop of five million takes 40 ms of `Bytes.size` against 64, and 17 of `compare` at `Int` against 48; `String.size` takes 1,433 against 1,430, the work being `string:length`'s.

In `make bench`, the language part's derived compare goes from 1.51 to 1.04 times Erlang and `compare` at `Int` from 0.99 to 0.62; the core part's `Bytes.size` from 1.28 to 1.00, `compare` at `Int` from 1.18 to 1.03 and at `String` from 0.95 to 0.29. `Map.get` stays at 2.0, an Ernest function of the library over its shim, called across units.

**What stays.** The mixer is still 2.6 times Erlang, since `Int.shiftLeft` and `Int.shiftRight` are Ernest functions of `Int` over a shim, `max(count, 0)` closing the difference for a count below zero, and a call of one crosses units, which the decision keeps as a call, OTP inlining none across modules either.

## The Emitter's Calls Against the Host's, 2026-10-27

MVP 3.96's item 9 analyzed, its shape for the build (the plan's item 9).

**The cause, measured.** A standard library shim is a function of its own unit, `try` around the host's call, so that a raise becomes §12.3's fault naming the foreign function, and a caller in another unit reaches it by a remote call. The mixer in plain Erlang written in that shape takes 1,252 to 1,268 ms, Ernest's own 1,191 to 1,223, against 290 to 294 written direct; with each bitwise operation a remote call to a wrapper with no `try` it takes 822 to 857. So the remote calls are two thirds of the gap and the `try`s with the shifts' extra calls the rest, and dropping the `try` alone would recover a third.

**The classes.** The standard library has 146 shims by their host module: 17 over `erlang`, 23 over the runtime, 15 over `ern_string`, 13 over `ern_set`, 11 over `maps` and the rest over a dozen more. A shim over a BIF the host compiles to an instruction loses the instruction as well as paying the call; `Bytes.size` over `byte_size` is 1.3 times the host in the bench for that reason. A shim over another host function pays a second call. `compare` at `Int`, 1.3 times, is the emitter calling the `Int` module's `compare`, an Ernest function in another unit. Two of the bench's slow rows are rules' costs and stay: `self` reads the process dictionary in a remote call, since a wrap's `self` is its recipient's (§6.5), and `Float.*` adds `+ 0.0`, since a product is never negative zero (§3.1).

**The decision for the build.** A call site keeps the wrapper's `try`, so that no fault changes its cause, but for an emitter's table of BIFs that cannot raise on their declared types, as `band` of two `Int`s cannot. The interface gains each standard library foreign declaration's host function, the one fact a dependent's call site lacks today; the standard library's code agrees by the floor (§8.7), so a host function written at a call site cannot drift from the shim it replaces.

## The BEAM Opcode Experiment, 2026-10-27

An experiment for MVP 4.4, run with the user, written up in `docs/proposals/beam_op_codes/`: two programs, Ackermann and a loop of bitwise arithmetic calling four small functions, each in Erlang, in Ernest and as hand-written BEAM assembly, once with BEAM's convention that a caller saves its registers across a call and once with a callee saving them.

What it found for MVP 4.4 stays in the proposal until it is decided: typed registers bought a fifth on Ackermann, where OTP's inference proves no range, and nothing on the loop, where it proves them all; and the callee's saving bought at most a few percent, in the case built for it, against the validator, the collector's soundness and the debugger, so BEAM's convention is the one to keep.

What it found outside MVP 4.4 is a defect of today's emitter, MVP 3.96's item 9: the loop runs four times slower in Ernest than in Erlang, 1,197 ms against 292 for ten million iterations, since a call of `Int.bitAnd` and its kin, `foreign fn` shims over `erlang:band/2`, is compiled as a call into the `Int` unit and not as the host's instruction, against CLAUDE.md's rule that such a shim runs at the host's speed. Ackermann, which uses only `+`, `-` and `==`, ran 15% faster in Ernest than in Erlang, and the tree interpreter 10%, each pair timing itself the same way.
