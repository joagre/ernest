64. **A record of operations cannot hold a polymorphic operation** (2026-09-28). A contract written as a record of functions, `SetOps(s, a)`, cannot hold `Set.foldLeft`: the field `fold : (s, b, (b, a) -> b) -> b` is refused, `type variable b is not a parameter of the type`. An effect variable may be a parameter of the record, but one record value then fixes one effect for all its operations. A Haskell class method and a Java generic method are polymorphic in such a variable, and nine of `Set`'s twenty functions mention one besides the set and its element, so it bites principle 1 where the contract is to stand for a library type. The choices: a field's type quantifies the variables the type does not take, as OCaml's polymorphic record fields do, checked where the record is built and instantiated where a field is selected, so that inference stays Hindley-Milner's; or the verdict that a contract holds what its types close over, the rest written over its `toList`. The first is much smaller than type classes, with no instance resolution, no constraint in an inferred type and no hidden argument, and it still puts a type scheme inside a type declaration, where the log's *Dropped from Unison* drops rank-n types. A field's own variable carries no inferred restriction, since none is written, so a value that needs one, `==` on it, does not fit the field. `map` and `filterMap` need a representation for the result's element, which neither choice gives, as neither Haskell's `Data.Set` nor Java's `Set` has one. MVP 2.97 waits on it.

67. **A `///` after code documents what follows it** (2026-09-28). §2.2 makes `///` a doc comment wherever it stands, and a doc block documents the declaration, constructor or field it immediately precedes. So `At(/// across` above `x : Int` documents the field `x`, a form the emitter's `docs_chunk_test` pins; and `let x = 1 /// note` above `export let y` makes "note" the first line of `y`'s page, which a reader who wrote a note on `x` would not predict (principle 1). `ern format` stops with an internal error on such a `///` (C17), whose fix depends on the answer. The choices: an ordinary comment after a token, which silently drops the compact field form's documentation; an error, `///` after a token refused with a help naming `//` for a note and a line of its own for a doc, one way each (principle 2), and nothing reinterpreted silently; or the rule as it stands, which the formatter then keeps as written. Recommended: the error.
