# Language feedback

What writing Ernest has felt against the principles, and what a reader found that questions a rule of the language rather than showing a defect (CLAUDE.md, *Defects and gaps*). An entry stays until a plan item decides it: a report change, an item of a milestone, or a line in the log saying it was dropped and why. An entry keeps its number, which the plan, the log and the code cite; the next is 219.

- **206**, 2026-11-02, text from bytes with what is not UTF-8 shown as U+FFFD: the terminal harness, `test/fixtures/pty/pty.ern`, renders what a program wrote, which may hold or cut bytes that are no character, and decodes it a character at a time over the bit syntax, `<<char:utf8, rest:bytes>>` and `<<_, rest:bytes>>` for U+FFFD, since `String.fromUtf8` answers `None` for the whole. The same decoding stands in Erlang in `ern_diagnostic:decoded/1`, for a source line a diagnostic shows, and in `ern_shell:decoded/2` behind the shell's `foreign fn decoded`, for a program's write in the region. Three writings of one operation, one behind a `foreign fn`; against principle 2. Whether it is the standard library's is E.0's question, and its sentence would state the choice, a U+FFFD a byte, as all three do, or one for each maximal subpart, as Unicode's practice gives. Felt as the harness was built.
- **207**, 2026-11-02, a program's environment and working directory: `Os.Command` has a program, its arguments and its input, so an editor under `Os.startTerminal` that needs `TERM`, or a program that must run in another directory, is started through `env` or `sh -c 'cd ...'` in the arguments, a workaround in place of two fields. Against principle 3; felt by the release review's reader of the standard library (E3-22).
- **208**, 2026-11-02, nothing closes what a block opened on every way out of it: `examples/fetch.ern`'s `fetched` closes its socket only on success, each earlier `<-` that answers `Left` leaving without, so a server that copies it keeps a socket for each failed fetch until its process ends; the correct form nests each step or spawns a process for the socket. Felt by the review's reader (E3-23).
- **209**, 2026-11-02, a monitored worker's result or its end: a worker that returns sends its result and its `Down` comes in either order, so each waiter passes over `Down(reason = Returned)`, records another end and takes the result, at five sites: the guide's §4.4, §5.2, §5.6 and §6.4, and the newcomer's program. No form runs a function monitored and answers its value or its end. Felt by the review's newcomer (N16).
- **210**, 2026-11-02, two examples parse a published specification by hand and get it wrong: `fetch.ern` a URL's authority, which ends only at `/` and takes no IPv6 literal (RFC 3986), and `web_server.ern` a `Cookie` header, cut at its first `=` (RFC 6265); `libs/http` has no target decoding and no chunked encoder, so a streaming server writes the framing by hand. The plan's `libs/uri`. Felt by the review's readers (E3-21, E4-22).
- **211**, 2026-11-02, a test's scratch and a failure's difference: no function of `Fs` or `Os` gives a temporary directory, so a test's fixtures go into the working directory and a second run meets `Exists`; and `Test.equal`'s failure prints two values of hundreds of characters with no difference marked. Felt by the review's newcomer (N15).
- **212**, 2026-11-02, a one-armed `if` for an effect: `if ending == Closes then Tcp.close(client) else Unit` and `if ... then fault(...) else Unit`, since an `if` has no form without `else`, at 8 sites of the repository's Ernest. Felt by three readers of the review (E4-28, N20, L).
- **213**, 2026-11-02, `kill` takes an `Address` where `monitor` takes a `Process`: `monitor(b, Gone)` with `b : Address(Never)` is refused, and `Process.fromAddress` stands between. Felt by the review's cold reader (K).
- **214**, 2026-11-03, a slice to the end: `String.slice(x, i, String.size(x))` and `Bytes.slice(b, i, Bytes.size(b))` stand at 23 sites, 16 of `String` (the shell's modules 11, `libs/markdown` 3, `fetch.ern` 2) and 7 of `Bytes`, where `List` has `drop` for the same; `String` and `Bytes` have nothing. Against principle 5; found by the release review's fix agent as it read the sites.
- **215**, 2026-11-03, a search for a carriage return: `String.contains(value, "\r")` finds no carriage return inside `"\r\n"`, since E.5 searches by whole graphemes and the pair is one, so a program checking a header's value for control characters writes the natural thing and is silently wrong; `libs/http`'s renderers read code points instead. E.5's rule, stated; felt by the release review's fix agent as it built G.11's refusals.
- **216**, 2026-11-03, a shown value's one line: `Io.show` writes a constructor outside the prelude with its module's name now, so a doc example's `// =>` line, which shape rule 6 keeps to one line under 100 columns, grew at 67 sites and five examples were reshaped to fit, a `Json.Value` and `Time`'s epoch split in two among them. Felt by the release review's fix agent; the rule is the page's and the width the style's.
- **217**, 2026-11-03, a reach into a library the peer holds: a program's lambda that names `Ansi.clearScreen`, spawned on a bare node whose own tree holds `libs/ansi`, answers `Left(Io.NotLoaded)`, the node saying the binding has no value there, since a program's reach crosses as forms and a binding that is no constant does not cross (§8.7), while §12.7 loads a toolchain-owned unit from the peer's tree only where the spawned function's own unit is the toolchain's. A reader who knows the peer holds the library predicts it serves (principle 1). Found by the release review's fix agent as the nodes test `own_units` lost its point to §4.2 and was dropped.
- **218**, 2026-11-03, no ascription on an expression: a probe that needed a `Peer.Service(Int)` as an argument could not write `Peer.service("x") : Peer.Service(Int)`, a parse error, and declared a top-level `let` to give the value its type. Felt by the release review's round reader; whether an ascription is a second way of what a `let`'s type does is principle 2's question.
