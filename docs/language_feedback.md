97. **A previous version's values are made only by what was kept from before the reload** (2026-10-10, MVP 3.1's item 5, `test/ern_shell_tests.erl`'s `reload_keeps_the_type_checked_under`). After a `:reload` changes `Counter.Msg`, a binding of the previous version's type takes only a message of that version, whose constructors are `Counter$1.Inc`, a name no input writes, since `$` marks a name the session made (§11.2). So a message for the previous version's process is made by a function kept from before the reload, `let inc = Counter.Inc`, or one an input declared then; a user who kept none cannot make one, though the process runs and its constructors print. Two versions as two types is the rule (claim 3 of `mvp3.1.md`); what feels against principle 3 is a type whose values the session shows and cannot write. Weighed for: a previous version's constructors writable at the prompt alone. Stands as MVP 4.3's decision.

98. **`:processes` shows two versions' processes alike** (2026-10-10, MVP 3.1's item 5). A reload's service runs beside the previous version's, and both are listed by their spawn site, `Counter.service:5`, the spawner's words, which are the same in both versions; which version a process runs is invisible at the prompt, where the session tells the versions' types apart by `Counter$1`. Weighed for: `:processes` naming the version of the unit a process runs, which the host's report of its current function gives. Half decided 2026-10-10 with MVP 3.1's read (W17): a reload's version's spawn sites carry the number, `Counter$2.service:5`, so the end's lines tell the versions apart; `:processes` naming the version in a column of its own stands as MVP 4.3's decision.
