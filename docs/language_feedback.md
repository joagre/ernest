# Language feedback

What writing Ernest has felt against the principles, and what a reader found that questions a rule of the language rather than showing a defect (CLAUDE.md, *The work*). An entry stays until a plan item decides it: a report change, an item of a milestone, a line of [`known_issues.md`](known_issues.md) where only a test or a built corner meets it, or a line in the log saying it was dropped and why. A dropped entry carries no condition: its need comes back as an entry when it is met in use again. An entry keeps its number, which the plan, the log and the code cite; the next is 342.

260. **`Fs` has no way to make a write reach the disk before it answers.** `Fs.write` is the host's `file:write_file`, which calls no sync, and E.17 promises of `rename` what a reader of the path sees, not what a power loss leaves. A program that keeps data across a power loss cannot be written in Ernest. The host has `file:sync/1` and `file:datasync/1`, so E.0 rule 1 admits the operation and rule 4 does not refuse it: the question is its shape. Two facts for it: `Fs` has paths and no open file, where the host's sync takes an open file; and a write that survives needs the file synced and, after the rename, its directory. Found 2026-11-17 by a reading of the guide's kept count (the log's *The Outside Reviews Read*); the plan's MVP 4.5, item 96.

261. **`Tcp` hands no listener to another process, and no second listen stands beside a live one.** `Tcp.give` moves a connection's socket and nothing moves a listener's, and `Tcp.listen` answers that the port is taken while a listener holds it (E.18). A program that takes new code while it serves therefore closes its old listener before the new one listens, and connections are refused between. The host has both: `gen_tcp:controlling_process/2` takes a listening socket, and the kernel's option to share a port lets a second listen stand. Found 2026-11-17 by ernest-httpd's session, asked what new code under traffic would take (the log's *The Server's Answers*); the plan's MVP 4.5, item 4.

265. **An address given to foreign code keeps a process until its target ends, one for each distinct address.** §8.4 has one check for each distinct address that has crossed, lasting until the process the address names ends, and an adapted address is distinct by its function and by what the function captured. A server that gives a foreign function a fresh `adapted(self(), fn(v) = Got(id, v))` for each request keeps a process, with what the function captured, for each request while it lives. §10 states the process. Read from the code and not measured. It questions §8.4's life of a check: memory that grows with a server's requests and goes only at the server's end. Found 2026-11-18 by the cold reading of item 111's sentences (the log's *A Checker Acts for the Target*); the plan's MVP 4.5, item 113.

270. **Nothing ends a socket and drops what its host holds.** After a `Tcp.close` or a kill the bytes the host holds go on to the far end, for 5 seconds without progress or up to 3 minutes with a trickle (E.18). A server that gives a client up at a write past its deadline frees its own slot and keeps the host's megabytes and descriptor outside its caps: on 0.10.0 three waves of 16 clients that read 4 kB a second took ernest-httpd's node from 107 MiB resident to 225. The ask: a function of `Tcp` that ends a socket at once and drops what its host holds, the far end reading a reset. Found 2026-11-21 by ernest-httpd's session, its line 35 (the log's *A Close Answers Once Its Bytes Are Sent*); the plan's MVP 4.5, item 158.

271. **The shell names three keys from their escape sequences, and no library names a key.** Appendix E.16 delivers every key the runtime does not decode whole as `Escape` and its characters, "from which a program names the rest", and `Ansi` writes sequences and reads none (Appendix G.3). So `Ernest.Shell.Editor` holds a sequence's characters and matches nine strings to name `Home`, `End` and `Delete`. Which sequence names `Home` is each terminal's convention, and a library's function would carry that table whole. The ask: a function of `Ansi` from a sequence's characters to the key it names. Found 2026-11-21 by MVP 4.17's item 119 (the log's *An Input Edited by Its Lines*); dropped 2026-11-22 on a count (*Three Feedback Entries Decided*), and reopened 2026-11-23 (*The Refusals That Rested on a Count*); the plan's MVP 4.5, item 176.

275. **`String.lines`, `trimStart` and `words` walk every grapheme.** Over the 9.1 MB of the repository's tracked sources, `String.lines` takes 913 ms where `Bytes.split` on a line feed takes 8 ms, `trimStart` 711 ms over 189,000 lines and `words` 2,450 ms over the same lines. A line feed outside `\r\n` is always a grapheme's boundary, so a split there by the bytes would answer the same parts. `tools/words.ern` reads every tracked file this way and takes 0.5 s and 1.6 s for its two jobs, where the awk it replaced took 0.07 s and 0.34 s; most of the difference is these three. The ask: each costed against the host's own work on input a program meets, as E.0 rule 1 and §10 cost an operation. Found 2026-11-23 by the build of `tools/words.ern` (the log's *The Three Tools in Ernest*); the plan's MVP 4.5, item 176.

277. **`Io.show` writes a constructor under its module's name, so a program that prints one bare writes the names by hand.** `tools/unicode_width.ern` holds `widthName`, three clauses that give `Zero`, `Wide` and `Pictographic` the names its own type declares, since the table it writes names them unqualified. The ask: whether a constructor's bare name has a function of its own. Found 2026-11-23 by the build of `tools/unicode_width.ern` (the log's *The Three Tools in Ernest*); the plan's MVP 4.5, item 176.

278. **`Io.show`'s declaration names a function no code calls.** `src/stdlib/io.ern` declares `"ern_io:show/1"`, since the checker holds a declaration's arity to its parameters, and the compiler calls `show/2`, the descriptor of the value's type after the value, at every site, a value passed among them. So the source names one function and the program runs another, and `make xref`'s short list carries the one that nothing calls; `Io.debug` was the second until it became a function of `io.ern`. The ask: whether a declaration whose type has a requirement names what the compiler calls, or the special case is said where a reader of the source sees it (§0's principle 3). Found 2026-11-23 by `make xref`'s unused exports (the log's *The Refusals Before the Readers, Built*); the plan's MVP 4.5, item 176.

279. **Nothing counts a part's occurrences in a `String` or a `Bytes`.** `tools/sizes.ern` counts a file's lines as `List.size(Bytes.split(bytes, <<10>>)) - 1`, which builds a list of every line to read its length, since `String.lines` walks every grapheme (feedback 275) and neither module has a count. The host has `binary:matches/2`, whose length is the count. The ask: whether `String` and `Bytes` gain a count beside `split` and `contains`, by E.0's rules. Found 2026-11-23 by the build of the review's listings (the log's *The Listings Before a Review, Built*); the plan's MVP 4.5, item 176.

280. **Nothing groups values under their keys.** `tools/clones.ern` holds `added`, `Map.update(map, key, fn(values) = value :: Optional.withDefault(values, []))`, for its windows by hash and its runs by pair, and `tools/sizes.ern` writes the same form inline for the files gone by name, as `tools/documents.ern` does a third time (the full review's *E3 places 4*). Neither `List` nor `Map` has a grouping, a `groupBy` from a list or an append to a key's list. The ask: whether `List` or `Map` gains one, by E.0's rules. Found 2026-11-23 by the build of the review's listings (the log's *The Listings Before a Review, Built*); the plan's MVP 4.5, item 176.

282. **A library's test data are computed in every program that uses the library.** A test is a top-level `let` (E.24), and every top-level `let` but a constant is evaluated before `main` runs in each module the program depends on (§8.5). `src/libs/json/json.ern`'s tests need a text of a million digits and one of a long line, which as bindings would hold 1.3 MB in every program over `Json`, so they are functions, `longDigits()` and `longDigitsRefusedAt(column)`, that each case calls. The ask: whether a test's bindings are evaluated only where `ern test` runs them, beside *N L7, N H5*'s test as a top-level `let` whose name nothing reads. Found 2026-11-25 by the libraries' build (the log's *The Libraries' Build*); the plan's MVP 4.5, item 176.

283. **A constant too long for a line is computed, and read at each call.** `Int.toFloat`'s bound, 2^1024 - 2^970, is 309 digits, past the line's 100 columns, and a literal is not written over lines, so `src/stdlib/int.ern` computes it, `shiftLeft(1, 1024) - shiftLeft(1, 970)`, in a top-level `let` that is no constant (§4.6). The call costs 56 ns where the host's conversion costs 35. A string literal too long for its line is continued with `<>` at run time, at 23 sites, 5 in the shell, 7 in the libraries and 11 in the tools. The ask: whether a literal may span lines, or an initializer of literals and arithmetic is a constant. Found 2026-11-25 by the libraries' build (the log's *The Libraries' Build*), and the strings 2026-11-26 by the release review, its *E2 17*; the plan's MVP 4.5, item 176.

284. **`ern format` leaves a line past 100 columns where a comment ends it.** A `match` clause whose body fits the line and whose trailing comment does not is left as written, 111 columns in `Forward -> if position < length then position + 1 else length // report §11.2: `C-f``, where §11.6 fits a line within 100 columns "where these rules can" and the repository's own style check refuses the line. The ask: whether the layout counts a trailing comment in a line's width, moving the clause's body to the next line as it does for a body too long, or moves the comment above. Found 2026-11-26 by the shell's build (the log's *The Shell's Build*); the plan's MVP 4.5, item 176.

286. **One result's type written at every function.** `examples/interpreter.ern` writes `Either(ParseError, #(Expression, List(Token)))` ten times, at each function of its parser and inside the type of a parameter that is such a function, where `ern format` lays a head out as a staircase five lines deep.
