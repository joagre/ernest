# Language feedback

What writing Ernest has felt against the principles, and what a reader found that questions a rule of the language rather than showing a defect (CLAUDE.md, *Defects and gaps*). An entry stays until a plan item decides it: a report change, a "Later" entry in the log, a question in the plan, or a line saying it was weighed and left alone. An entry keeps its number, which the plan, the log and the code cite; the next is 89.

78. **`let _ = e` for a value discarded** (2026-10-01, W-31). A statement that is not the last has type `Unit` (§5.4), so a value an effectful call answers, `Tcp.write`'s `Either`, is discarded with `let _ = e`, eleven programs, and a `foreach` body is a block for it. The choices: `List.foreach` and its kin taking `(a) -> b with e` and discarding the result, which makes the common body one expression and hides nothing, the callback's result being the caller's to ignore; a statement of any type accepted, which principle 3's sentence refuses as a value dropped; or the form kept. Maybe: `foreach` over any result, decided with the library family's edits or after 0.2.0.

79. **An ask that answers into the mailbox** (2026-10-01, W-34). A `Reply` is made only by `Address.call`, which waits, so a process that must send a request and keep receiving spawns a helper to wait for it (the guide's §4.4). E.0 shape rule 8 has the form already: a function that delivers later takes a function from the message to the caller's mailbox type, as `monitor` does. `Address.ask(addr, mk, wrap)` would make the reply, send `mk(r)`, and deliver `wrap(answer)` to the caller's mailbox, without a limit, an alarm being the caller's. The choices: the prelude function, which §9's criterion admits since the runtime alone makes a `Reply`; or the helper kept. Maybe: the function. Decided by a milestone after 0.2.0 that touches §6.6.

80. **A `Down` after the dead process's messages** (2026-10-01, W-38). §6.9 says a `Down` has no order with the messages the ended process sent, so a result that must not be lost to a `Down` comes as a call's answer, and the guide's §5.6 routes workers' results through `main`, each count crossing two mailboxes. The host's monitor keeps that order, a `DOWN` arriving after every message the dead process sent to the monitoring process; Ernest's reaper delivers the wrapped `Down` from a process of its own, which loses it. The choices: the monitoring process taking the host's monitor itself, the runtime applying the wrap as the process receives, so that §0's host paragraph takes a seen outcome; or the rule kept and stated, as it is. Maybe: the host's order. Decided with the runtime's monitor design, after 0.2.0.

81. **A server that watches its client names the client's mailbox** (2026-10-01, the release review's N-L1). `monitor` takes an `Address`, authority over a process, and a constructor cannot hold an `Address(a)` of any `a` (§3.9), so a message type that carries whoever leased an entry becomes `Msg(client)`, and one cache serves one client type; a `Process` names the process but cannot be monitored (the log's *`kill` and `monitor` Keep the Address*). The choices: `monitor` of a `Process`, an address every address converts to, or the parameter as the cost of the rule.

82. **The phantom parameter reaches every holder** (2026-10-01, N-L2). The `Msg(client)` of entry 81 leaves every holder's type open: at the prompt `let c = Cache.start()` is refused until an annotation names a client type the shell never is, while the same `let` in a block keeps its variable open (§4.6).

83. **A test receives nothing** (2026-10-01, N-L3). `Test.Case`'s `run` is `() -> Test.Result with Never`, a process root as an entry point is (the log's *Tests, `Erl`, and `Ets` Moved*), so a test that must see a `Down` kills the process and polls with a timed wait, the polling loop written twice, in the demo and in the tests. The choices: a test that names a mailbox type, or a `Test` function that waits for a message with a deadline.

84. **An example annotates a value for the printer** (2026-10-01, the release review's C-14). `Io.show` writes by a type known whole (Appendix E.1), so a doc example of `Either.map(Right(2), ...)` first binds `let found : Either(String, Int) = Right(2)`, a line that exists for the printer alone, where a reader predicts `Right(2)` to show.

85. **A digit's predicate written by hand** (2026-10-01, C-15). `Char.isAsciiDigit` left the library (the log's *What the Library Admits*), and `fn(c) = c >= '0' && c <= '9'` is written four times, in `String.toInt` and three places of the Markdown parser.

86. **`Test.` on every test** (2026-10-01, C-16). `Test` leaving the prelude puts `Test.Case`, `Test.Passed`, `Test.Failed` and `Test.Result` into every test, three qualified names a test, 68 in the shell's editor alone, with no way to bring one module's names in unqualified (principle 3, the log's *Names Stay Qualified, Without Import or Alias*).

87. **`NotUtf8` carries the whole file** (2026-10-01, C-17). `Io.NotUtf8(bytes)` was shaped for a name or a link's target, so a history file that is not UTF-8 is answered as `Left(NotUtf8(bytes))` with the whole file in it, which the shell reduces to one sentence.

88. **One budget over several waits** (2026-10-01, C-18). Shape rule 8 bounds one request by its milliseconds, so `Os.run`, which holds one time over several reads and writes, computes `deadline - Clock.monotonic()` by hand before each, as every function that composes requests under one time will.
