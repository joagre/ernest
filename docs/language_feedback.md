234. **The runtime loads its own modules on first use, so a descriptor's limit hangs it** (2026-11-04, ernest-httpd's 26, on 0.10.0+612faac8). Under `ulimit -n 48`, a `Tcp.accept` that meets the host's `emfile` is answered nothing. The runtime cannot open `ern_io.beam`, `erl_posix_msg.beam` and `io_lib_pretty.beam`, the logger writes `DEFAULT FORMATTER CRASHED`, and the accept neither answers nor ends. `Fs` answers `Timeout` after its full time instead of the error, and a fault is a raw host term, `{{error,[{io_lib_pretty,nofile}]},...}`. The same program with one failing `Fs.read` and one failing `Tcp.listen` first, which load those modules, answers `Left(Other("too many open files"))` as E.18 says. Asked: the runtime loads its own modules, and the host's it calls, at its start, and the report says what a load does when the host cannot open the module's file. ernest-httpd's test of its listener's retry waits on it.
