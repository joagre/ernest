# Language feedback

What writing Ernest has felt against the principles, and what a reader found that questions a rule of the language rather than showing a defect (CLAUDE.md, *Defects and gaps*). An entry stays until a plan item decides it: a report change, an item of a milestone, or a line in the log saying it was dropped and why. An entry keeps its number, which the plan, the log and the code cite; the next is 159.

- **149**, 2026-10-24, the full review's N22: a `Reply` names no caller, so a server that must watch its caller needs the caller to put its own `Process` in the request, and nothing checks that field; Erlang's call hands the server `From`. Decided to keep as a protocol's own, by principle 5.
- **150**, 2026-10-24, N23: a monitor cannot be taken back, so a server that monitors each caller piles up monitors and later `Down`s for as long as the caller lives; the newcomer's guard kept a `Set(Process)` of who it already watches. Kept until a second program asks, by principle 5.
- **151**, 2026-10-24, N24, B-H2: a function that only pauses, `receive { after ms -> Unit }`, carries `receiving e`, and so does every caller, though no message is taken; the newcomer read `receiving` as "reads this process's mailbox". The rule is §3.9's process-only wait, the one silence; the guide shows the annotation and the help names it.
- **152**, 2026-10-24, N26: `Address.call` answers `None` for a time run out and for a callee ended alike, so a caller cannot tell a slow table from a gone one. §6.6's rule that `None` says nothing stands.
- **153**, 2026-10-24, U-L1: `Process.status` answers `None` for a process that ended and for one of another node alike, and a `Process` names its node though nothing reads the node; a program tells the two apart only through a `Peer.computeAt`. E.21 states the two `None`s.
- **154**, 2026-10-24, U-L2: `Peer.offer`'s `Left(holder)` is a `Process`, which `monitor` takes and `kill` refuses, so a held service cannot be ended from what its holder gives; a service waiting on an old version's holder is moved only through an address kept before the reload.
- **155**, 2026-10-24, E22: waiting for one process's end from a function that receives nothing costs a second process and a call, since a `Down` reaches only a mailbox; `Test.faults` spawns a judge for it.
- **156**, 2026-10-24, E24: a spawned function must return `Unit`, so running a function only for its fault takes a lambda and a `let _`.
- **157**, 2026-10-24, the Erlang programmer's close: supervision and in-place upgrade exclude each other, a service under `restarting` falling back to the code it started with at its next fault (§6.9), so an operator who needs both gets one or the other; what the deployment guide's §5.3 says.
- **158**, 2026-10-24, the Ernest batch's B-C8: no function writes a time as text, `Clock` giving epoch milliseconds alone, so a line that carries its time, as `ern run`'s lines do in a log, cannot be written in Ernest; writing RFC 3339 by hand is a dates library's work, and `ern_cli:stamp/1` uses the host's `calendar:system_time_to_rfc3339/2`, which E.15 could shim under E.0 rule 1.
