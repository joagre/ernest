# Ernest Toolchain: Architecture Notes

How the toolchain's code is arranged: its stages, its modules and what each does, the runtime, and the kinds of tests. The code wins any conflict with this document. The language is the report's; the layout of the repository and the commands are [`development.md`](development.md)'s; the reasons are the [decisions log](decisions.md)'s; the roadmap is the [plan](implementation_plan.md)'s. The Erlang follows [`style.md`](style.md).

## The pipeline

One Ernest module goes through these stages, each an Erlang application under `erl/`:

| Stage | Modules | In | Out |
|---|---|---|---|
| lexer | `ern_lexer` | source text | tokens |
| parser | `ern_parser`; `ern_ast`, a node's span and the walks later stages share | tokens | AST, records of `ern_ast.hrl` |
| formatter | `ern_format` and its printer `ern_pretty` (§11.6), which `ern_docs` lays a type declaration out with (§11.4) | source, tokens with comments, AST | the text laid out |
| checker | `ern_typecheck`, with `ern_types`, `ern_prelude`, `ern_exhaust`, `ern_bound` (§3.11), `ern_scope` (§5.4), `ern_bitspec` (§5.11), `ern_interface`, the interface chunk, and `ern_canonical`, the canonical forms and their chunk (Appendix H) | AST, dependency interfaces | typed AST, interface, environment; the canonical forms and their hashes |
| emitter | `ern_compile`, a checked module's compile, with `ern_docs`, the `Docs` chunk; `ern_emitter`, the back end, which makes a unit from canonical forms (Appendix H); `ern_descriptor` (§8.4), the shell's descriptors | typed AST, environment; the emitter, a `#unit{}`: the canonical forms, what the build adds, and the link | Erlang forms, then BEAM with the `ErnI`, `Docs` and `ErnC` chunks |
| runtime | `ern_rt`, `ern_boundary`, `ern_show`, the system processes `ern_fs`, `ern_tty`, `ern_tcp` and `ern_os`, `ern_peer`, `Peer`'s shims and the frames a node's gateway reads (§8.7), `ern_code`, the code table (§8.7), the host's limits (§11.2), and `Code.running` and `Code.hashes` (Appendix E.28), the standard library's shims, `ern_tty_signal`, the terminal's resize handler, and `ern_exec`, the one helper in C, which also holds a node's lock on `ernest.pid` (its `lock` mode) and signals the node that holds one (its `node` mode) | | what compiled code calls |
| diagnostics | `ern_diagnostic`, in `shared`, beneath every stage | a `#diagnostic{}`, the source | the text of §11.5 |
| chunks | `ern_chunk`, in `shared`, which reads the term a compiled module's chunk holds: plain data and nothing else, its new names within the room the host has for names (§11.1), so that a crafted `.erc` is refused and never run or let to fill the host | a chunk's bytes | the term, or `error` |
| namespaces | `ern_namespace`, in `shared`, the one mapping between a path's components and a namespace's segments (§4.2, §11.1), which the build, the emitter's module names and the shell's `:load` share | a component or a segment | the other |
| cli | `ern_cli`; `ern_release`, the version text, whose mark `-dev` says the build is no release; `ern_build`, the build every job reaches; `ern_node`, a node's configuration directory, made, checked and read (§8.7, §11.3); `ern_carrier`, a node's carrier, its host's flags, its name, its cookie, the floor's digest, its rule and its lines, `ern_epmd`, which answers the host in the port-mapper's place, and `ern_gateway`, a node's gateway, which records a peer's word that it ends and watches the node's connections, saying each change, an end where the peer said so, and which hands each peer's frames to a worker of that peer's, which `ern_peer` reads, one across a loss of the peer's connection until it holds no frame and no kept process (below), the worker handing a spawn or a compute of a function the node lacks to the exchange and a message to an adapted address to the process it keeps for the address (§6.5, below), and the exchange's four frames straight to `ern_exchange`, the node's exchange (§8.7, below), records a call's notes itself, in `ern_rt`'s tables, where a restart reads them, a compute's frame among them as its call's first note, and answers a utilization itself from the node's measure, or the utilization its program set, keeping the last reading of the schedulers' time and the host's keeping of it, which lasts as long as the gateway; it tells each connected peer the same number with its own interval every `utilization-interval`, by one timer of its own while the node lists peers and at a peer's connection, and holds each peer's telling in `ern_peer`'s `ern_utilizations`, `{Node, Utilization, At, Interval}`, aged by the teller's interval, which the peer's loss empties of it and a compute that names no peer reads (`ern_peer:picked/0`) (§8.7); `ern_shell`, the shell's front end; `ern_code_load`, `Code.load` (Appendix E.28); `ern_page`, §11.4's renderer; `ern_signals`, the handler of termination and hangup; `ern_out`, a job's standard output and standard error | command lines, shell inputs | `ern`'s jobs, a session |

The Makefiles pass `VERSION` to `erlc` as a macro, and the repository's build `DEVELOPMENT` beside it, by which `ern_release`'s version text, which `ern --version` and the shell's start line print, carries `-dev`; the release archive recompiles `ern_release` without it; the pages and the `.erc` compiler stamp name `VERSION` alone, being a release's; the cookie reads the mark (`ern_carrier:cookie/2`), a development build standing on the digest of its own code. The Emacs mode calls the toolchain only as `ern format -` ([`emacs_mode.md`](emacs_mode.md)).

`bin/ern` finds its tree, refuses a working directory whose name is not UTF-8, tells the host to write no crash dump (§10), and starts the host with `-noinput`, with `erl/*/ebin`, `build/stdlib` and `build/shell` on the code path, with `ern_signals:install/0` and then `ern_cli:start/0`; [`install.md`](install.md) lays out the installed tree. `start/0` installs `ern_signals` again, for a caller that is no launcher, and runs `ern_cli:ern/2`, a run writing to the node's own descriptors. Every job but the shell writes its own text through `ern_out`, ports on descriptors 1 and 2 in place of the host's `user`, which halts the host when a stream's reader has gone; `ern_out` ends `ern` with 141 then (§11). The shell keeps `user`, which is its terminal, and `ern_tty` asks `user` whether a stream is a terminal and what size it is, whatever device a job writes to. `ern` then ends with the job's status, with 70 after a failure of the toolchain itself, or by the signal that ended a run. `ern_signals` takes `SIGTERM` and `SIGHUP` from OTP's default handler: during a run it ends the run through `ern_rt:signal/1` (§8.6), and otherwise ends `ern` at once; `die/2` restores the signal's default action and sends it again (§11.2).

## Tokens and AST

`ern_lexer:tokenize/1` returns `{ok, [Token]}` or `{error, #diagnostic{}}`. A token is `{Category, Position, Value}` for a literal, an `ident`, a `typename` or a `doc` block, and `{Symbol, Position}` for an operator, a delimiter or a reserved word. `Position` is `{Line, Column, End, PreviousEnd}`, `PreviousEnd` being the end of the token before. `tokenize/2` with `comments` adds each comment as `{comment, Position, Text}`, for the formatter.

`ern_parser:parse/1` takes tokens; `parse_string/1`, `parse_expr/1`, `parse_type/1` and the shell's `parse_statement/1` are conveniences. The diagnostic of an unfinished input carries `expected`, which completion reads, and `within`, the innermost call and the argument's index, which `Shift-Tab` reads (§11.2).

Every node is a record of `erl/parser/include/ern_ast.hrl`, one per production of Appendix A, `span` first, which `ern_ast:span/1` reads. A `fn` declaration's requirement is a list of `#member{}`, and in its body the parser makes `a.compare` and `a.negate` of a type variable of the signature an `#e_member{}`, as `a.+` is wherever it stands (§4.9); the declaration binds no name that is one of its type variables, so the two readings never meet. Expressions and patterns end in a `type` field the checker fills. A name, `#e_var{}`, carries a `referent`, what §4.2's lookup resolved: `var`, `#own_declaration{}`, `#remote_declaration{}` or `{prelude, QualifiedName}`. The canonical form reads it and never resolves a name again (Appendix H), and the compile reads the order of the top-level lets from `ern_typecheck:let_order/1` (§8.5). Declarations carry `doc` and `export`. The parser rewrites twice: parentheses make no node, and `x |> f(a)` is the call `f(x, a)` with its `pipe` flag set, so that `x` is evaluated before a callee that is not a name (§5.1). A clause's `or` alternatives are one `#p_or{}` (§5.9). `prune_docs` keeps a doc block only where §2.2 attaches it, and the module's is `#module_doc{}`, first in the list.

Expressions are parsed by one precedence-climbing loop, patterns by a second small one, and declarations by recursive descent. Nothing backtracks: where the first token does not decide, the parser reads the later token that Appendix A's last paragraph names.

## The type checker

`ern_typecheck:check(Namespace, Declarations, Interfaces)` returns `{ok, Typed, Interface, Env}` or `{error, [#diagnostic{}]}`, `Interfaces` being the `#interface{}` records of the modules referred to. `infer/2` gives an expression its type, and `ern_typecheck:check_expr/5` checks one against an expected type, pushing it through branches, clauses and blocks, which gives a diagnostic §11.5's labels.

Types are the terms of `erl/checker/include/ern_types.hrl`: `{tcon, QualifiedName, Args}`, `{tvar, Id}`, `{ttuple, Elements}` and `{tfn, Params, Effect, Result}`, `Effect` being `none`, where the function receives nothing, or a type. Each variable has a `#type_variable{}` entry with its level, its restrictions (`equality`, `process_only`, §3.9) and its annotation's name, in a `#type_state{}`. `ern_types` owns this state: unification with the effect rules, generalization by levels, instantiation, and the printer that diagnostics and `ern doc` share.

`ern_prelude` holds §9 as tables, each entry documented: the built-in types, the declared types as Ernest source, the values with their type text, and the process-only values. `ern_typecheck:prelude_env/0` builds the starting environment from them and from the standard library's interfaces, `ern_prelude:stdlib_interfaces/0`. `ern_prelude:docs/0` makes of the tables a `Docs` term, which `ern_page:prelude_page/0` renders for `ern doc` and `ern_page:prelude_declaration/1` for `:doc` and `Shift-Tab`.

A module is checked in this order:

1. `declare_types`: every type, its constructors with their fields in declared order (§3.5); `mark_abstract` marks an abstract type, whose constructor `lookup_constructor` refuses elsewhere (§4.4). Its third pass, `check_recursive_groups`, takes the cyclic strong components of the module's types over the names in their fields and refuses a group's type named at other than the declaring type's parameters (§3.9).
2. `check_values`: the value declarations in dependency groups, from a `digraph` of references by name (§4.2). `run_group` checks a group when the fold reaches it, or when `demand` asks for one of its names during another definition's inference (§4.8). `check_group` gives each member a monomorphic placeholder, unifies the annotations first, infers the bodies in order and generalizes. `alternatives_differ` and `alternatives_agree` check pattern alternatives (§5.9). After each group, `let_cycles` reports a cycle of top-level lets (§8.5).
3. `post_checks`, per definition: `<-` resolved to `Either` or `Optional` (§5.5); operators left open by `operator_result/4` (§4.8); what each requirement is supplied with, `supplied/2` (§4.9, below); rigid annotation variables (§3.9); the local-fn use order (§5.4); undetermined block bindings (§4.6); exhaustiveness by `ern_exhaust`, Maranget's algorithm with a witness (§5.9); and the restrictions an instantiation carries, `check_pending_restrictions`. Once a group's post checks are done, `ern_bound:check/2` reads each top-level definition for a spawn on a peer (§3.11): the function it starts, a declaration's name or a lambda written in the definition, what that lambda captures, and the process's mailbox type, against `ern_bound:binds/2`, the bound type; it runs there and not at a local fn's end, since what a local fn's lambdas capture from around it is typed by the definition that encloses it. It reads a `Code.running` there too (Appendix E.28): the name of a top-level `fn` that is no foreign declaration (`ern_typecheck:is_foreign/2`), its result type `Unit` and its mailbox type, read from its declaration's scheme (`declaration_scheme/2`), where it has one, holding no type variable; the call's type, `List(Address(m))`, takes its `m` from the declaration's effect at the call itself (`running_mailbox/4`), so that a send over the list is checked against it, and leaves it a variable for a function that receives nothing.
4. `check_abstract` and `check_exports`: §4.2's and §4.4's visibility rules.
5. `interface_of`: the exported types and values, and the private types they name, a mailbox type an exported function receives wherever an arrow's effect names it and a type an abstract type's fields name, with those theirs name (`private_types/3`), which a dependent's descriptors read through `described_type/2` and no name of its resolves to (§4.2, §8.4, §11.1).

**Requirements** (§4.9). A declaration's requirement rides on its `#scheme{}`, `[{Id, Member}]` over the scheme's variables, so that it travels with the name through the globals, a block's locals and a compiled interface, and `ern_types:format_scheme/2` prints it after the type wherever a declaration's type is printed; `ern_types:instance/2` instantiates it beside the type. `signature_shape` puts it on a definition's placeholder, so that a recursive use is supplied as a later one is, and `publish` and `release` carry it over generalization. The members in force, the enclosing declarations', are the environment's `requirement`, and an operator on a type variable among them resolves to its member. Each use of a declaration with a requirement leaves a `#pending_member{}` in its `#e_var{}`'s `supplies`, as an operator does in its node's `member`, `Io.show` does for its descriptor, `Foreign.term` does for the type its value crosses at (§8.4), under a member of its own, `exposed`, which no requirement supplies, and `Peer.service` for its service's message type (§8.7), under `service`, supplied as a `#service_type{}` once the type is known whole and not bound (§3.11); at the definition's end `supplied/2` replaces each by a `#known_member{}`, a known type's member with its own requirement supplied in turn, a `#required_member{}`, the enclosing requirement's, or a `#shown_type{}`, its `member` `show` or `exposed`, the records of `ern_types.hrl`, or reports the error §4.9 names. A local fn's are resolved at its own end, with its own requirement in force. `derived_members/2` makes each `derives compare` an ordinary `fn T.compare` declaration before the values are checked, with the requirement its fields' comparisons reach, read to a fixpoint over the module's derived types; and `filled/7` reads `Ops(..Set)` as the construction that names each field's declaration in the namespace (§5.6). A path in a record update, `Pool(..pool, stats.indexed = e)`, is `updated_through_paths/7`: the base and each value are bound once, in source order, to names no program spells, and the construction over them nests an update per first segment, whose constructor is the one of the type the field reaches (§5.6, §5.1); the typed tree holds the block, and the emitter sees only bindings and constructions.

A block's local `fn`s get placeholders from their annotations before any statement is checked, and one is generalized once every later local fn it references is checked (§5.4). An initializer is checked as a body of mailbox type `Never` (§4.6), and one that is no value, `is_value_form/1`, is not generalized. `builtin_operators/2` reads `fn Float.+` in a built-in type's module as that module's `+` (§4.8).

The environment is opaque outside the module. The compiler reads it through functions of its own, `type_state/1`, `resolve_type/2`, `lookup_type/2`, `lookup_constructor/4`, `node_type/1` and `foreign_implementation/1` among them; the shell also through `declared_scheme/3`, `fields/2` and others, and through `ern_ast:pattern_bindings/1` for the names a pattern binds.

## The compiler

The build's path is typed tree, form, unit. `ern_compile:compile/5` takes the checker's typed tree and environment, has `ern_canonical:module/5` write the forms (below), and gives `ern_emitter:unit/1` a `#unit{}` (`erl/emitter/include/ern_unit.hrl`): the module's `#definition{}`s, each form also with the source woven in, its `sourced`, `{'$at', {Line, Column, Name}, Node}` at each node, the line its code is annotated with and the name of the local it binds, which `ern_canonical:stripped/1` takes out for the hash; what the build adds that is no definition's, the module's foreign functions with their schemes as forms write them, what it exports, the order its bindings are initialized in, the units of its dependencies, its reaches and its lambdas', and the shell's namespaces and offset; and the *link*, `#link{}`, from each reference its forms make outside the unit to where it is, a function's unit, function, arity, kind and identity (`#linked{}`) and a type's name and constructors (`ern_canonical:declared_type/4`), and the state a type prints under from the module (`ern_types:printing/1`), all read from the environment's interfaces (`ern_compile:link/5`); a definition or a foreign function that gives its module's printing, `{Namespace, Shadows}` as text, one read from a compiled form or that arrived, prints its types in a check's cause under that scope (`ern_emitter:printing/2`), so that a cause reads alike on every node, and a descriptor, which holds its causes' text, is the check site's. The emitter reads nothing else, no typed tree and no environment, so that a unit a node makes from forms that arrived is made by the same back end from the same input; without the source a unit's code has no lines, its variables are named by their locals' numbers, and its spawn sites name the declaration alone (`units_from_forms_alone_test_`). The `ErnI` and `Docs` chunks are the build's and no unit's, and are made from the typed tree and the environment. Three makers give the emitter a `#unit{}`: the build's (`compile/5`); the shell's load of a compiled module beside another unit of its name, which makes it a unit of its own from what its `.erc` records, linked through the session's interfaces and its units (`from_compiled/5`); and a node's arrival (`ern_arrival`, under *The runtime*), linked through the code table. All compile through `compiled/2`, which answers the host's errors, a build raising them as its defect.

`ern_emitter:unit/1` builds Erlang forms with `erl_syntax` in one traversal of each form, threading a record `#emit_context{}`: the unit, its own definitions and foreign functions by position, hash and name (`#own{}`), the definition being compiled and the restrictions its schemes give its type variables, the variable map, a counter, the local-fn table, the lifted functions, and whether the unit builds a function value, a fun of its own code that an expression or a supply emits (`function_value/2`), by which the shell keeps an input (§11.2). `prepared/2` first makes each reference to a member of the definition's own group the reference that names it outside the group, and marks each lambda and local function with its position among the definition's and each local function with the number its block binds it to (Appendix H's walk). It has a clause for each node of Appendix H, and a value's representation is §8.4's ABI.

- A unit's functions are named by their position in it (§11.1), so that a unit adds one atom to the host, its own name: its definitions in the order of their forms, a type taking its position, then its foreign functions in the order the module declares them, the function at position N `'$N'` (`function_name/1`); a local fn at position P in the definition at N is lifted to `'$N.P'`, and the entry a spawn on a peer starts a lambda or a local fn by is `'$N.P.entry'`. The functions the runtime calls on every unit keep their names, `'$init'/0`, `'$deps'/0`, `'$tests'/0`, `'$spawned'/2` and `'$code'/0`, a descriptor's is `'$type_K'`, and an arrival's function that faults naming what the node lacks is `'$lacked_K'` (§8.7), names every unit shares. The interface holds each function's position (`positions`), by which a dependent calls it, and its hash covers the positions of the values it exports (`ern_interface:hash/1`), so that a dependent is compiled again where a position it calls moved. `--emit-erl` writes each function under a comment that names it as the program does (`ern_emitter:source/1`).
- A caller from Erlang finds a unit's function by its qualified name in the unit's `'$code'/0` (`ern_code:function/2`): the entry point and the shell's program (`ern_cli`), an input's entry (`ern_shell:value/2`), `Markdown`'s functions for `ern doc` (`ern_page`), and the tests (`ern_named`, in `erl/runtime/test`). A fault's trace shows each function by the name its unit's build gives it, read back from `'$code'/0` (`ern_code:function_text/2`, `ern_rt:trace/1`): `helper`, `'Vec.+'`, a lifted local fn `'helper$2'`, an entry `'helper$spawn$1'`, and a fun after its function, `'-helper/1-fun-0-'`.
- Every binding is a fresh Erlang variable `Name_N`, `L_N` where the form holds no source, so that a unit made from forms makes no atom past the largest unit's before.
- A local `fn` is lifted to a unit function `'$N.P'`, whose leading parameters are the variables it closes over, its own and those of the local fns it references (§5.4). A call passes them; a use as a value is a closure.
- `let p <- e` is a `case` on `Left`/`Right` or `None`/`Some`, the rest of the block in its second clause.
- A selected field (§3.5) is `erlang:element/2` where every constructor holds it at one place, and a `case` on the tag otherwise.
- A clause with alternatives is one Erlang clause per alternative, each calling a fun that holds the body (`alternatives/3`). A guard that is not an Erlang guard falls through by a continuation.
- A top-level `let` is a getter over `persistent_term`, its key its unit and its getter's name, filled by `'$init'/0`; every unit exports every binding's getter (§11.1), so that a definition that arrives reads a binding of its reach wherever the node holds it with its value, a module's private one among them (§8.7), and exports a function where its module exports it, an arrival every function it holds. A module lists its dependencies in `'$deps'/0`, its tests in `'$tests'/0`, and in `'$code'/0` what it holds, which the code table reads as it loads (below): each definition by its qualified name, an arrival's by its name as text, with its hash and its function and arity, a function with its reach, the bindings and the foreign declarations it names transitively, or a binding's key; each foreign declaration's implementation and function; and each lambda and local fn a `Peer.spawn` starts, by its identity, with its entry and its reach; and, last and under the module's namespace, `{calls, Units}`, the `ern@` and `ern$` units its code calls, which a standard library module leaves empty. `compile/5` alone writes `'$code'/0`, from the canonical forms' hashes (`#unit.code`), so the golden files and `--emit-erl` have none.
- A spawn on a peer sends no fun (§8.7): `ern_emitter`'s `spawned/2` writes the function as its identity, `{function, Hash}`, `{foreign, Names}`, `{lambda, Hash, Position, Captures}` or `{restarting, Limit, Spawned}`, a lambda's and a local fn's position the one `prepared/2` marked. A lambda or a local fn a spawn on a peer starts gets an *entry*, `'$N.P.entry'`, that takes its captures in the order its form first names them (`captures/1`) and runs it; `'$spawned'/2` runs an entry, or a function or foreign function of no parameter, by its name, over the captures, which is how the peer's `ern_peer` starts what its code table found. A service carries its type's hash, of the type its form's supply holds (`service_hash/1`), a session type's under the session's one namespace, `$Session` (Appendix H).
- `spawn` passes its site as a third argument (§6.9), the name `site_name/2` gives its declaration and the line: the qualified name under the unit's site namespace, a reload's version's `Counter$2.worker`, a session declaration's own, an input's expression's asked of the shell as the spawn runs (`ern_shell:input_site/2`), and an arrival's definition's name as its code frame gave it, its lines the sender's, `Counter.worker:23` (§6.9, §8.7).
- A requirement's members are parameters after the written ones, in the order it writes them (§4.9); `#emit_context{}`'s `members` holds each one's variable by its type variable and member. A call appends what the checker supplied, `supply_form/2`: a known type's member as a function value, its own members bound into a closure, the enclosing requirement's parameter, or `show`'s descriptor; a declaration with a requirement as a value is a closure that supplies them. A lifted local fn closes over the enclosing requirement's parameters its body uses (`enclosing_members/3`).
- A `Float` operation is inline (`float_operation/5`): it adds `0.0`, so that a negative zero is `0.0` (§3.1), and makes its own `badarith` §7.4's fault. A float segment's variable is `{zero, V}` in the variable map, read as `V + 0.0` (`variable_form/1`).
- A type's descriptor is a function `$type_N`, made from the type as its form writes it, the constructors of a type of another unit the link's (`describe/4`); the cause a check faults with prints the type as §11.5 does from the module, its variables named by their numbers' order, since a form holds no annotation's names (`printed/2`). A function type's holds a maker (`built_descriptor/1`), with which `ern_boundary` wraps a function value. A `show`'s descriptor wraps the types its form's supply names as `<abstract>` (Appendix E.1); another descriptor wraps none, since only the printer reads the wrap.
- Another module's function as a value is `fun M:'$N'/A`, `M` the module's unit, which never takes a second version (§11.2). A unit is the module's Erlang name but where `compile/5`'s `units` names another: the shell gives the unit of each version a reload brought, `ern@counter$2`, and of each previous version's namespace (`ern_compile:unit_of/2`).

`compile/5` runs `compile:forms` with the chunk `ErnI`: a format number, the canonical interface, and what §11.1's recompile rule compares, the hashes of the source, of each dependency's interface and of the standard library's, the hash of each other module's definition the module's forms name, its `references`, the build of `ern`, and whether the module builds a function value, `builds_functions`. `ern_interface` owns the chunk: `encode/2`, `read/1`, which refuses another format, and `hash/1`, which leaves variable names, the definitions' hashes and the positions of the functions no dependent calls out. Before it, `ern_canonical:module/4` writes each definition's canonical form and hash (§8.7, Appendix H), which `compile/5` puts in the chunk `ErnC`, `{FormVersion, #recorded{}}`, the records of `ern_canonical.hrl`: each `#definition{}` with its sourced form as `ern_canonical:recorded_source/2` writes it, the lines of its source, a session's input's counted as its session counts them, the locals' names left out, and its `name` where its sites write another than its qualified name, `f` for a session declaration, `input 3` for an input's expression, `Counter$2.worker` for a reload's version, and its `printing`, the namespace its forms write the module's types under and the prelude names its types shadow, as text (`ern_types:printed_scope/1`); the module's foreign declarations with their schemes, implementations and printing; and its bindings' order, by which a code frame carries a definition with its name and lines and the shell makes a compiled module a unit of another name; and the hashes by qualified name in the interface's `identities`, by which a dependent's forms name them. The walk writes a reference to a definition of its own module open, `{'$own', QualifiedName}`; `closed/1` takes the strongly connected components of those references, in dependency order, hashes each, a group of two or more as one, and closes each open reference as the group's position or the hash of what it names. A type the emitter reads at a node, an operator's operand's, a selection's, `<-`'s and `Address.call`'s answer's, the form holds there (Appendix H). A `show`'s supply holds the view its site has, the abstract types of other modules the printer meets (`shown_abstract/2`). A name a shell session declares, a type's, a binding's or a foreign declaration's, is written under `$Session` in a form and in `'$code'/0` (`ern_canonical:form_name/2`, `ern_emitter:form_name/2`); the references the build compares keep the input's name, and the walk records the qualified name each reference to another module names (`links`), by which the link finds it. `read/1` reads the chunk as data alone, through `ern_chunk`. `ern_docs:build/4` builds the EEP 48 `Docs` chunk in the same compile, an entry per declaration §11.4 renders, with its signature, its doc block, and, in its metadata, parameter names, constructors and fields; its `BeamLanguage` is `ernest`. `erl_source/4` is `--emit-erl`.

A module's atom is its Erlang name, `ern@` and its path (report §11.1). Its functions' names are their positions, above; the `Docs` chunk keys a function by its Ernest name, a type member's with its prefix, `'Stack.push'/2`, and `module_info` and `record_info`, which the host gives every module, as `'module_info$'` and `'record_info$'`, so that the host's documentation tools take neither for the host's (`ern_docs:doc_key/1`).

## The runtime

`ern_rt` is what compiled code calls for processes, and the runner. It keeps ten tables:

- `ern_processes`: `{Pid, Site, Timers, Foreign, SpawnOrder, Root, Peer}` per process the runtime started or adopted, `Timers` and `Foreign` counting its timed receives and foreign calls, `SpawnOrder` its place in the order of spawns, which `RestForOne` reads, `Root` the process at the head of its spawn chain, its spawner's root where the runtime started the spawner and else itself, a peer's spawn and a process `ern_rt:spawn_root/3` starts their own root, an opened process its owner's, which `started_by/1` reads (§11.2), and, while `Code.load` evaluates bindings in a process, that process's and what it starts a mark of their own, a reference, given back to the process's root by the reaper, between two spawns, once the evaluation is over (`rooting/0`, `rooted/2`, Appendix E.28), and `Peer` the carrier node of the peer whose spawn started the process, named in its fault's line (§11.2), or `none`. A standard library call is counted only where its implementation's runtime module lists it as one that may wait on a process, in its `-waits` attribute; every other one waits on no process, or only in a callback it runs as Ernest, and is not.
- `ern_calls`: `{Caller, Callee, Reply}` per pending call, keyed by the caller, which makes one call at a time; `Reply` is the alias of the caller's monitor of the callee, and the reply's. A compute's caller (§8.7) has the row `{Caller, {ern_gateway, Node}, Alias}`, the peer's gateway its callee, so that its time run out and its end send the call's second note as a call's do.
- `ern_callees`: the same calls by callee, `{{Callee, Caller}, Reply}`, ordered, so that a restart reads its own callers; on the peer, a compute's process is `{{Pid, Caller}, {compute, Alias}}`, which a restart passes over and whose end tells the caller through the note.
- `ern_faults`: `{Subscriber, Address}` per subscription to faults.
- `ern_terminating`: `{Subscriber, Address, Told}` per subscription to the program's end, `Os.termination` (E.23), `Told` whether the end has told the subscriber in its present run, gone with its process's death or restart (§6.9).
- `ern_held`: `{{source, Holder}, Count}` for each holder of a source: a system process, a socket or a running program, the reaper for a watched process it did not start, a counted delivery process (`counted_link/2`), and `Tcp`'s connect and accept workers; and `{{opened, Pid}}` for each process a system module opened.
- `ern_deliveries`: `{{Recipient, Starter, Pid}}` for each delivery a process started, ordered, so that a restart of the recipient reads its own deliveries and its starter can end them, and the reaper reads every delivery to a process that has ended and ends it.
- `ern_restarts`: `{Pid, Alias}` for each restart a process may be asked (§6.9).
- `ern_checkers`: `{{checker, Key}, Checker}` for each checker of §8.4, and `{{behind, Checker}, Pid, Address, Key}` for what it stands in front of.
- `ern_launch`: how the terminal is read, `{reading, Kind}`, the entry process, `{entry_process, Pid}`, the process a deadlock faults, `{deadlock_victim, Pid}`, while the end looks for its subscribers and waits for them, the runner that tells them, `{ending, Runner, Launch}`, and once the wait is over, `{wait_over}`, from which a fault is read as the program's end (§8.6); and the utilization the program set with `Peer.setUtilization`, `{utilization, Utilization}`, which the gateway tells and answers in place of its measure (§8.7).

Its parts:

- **An address** is a pid, `{adapted, F, Target, Maker, Launch}` (§6.5), `Maker` the process that made it, whose node applies `F`, and `Launch` the reference of the launch that made it, whose end ends the address, so that a message to one of an earlier start of the node, or of an earlier run of `ern test` over a directory, is dropped wherever `F` would be applied, a send here and a peer's frame alike (§8.7, §11.2): a send pays the host's liveness check of a maker that lives, which is of the launch in progress, and compares the launch only for one that has ended (`adapted_way/2`), and a frame's address is compared as it arrives, no process kept for a dead one (`kept/1`); a process the runtime did not start that outlives its launch keeps its addresses alive while it lives, which only an Erlang test can be, or `{foreign, Pid, D, B}` for an address foreign code gave that names no process of the program (§8.4); `send` applies the functions in the sender, and a message to one made on another node goes to that node's gateway as a frame, where the process kept for the address and the sending node applies them (§6.5, §8.7): the gateway's worker for the peer keeps a `#kept{}` for each adapted address the peer sends to, its pid, the worker's monitor of it and the messages handed and not yet applied, starts the process with `kept/1`, linked to the reaper, which traps its exit, and with no row, acting for the address's target where the target is on this node (`acting_for/1`, below), as a message to the address arrives where none is kept, hands it each message, `{apply, Message}`, in the order the frames came, counts each `{applied, Pid}` it answers, and tells it to `stop` once none waits, forgetting it; one that ends otherwise, with its run or killed from foreign code, it forgets at its `'DOWN'`, and the next message to the address starts another. A loss ends no kept process: the gateway hands the worker `{lost, Order}`, `Order` the place among the node's moments where it learned of the loss (`erlang:unique_integer([monotonic])`), after the frames before it; the worker lets go of the spawns whose rows were written before it (`ern_peer:lost/2`), tells the exchange, and goes on, reading the frames that come after the connection is opened again, so that a message sent after the loss reaches the process kept for its address after one sent before it (§6.4). The gateway counts the messages it hands each worker (`hand/3`); a worker that has run a loss and holds no kept process asks it to end, `{idle, Node, Worker, Taken}`, with the count it has taken, and the gateway answers `stop` and forgets it where it has handed it no more, and otherwise lets it go on to ask again; a fault in one takes the message's place in the target's mailbox as `{'$ern_fault', Cause}`, as a bad message's does (§6.5, §8.4), and a message to a foreign address is exposed as a foreign function's argument is. `process_of/1` is the pid behind an address, and `held/3` how the boundary holds one foreign code gave. **`Reply`** is the call's monitor's alias, which the call's end deactivates, dropping a late answer; one foreign code gave back is `{foreign_reply, Reply, D, B}`, `D` its answer's descriptor.
- **A call** (§6.6) monitors the callee and writes its `ern_calls` row, so that it ends when the callee ends, by the monitor, or restarts, by a notice to each alias noted against it. **A compute** (§8.7) is a call's wait over an alias that takes one answer, `compute/3`, its frame the call's first note, which the peer's gateway records before its worker reads the frame; the peer's reaper starts the process only once the note names it (`is_noted/2`), so that a second note that came first leaves it never run, and the process runs `computing/2`, which lets the note go and answers the value, or the fault's cause and trace, its own end then `{ern, carried, Cause, Trace}`, which no report reads; a process that ends unanswering tells the caller its `Reason` through the note. Ernest answers `{Reply, answered, V}` and foreign code `{Reply, V}`, the form §8.4 gives it, and so does Ernest to a `{foreign_reply, Reply, D, B}`, its answer exposed; a program's call checks only the second form, against the reply's descriptor the compiler passes it (`call/4`, `call_forever/3`), and the runtime's own calls (`call/3`, `call_forever/2`) check nothing.
- **`restarting/2`** (§6.9) runs the function in a `try`, and on a fault within the limit begins a fresh run and runs it again; past the limit the fault goes on to `run/1`. `fresh_run/0` asks the reaper, the clock and the terminal to cancel what the process asked of them, its waits and fault subscription, its alarms, its keys, the reaper and the clock each ending every delivery to the process (`abandoned/1`), then empties the mailbox, and then ends the pending calls. For a restart asked for (E.22), the outermost one keeps an alias made with `priority` in the `{restart, Pid}` row, to which `Supervisor`'s private shim `ask_restart/1` sends `'$ern_restart'`; every emitted `receive`, and every call's wait (`call/4`, `call_forever/3`, which `call/3` and `call_forever/2` reach), take it first and call `restart_now/0`. `start_cause/0`, another shim, answers `First`, `AfterFault` or `Asked`, and `spawn_order/1`, the third, a process's place in the order of spawns, which `RestForOne` reads.
- **A time** (§6.3) is a deadline on the monotonic clock (`deadline/1`); `remaining/1` caps a wait at the host's longest timer, and the wait is taken again in slices. The clock holds an alarm after milliseconds so, and an alarm at a time by the time itself, read against the host's clock (E.15): the host's timers count monotonic time, so the clock's process monitors the host's time offset and, at each change, sets every alarm at a time again (`set_again/1`). It monitors each process it holds an alarm of, one monitor for each, gone with its last alarm, and forgets an ended process's alarms as it forgets a restarted one's (`alarms_canceled/2`), so that an alarm whose process has ended is no source (§8.6).
- **The reaper** `spawn_monitor`s every process a program spawns, and monitors every listener, socket and running program a system module opens (`opened/2`), writing each one's row, and holds the monitors of them (§6.9), and those of a `monitor` of a process it did not start. Each `Down` is delivered by `wrapped/3`, in a counted process of its own. `spawnMonitored`'s monitor, and the runner's of the entry process, are made with the spawn. The runtime's own processes, each delivery the reaper starts, a `Down`'s and a fault report's, each process kept for an adapted address and each of the end's tellers, are linked to the reaper, the two last through `reaper_held/2`, and each alarm's delivery to the clock, so that they end as these are stopped at the program's end, and each delivery of a subscriber's `wrap(reply)` to the teller that starts it; all three trap exits, so that one that ends otherwise than it returns, killed from foreign code, ends nothing else, and is no source any more, its row of deliveries gone (`undelivered/2`), and the monitors one of the reaper's made go with it, a teller's (`held_ended/3`). A delivery ends with its recipient (§6.9): where the reaper learns of a process's end, it ends every delivery to it, whichever process started it (`abandoned/1`), as a restart does, each row taken before the delivery is killed, and a call the delivery's function was making ended with it; and a delivery whose recipient has ended already, an alarm's that fires after its process's end among them, ends before it starts (`counted_link/2`).
- **A process of the runtime's own that acts for another** (§6.9, §6.5), each delivery, the terminal's courier of a subscriber and a process kept for an adapted address whose target is on this node, holds what stands for its row in its dictionary, an `#acting{}` (`acting_for/1`): the process it delivers to, which `Process.current` answers (`current/0`), and which owns what the function opens, since `Os` and `Tcp` take the owner from `Process.current`; the marks of the `Code.load`s called in it, which its spawns take for their root in place of that process's (`parent/0`, `rooting/0`), so that the process it acts for runs on beside it unmarked; and the site of the binding such a load evaluates (`initializing/1`, `site/0`). A spawn sends the reaper what its root is read from, the spawner, the process acted for or the mark. Where the target is on another node, the process kept acts for none.
- **The runtime's one checker** is the foreign boundary's, one per address and mailbox type, living as long as the process behind it, so that a compiled `receive` never sees a foreign message.
- **A deadlock** (§8.6) is found by the reaper's look, which comes after 100 ms without a message, and again after 100 ms while nothing can deliver but a process still runs; while something can still deliver it comes once a second, since a deadlock can begin only once that has ended and a program at rest pays a wake-up of the host for each look (the log's *The Reaper's Look at Rest*). Where nothing can still deliver, by `ern_held`'s `{source, Holder}` rows, the calls in `ern_calls` on a system or an opened process, the system processes' status and mail, and the counts in `ern_processes`, it takes two snapshots of every live process's status and reductions; equal snapshots, all `waiting`, with nothing able to deliver between them, make the runner fault the entry process with `deadlock`. The check is off while the shell holds the terminal. A module loaded on its first call counts as a foreign call, since `ern_rt` is the `error_handler` of every process the runtime starts and loads inside `in_foreign/1`.
- **Sources** (§8.6) are counted, not asked about: the clock counts an alarm until it is delivered, `stdin` a request until its answer, the terminal its subscriptions, and the reaper a monitor on a process the runtime did not start, until its `Down` is delivered. A call to a system process, a listener, a socket or a running program counts from its `ern_calls` row, written before the request is sent. A timed `receive` and `Address.call` count themselves in and out, and a foreign call runs inside `in_foreign/1`, but for a standard library function without a mailbox type, which waits on no process. The compiler writes a foreign call in place, its exception turned into a fault by `ern_boundary:raised/6` and its return checked as its type needs: `any` not at all, `int`, `bool`, `bytes` and `float` in place, a value with no function, float, address or `Reply` in it by `check/3`, and any other, `char` and `string` among them, by `value/3`. The standard library's own return is not checked, and its own arguments are not exposed (§8.4).
- **Standard input** is a port on descriptor 0, opened per request and closed at its answer; the terminal reads keys through it, in `stty`'s raw mode. For a run, `run_main` sets standard output and standard error to `latin1`, so that they take bytes (§8.2).
- **Faults** are reported by the reaper (E.21), at a process's end with a fault and at a restart. `report/5` builds the `FaultReport`, its `spawnedBy` the name `ern_peer:name/1` gives the spawning peer's node, gives it and the peer to the run's `faults` function, and delivers it to each subscriber in `ern_faults` in a counted process. `Process.status` reads `ern_processes`, the host's status and `ern_calls`.
- **`run/1`** wraps every process body, so that an exception is a fault: `badarith` is `Fault("division by zero")`, and a thrown `{ern, fault, Cause}` is `Fault(Cause)`. `run_main` sets the host's backtrace depth to 64, the host's most, the frames `ern_code:running/1` reads (E.28), of which a fault's trace shows the innermost twelve (E.21): a raise saves that many frames.
- **The code table** (§8.7) is `ern_code`'s, an ETS bag of that name, made at its first use by a process of its own that holds it for the host's life, since the units it describes outlive a run. `loaded/2` puts a unit's rows from its `'$code'/0` as it loads, given its compiled form, in `ern_cli`'s load of a program and the shell's, and `loaded/1` one the host loaded from the code path, the runtime's of the standard library and of a module on demand (`load/1`), its compiled form read from the path; each passes over a unit whose code it holds already: each function and type by `{hash, Hash}`, a function with its reach, each lambda and local fn a spawn on a peer starts by `{lambda, Hash, Position}`, the unit's own row by `{unit, Unit}` with its version, its keys and the units it calls, each binding by `{binding, QualifiedName, Hash}` with the key `ern_rt:binding_value/2` reads its value under, each foreign declaration's implementation and function by `{foreign, QualifiedName}`, the name as text, as a peer's frame names it, and the unit's version and keys by `{unit, Unit}`. A unit no file holds, a load's or an input's of the shell, or an arrival, is put there with `loaded/3`, which keeps what its compiled form records, `#recorded{}`, in a row of its own, `{forms, Unit}`; a build's unit's are read from the `.erc` the host loaded it from at the first request that needs them and kept in the same row from then on (`kept/2`), so that `forms/1` answers both from one place, the exchange's reading of a unit (§11.2), which reads each unit once in a request. `linkable/1` answers a definition another unit's code can reach by its hash, a type, or a function its unit exports, the answering unit's (`answering/1`), and `valued/1` the unit and getter of a binding held with its value, by which an arrival links. A unit loaded again with other code replaces its rows, and `unloaded/1`, which the shell calls where it deletes a module, takes them, its forms among them. `function/2`, a unit's function by its qualified name, `function_text/2`, a function's name as a trace shows it, `spawnable/1`, `holders/1`, the units that hold an identity, `forms/1`, `called/1`, the units a unit's code reaches through its calls, itself among them, `absent_binding/2`, each binding of a reach read in the called units that hold it, `absent_binding/1`, each read in any unit that holds it, which the exchange asks before any code crosses, `foreign/2`, `declared/1` and `declared/2`, a foreign declaration a unit no file holds records, an arrival's lacked one among them, by a row `{declared, QualifiedName}` the load puts beside the record, of any unit or of the units a function's code calls, and `present/1` are the lookups; where several units hold an identity, `answering/1` takes the latest loaded whose initializers have run (`ern_rt:is_initialized/1`), else, for a function, the latest loaded, and `value/1` the latest initialized or `absent` (§8.7, §11.2); a peer's spawn reads `spawnable/1`, then `present/1` for each foreign declaration of the reach, then asks the run's reaper for each binding's value before it starts the process. `running/1` is `Code.running` (E.28): the units and functions the rows `{hash, Hash}` of the declaration name, a frame of any of them in a process's `current_stacktrace` listing the process, so that the build's unit and a load's or an arrival's of the same definition count alike and no row is added; `hashes/1` is `Code.hashes`, the `.erc`'s `#recorded{}` read by `ern_canonical:read/1`. `is_free/1`, `is_held/2`, `fresh_unit/1`, `unit_beside/2` and `placement/4` name and place a unit as the shell's load and `Code.load` place one: a module of a compiled form held, loaded as it is, or made from its forms, and a unit an earlier load made of the same forms, linked to the same units, a refused load's among them, taken as it is. `binding_keys/1` gives the keys of the values a refused load of either erases, once `ern_rt:kill_started/1` has killed what its evaluation started; its units stay loaded and in the table. `counts/0` reads the host's limits (§11.2), the atoms from `erlang:system_info(atom_count)` and `atom_limit`, and the module names, the export entries and the lambdas from the index tables of `erlang:system_info(info)`, which the host reports nowhere else. That text is the host's whole state, so it is read at the first load and where a count nears its line, and not at each load: the table `ern_code_sums`, which the code table's holder makes beside it, keeps a sum of each count, the host's own from the first load, to which each unit loaded adds a module name, its export and import tables' counts and its table of lambdas' count (`summed/1`); `nearing/0` compares the sums and the atoms, read at each load, with four fifths of their limits, reads the host's counts where one reaches it, gives a line for each the host's own count has brought there and not said before, and takes the host's counts as its sums; `ern_cli:say_limits/0` says the lines, at a run's start through its `init`, at each arrival and `Code.load`, and at each load of the shell's.
- **The exchange** (§8.7) is `ern_exchange`'s, in `cli` beside the gateway, one registered process on each node from its start, which keeps its exchanges in its own state and no table. As a spawner's node it answers a peer's `{reach_request, Exchange, Identity}` with `{reach, Exchange, Identities, Bindings, Foreigns}`, the hashes of the definitions the function's definition reaches through the forms' `{hash, H}` references, code and types, the bindings the function's reach names and its foreign declarations, each `{Name, HostModule, HostFunction, Scheme, Printing}`, the scheme and the printing from what the declaring unit records, read from `ern_code`'s `spawnable/1`, `holders/1`, `forms/1` and `foreign/2`, a foreign function spawned by its name, `{foreign, Names}`, its declaration alone; and `{lacks, Exchange, Hashes}` with a `{code_frame, Exchange, Hashes, Bytes, References, Sources}` for each definition alone or group, dependencies first, `Bytes` what `ern_canonical:hashed/1` gives of its forms written by `bytes/1`, `Sources` the external term format of each member's `{Name, Sourced, Printing, Calls}` as its unit records them, its name as text, its sourced form, what prints a type in a cause as its module writes it, its namespace and the prelude names its types shadow, as text (§8.7, §11.5), and the foreign declarations its form calls, each `{Name, HostModule, HostFunction, Printing}` as text, found as the reach's are (`calls/2`), a frame of none where one is found nowhere; it keeps nothing between the two, and answers `{reach, Exchange, none}` where it no longer holds what is asked. As the node asked, it takes from the gateway's worker each spawn or compute whose identity the code table lacks, asks the spawner's node, answers the identities that are not `linkable/1`, a definition held without its function exported among them (§8.7, §11.1), and holds per exchange the frames that wait, the reach, the hashes still lacked, the code frames verified (`ern_canonical:verified/2`), their sources read with `[safe]` once the forms are, each the form once its lines are taken out and its declarations those its form calls (`framed/4`), as `#definition{}`s with their declarations apart from the code table; two spawns of one identity share one exchange (`asked`). `NotLoaded` comes from `ern_peer:reach_lacked/2`, a foreign declaration's module that is not here or its function not in it at the declaration's arity, the module loaded first where it is on the code path, so that both are atoms of the node's once it answers none, or a binding without its value; every answer comes from `ern_peer:failed/4`, said through `ern_gateway:outcome/2`; a whole reach goes to `received/5`, which makes it one unit under the pool's next name (`ern_arrival:received/5`, `name/1`) and reads each spawn and compute that waits again with `ern_peer:frame/2` (`started/1`), or answers `Other` with the reason. A frame it cannot read, a field, a form whose hash is not the one named, a source that is not its form, a frame out of its order or from another node than the one asked, ends the connection as the worker's does, and a loss, which the worker tells it after its own frames, drops the exchanges asked of that node, their other nodes' spawns asking anew. The exchange keeps the prelude's environment, built at its first arrival, and the pool's count.
- **An arrival** (§8.7, §11.2) is `ern_arrival`'s: a reach's definitions, each named by its frame's name as text, a type by its form's qualified name, made a `#unit{}` with namespace and site namespace `[]` and every function exported, a binding that crossed in its group left out and named by its identity in its group's other forms; a foreign declaration of the reach a `#foreign_function{}` of the unit's own, the host's module and function its declaration names, atoms the node has once `ern_peer:reach_lacked/2` has found both, and so is each foreign function the definitions call beyond the reach, from its code frame's declaration, where `ern_peer:foreign_lacked/1` finds both (`called_foreign/3`); the reaches `ern_canonical:unit_reaches/2` computes from the forms and the code table's; and the link, a function by its hash to `linkable/1`'s unit and function, a binding by its identity to `valued/1`'s getter, a name of the library's or the prelude's as the build links it from the prelude's environment (`ern_compile:named/2`), and a type to its form, the unit's own, one a held unit keeps (`forms/1`), or the environment's. What the definitions name beyond the spawned function's reach that the node lacks, a binding without its value or a foreign function whose module or function is not here, is linked to a function of the unit's own, `'$lacked_K'`, which the emitter writes from the unit's `lacked` and which faults naming it, `the binding Q has no value here`, `the module M, which Q calls, is not here`; no process reaches one, since a spawn whose reach names it is answered `NotLoaded` first, and the code table lists none of them (`lacked/2`). A binding of the reach without its value, which `reach_lacked/2` answered first, is still refused. The unit records every foreign declaration the reach and the frames carried, a lacked one among them with the host's module and function each an atom of the node's where it has one and text where it has none (`held/1`), and no other row names a lacked one, so `spawnable/1` finds nothing for it; `ern_code:declared/1,2` reads it from the rows the load puts beside the record, by which a held function's `NotLoaded` names its module (`ern_peer`'s `lacked_module/2`) and the exchange's `implementations/2` ships it onward in a reach or a code frame as the node's own, a third node linking it as it links any, and answers the reach of it spawned by its name as its declaration (`reach/1`), the peer finding what it lacks itself. Each definition and foreign function prints a type in a check's cause as its module writes it, the emitter's `printing/2` setting the scope the frame gave over the link's state, a name no atom of the node names leaving it no module's. It is compiled by `ern_compile:compiled/2`, loaded by `code:atomic_load/1`, one batch, off the code path, and put in the code table with what it records, the definitions as they arrived; any failure is the peer's reason in a line. The pool's name is `ern$N`, the first the host holds no unit of from the exchange's count (`name/1`), which grows for the node's life, since no unit is let go (§11.2).
- **`Code.load`** (Appendix E.28, §11.2) is `ern_code_load`'s, run in the calling process: the module at the path, its root from its namespace's depth, and its reach, each module found by namespace under that root and then on the run's load path, which `ern_cli:load_path/0` keeps from the run's start, read as `ern run` reads one, its forms verified against their hashes (`ern_canonical:is_verified/1`) and its interface and the standard library's checked as `ern run` checks them, `Invalid` and `NotFound` its refusals. Each module is placed as a unit (`place/2`, `ern_code:placement/4`): the node's own where it holds that very code and each module it uses is under its Erlang name, or where an earlier load made a unit of the same forms linked to the same units; its compiled form loaded as it is where the host holds no code of its name and each module it uses is under its Erlang name; else made from its forms by `ern_compile:from_compiled/5`, under its Erlang name where that is free and a name of its own otherwise, linked to the units its dependencies were placed as. The units it makes are loaded by one `code:atomic_load/1` and put in the code table, a refusal of the host's answering `Other` with the reason; then the bindings of each unit without values, in `ern_rt:ordered/1`'s order, run in the caller under a mark of its own (`ern_rt:rooting/0`), or, in a process acting for another, in what stands for its row, its site given back after, and a fault undoes the load as the shell's `withdraw/2` does, what its evaluation started killed and its bindings' values erased, its units left loaded, out of reach, so that the module loaded again, unchanged, makes no unit (§11.2), and answers `Site faulted: cause` (§8.5).

### The runner

`run_main(EntryPoint, Site, Options)` makes the tables, starts the reaper and the system processes `stdout`, `stderr`, `stdin`, `fs`, `terminal`, `tcp`, `os` and `clock`, and binds each under `persistent_term`, where `ern_rt:system_process/1` reads it. In the entry process it runs the standard library's initializers, then `Opts`' `init`, then `Main` (§8.5); the runner's `init` is `ern_rt:init_modules/1` over the modules it loaded, the shell's own among them for `ern shell`, each set ordered by its `'$deps'/0`. It waits for the entry process, a deadlock, `Os.exit`, a stream gone, or a signal; then tells the subscribers of `Os.termination` (`told/3`, §8.6), each by a teller of its own, a process that has its `wrap(reply)` delivered by a delivery of its own, noted against the subscriber, which the subscriber's end or restart ends, and waits on the reply as a call waits on its callee, so that the subscriber's end or restart ends the wait, held by the reaper as a delivery is and monitored by the runner, so that a teller that ends before its word, as one does whose delivery foreign code kills before it arrives, ends nothing else and the end no longer waits for its subscriber, which it says, and waits for every teller, telling at once a subscription made meanwhile, which `termination/1` tells the runner of, and ending the wait at once at an `Os.exit` or a second termination; then ends every live process with `ProgramEnd` and flushes `stdout` and `stderr`, each answering whether its stream took what was pending, by asking its port's queue at the host's finest wait, a millisecond, until it is empty or the port has ended with its reader (the log's *The Tests Wait on What They Mean*); and returns `{gone, Stream}` where one did not (§8.6), and otherwise `ok`, `killed`, `{fault, Msg}`, `{fault, Msg, Trace}`, `{initializer_fault, Site, Msg}` for a top-level binding that faulted before `Main` ran (§8.5), `{exit, Status}`, `{gone, Stream}` or `{signal, Signal}`. A deadlock, and a fault a system process finds, are made the entry process's fault. A reference tags each launch, under `persistent_term`'s `{ern_rt, launch}` while it runs, which each adapted address its processes make holds, and the reaper's late notices of it are flushed.

The options are `faults`, the runtime's own subscriber; `say`, the function that writes the runtime's own line on standard error, `ern_carrier:say/1` for `ern run` and `ern test`, which carries the line's time where a fault's line does (§11.2), and else a line written to `stderr` as it is; `stdout` and `stderr`, a function or `{fd, N}`, a port that learns when a write fails (§8.2); `stdin` and `keys`, a function answering each read, and `time`, the clock the `Clock` process reads, for tests; `init`; `arguments`; `exit => fault`, for the shell and `ern test` (§11.2); and `flush`, for the shell, which writes what its sinks passed to its screen once the end's wait is over, `stdout` and `stderr` having first taken what was sent them, so that what a program wrote while the end waited is not ended with the screen (§8.6). A `Write` is answered once the function or the port has taken the bytes.

### The system processes

- `ern_fs`, `ern_tty` and `ern_tcp` are the processes behind `Fs`, `Terminal` and `Tcp`, speaking their modules' message types. A socket's and a listener's process traps exits, so that however it ends it closes its host socket itself; a socket with bytes the far end has not taken hands its host socket to a closer of its own, `lingering/4`, since the host's close would hold it open for as long as the far end takes nothing. `ern_tty_signal`, added to OTP's signal server at the first subscription, sends the terminal's process each `SIGWINCH`.
- `Tcp`'s reference answers `Listen` and `Connect`, and each socket is a process over its `gen_tcp` port speaking `Tcp.SocketMsg`, alive until `Tcp.close`. A waiting request carries its milliseconds, and the socket, the listener's worker or the connect's decides the timeout, so that a request that timed out took nothing. A waiting request is a source against its holder, and listeners and sockets are recorded as opened.
- `ern_os` (E.23) answers `Start` with the program's process, linked, opened, and a source until the program ends. That process owns a port of `ern_exec` (`erl/runtime/c_src/ern_exec.c`), which runs the program in a process group of its own, speaks frames of a length and a tag for the input, the output, standard error, the acknowledgments and the exit status, and kills the group when the port closes. The program's process speaks `Os.ProgramMsg` and holds the time limit; `Os.run` is Ernest over it. Run with no program, the helper writes back the user it runs as and its environment, which `ern_os:host/0` reads once as the program starts, for `Os.user` and `Os.environment`. The environment is the one `ern` was started in (E.23): the launcher keeps what it and the host's start change ([`install.md`](install.md), *The launcher*), and the helper puts each back before it answers or runs a program. A program it runs starts with every signal at the host's default, since an ignored signal stays ignored in a program started.

### The standard library

Appendix E is one Erlang module per namespace, `ern@list` and so on, compiled by `make` from `src/stdlib/` into `build/stdlib`; the standard library is every `ern@` module in a `stdlib` directory on the code path. `ern build` lets its source root take prelude namespaces (`is_stdlib_root/1`, §4.2). `ern_prelude` holds §9 alone: a module declares its own types, and a prelude operation in a type's namespace, `Int.compare`, is in that type's module. Every contract is Appendix E's. `erl/runtime/test/ern_stdlib_tests.erl` calls each module by the ABI, each function found by its name (`ern_named`). `prelude_targets_test`, in `erl/emitter/test/ern_emitter_tests.erl`, holds every name of `ern_prelude:values/0` exported by its module with its type's arity, and `stdlib_targets_test`, in `erl/runtime/test/ern_doc_tests.erl`, does the same for the standard library, each the function at the position its interface gives it.

- **The shims.** A shimmed module's Erlang helper is named `ern_` and the module's name. `ern_char` reads E.6's predicates above ASCII from the host's `unicode_util` tables, the ones `string` follows (the log's *Char Reads the Host's Tables*). `ern_map`, `ern_set`, `ern_string`, `ern_path` and `ern_bytes` hold those of their sections' primitives that no host function is as it stands: one whose answer no Ernest value is, one that takes an atom, one that raises where Ernest answers `None`, or one over the runtime's representation, `Set`'s tag or a path's syntax. The rest are host functions named in their `foreign fn`s, and `primitives_test` holds each module's `foreign fn`s equal to the primitives its section names. `ern_float:text/1` writes a `Float` for `Float.toString` and `ern_show`. A `Set` is `{set, S}`, `S` a version 2 `sets:set`, so that it is not a `Map`.
- **Printing.** `ern_io:show/2` and `ern_io:debug/2` write through `ern_show`, which reads a value by the descriptor the compiler passes for its type, `ern_boundary`'s with field names and abstract types added; the `any` descriptor falls back to §8.4's representation (E.1). The shell prints through `ern_show` with a depth and a length.
- **The bit syntax's checks**, those of §5.11 and §7.4 that the host's bit syntax does not make, are `ern_bits`, which the compiled bitstring code calls.
- **The foreign boundary** is `ern_boundary` (§8.4). `expose/2,3` replaces each address in a foreign function's argument, a message to a foreign address, or an answer to a `Reply` foreign code gave, with a checker that checks each message foreign code sends it, and in place of one that fails sends the receiver `{'$ern_fault', Cause}`, which every wait the emitter writes, and `ern_rt`'s waits for an answer, take before any other clause but the restart. The compiler writes the call in place; `raised/6` turns its exception into a fault, and `check/3` or `value/3` checks its return. `value/3` also checks a reply foreign code gave and wraps each function value so that its result is checked at every call. Both, and the checker's check of a message, are `conformed/3`, which matches a float only where it is no negative zero, and makes a value that fails so again with `0.0` for each (§3.1) and matches it again, so that a value is walked once unless it holds one or faults.

### The libraries' primitives

A library under `src/libs/` stands on the host as the standard library does, and the primitives it needs in Erlang are an application of their own under `erl/`, named for the library, on the code path as every application is (§11.2). `erl/json` is `libs/json`'s: `ern_json:parse/1` builds Appendix G.6's values through `json:decode/3`'s callbacks as the host reads, and turns the host's three errors into `Json.Error`, and `ern_json:format/1` gives `json:format/3` the host's terms, by which it lays out an array, and an encoder that writes an object's members in the order of their names.

## The tools

`ern_cli:ern/2` takes the job from the first word, each job's options a getopt spec of its own; `no_job/1` and `old_option/2` refuse an old spelling with the new one. `ern_build` holds the build and what every other job takes from it, a module's source and namespace, an interface, a file written whole, and it alone of the jobs is in the compiler's hash (`compiler_modules/0`, §11.1), so that a change to another job recompiles nothing. `write_whole/2` and `write_whole/3` write every file a job writes: to a dot-name beside it, the writer's own, made there or not at all, so that a name another planted is never written through, its mode set before its data, then renamed into its place, a link followed. `write_output/2` and `write_output/3` write so in the place itself, a link replaced: a build's outputs, and the configuration directory's files, which `ern config` writes into a directory it made, closed, and found empty. `ern run`, `ern test` and `ern shell` also install `ern_signals`, for a test that calls the job, and lower the host's logger to warnings.

- **`ern build`**, in file or directory mode: modules from paths (§11.1, §4.2), with `namespace_clash` refusing a module namespace that is a type namespace of its parent; dependencies from a parse-only scan of qualified names; a `digraph` for order and cycles. Per module, the dependencies' interfaces from the build directory, §11.1's recompile rule over the `ErnI` hashes, the `references` against the hashes the dependencies' interfaces hold, and `stdlib_hash/1`, then check and canonical forms; a dependent within the build is checked against the interface as its compiled form will hold it, with its definitions' hashes and positions (`ern_interface:written/1`). A checked module is emitted and written once every module of the build its forms name by name is checked (`built/3`, `referenced/3`), linked with their interfaces (`ern_typecheck:with_interfaces/2`), so that a module of the standard library's own build that names another by a prelude name or an operator alone, no dependency of §11.1's, calls it by its position whatever order the build takes; `compiled_in_order/3` compiles parsed modules in a given order in memory, which a test reorders. Directory mode sweeps stale `.erc` files.
- **`ern run`** reads the `.erc`, derives the root from its namespace's depth, puts the root and the `--load-path` roots on the code path, loads the dependencies by namespace, and calls `run_main`. A module the host holds already, with the same code from the same file, is taken as it is, as `ern test` over a directory meets one for each file; other code of its name is an earlier program's in the same host, whose old code is purged before the load (`loaded_unit/3`). `reporting/2` gives the run `report_fault/3` as `faults`, writing through standard error's process, with `, spawned by the peer X` after the cause for a process a peer spawned, and, from the launcher, `{fd, 1}`, `{fd, 2}` and the stamp §11.2 describes; a test calling `ern_cli:ern/2` gets standard error on its own device. `outcome/2` gives §11.2's status. Given `--config-dir` and no `.erc` it starts a bare node (§8.7): `as_node/4` refuses one whose configuration has no `listen` before it answers the launcher's first start (`listens/3`), the `--load-path` roots go on the code path and are loaded whole as a node's are, and `run_bare/2` calls `run_main` with an entry that waits for the node's end (`waits/0`) under the site `bare node`, its `init` saying the host's limits alone, since `run_main` evaluates the standard library's bindings in every run (§8.5).
- **`ern shell`** loads a file and names its entry point, which the shell spawns beside it, or none (`shell_entry/4`); see *The shell* below.
- **`ern test`** is `run_tests/4`: it calls the module's `'$tests'/0` and runs each test in a monitored process of its own. The running test is recorded before it starts, in a table of `run_tests/4`'s own, so that its fault is its line and not a report, and `ern_rt:deadlock_victim/1` names it to the reaper (§11.2).
- **`ern format`** is `ern_format:format/1`: it lexes with the comments, parses, walks the tree into a template of the layout, a function per production, and walks the template in source order with a cursor over the tokens, placing each comment beside its token; `ern_pretty` prints it in 100 columns. `ern_format:markdown/1` lays out a CommonMark text's Ernest blocks.
- **`ern doc`** renders a page with `ern_page:page/1` from the two chunks, compiling a source in memory first; `doc_dir/3` writes each of a directory's pages that is missing or older than what it is made from, by `outdated/2`, and its index where the index's text differs. It compiles nothing where every page is current; otherwise `read_compiled/2` reads each module whose `.erc` in the build root is as new as its source, and `ern_build:compile_in_memory/5` compiles the rest. With `--man`, `ern_page:manual/1` renders it through the `roff` of `libs/markdown`, which `make` copies into `build/shell` with `libs/ansi`, which it uses; the job lays its pages out in a started runtime, `ern_cli`'s `in_runtime/2`, so that the library's top-level bindings and the standard library's have their values, and starts none where no page is to be written. `ern(1)` is `tools/manual.ern`'s, which `make manual` runs to render §11 of the report.
- **`ern config`** writes Appendix C's file and an Ed25519 key pair (§11.3).
- **`ern reload`** and **`ern stop`** send the node that holds their directory's `ernest.pid` hangup and termination, through the helper's `node` mode (`ern_node:signaled/2`, `stopped/1`), which reads the number under its own lock and signals only where the node's lock is held; `stop` then waits on the node's lock, released by the host when the node has ended. A node holds the file through the helper's `lock` mode, a port the runner's process owns until the host ends (`ern_node:pid_written/1`). A node takes hangup as a reload, `ern_signals` asking `ern_carrier:reload/0`, and ends in order: the reaper waits for the deaths of the processes it ended, and `ern_carrier:depart/0` first sends each connected peer the `node_ends` frame, by which the peer says it ended and not that it was lost, then asks each the host's own question before the connections close (§8.7).

### The shell

The shell is an Ernest program over `Terminal`: `src/shell/shell.ern` and its six modules under `src/shell/shell/`, compiled by `make` into `build/shell` with `libs/markdown` and `libs/ansi` beside it. [`src/shell/README.md`](../src/shell/README.md) guides a reader through the code, and [`shell_design.md`](shell_design.md) holds the design. `ern_cli:shell/3` starts it.

`ern_shell` is the front end the shell reaches through `foreign fn`. It holds the session and checks an input with `ern_typecheck:check/4`, the session being a scope of its own. `:load` brings each module as a unit of its Erlang name, or, where the node holds other code of that name, of a name of its own, `ern@counter$2` (`compile_unit/5`), a module loaded from its compiled form placed as `Code.load` places one (`compiled_unit/5`, `ern_code:placement/4`), loaded as it is, made a unit from what its `.erc` records as it is installed (`install_one/2`, `ern_compile:from_compiled/5`), or a unit the node holds of the same code, a build's or a refused load's, taken as it is; a load places each module after the modules it uses, so that each is compiled, or made from its forms, to call the units they were placed as: a module of the load path is found and placed before the module that uses it is compiled, and a module of the source set is compiled before a module of the load path that uses it (`#placing{}`, `needed_placed/3`), a module that uses one whose placing waits on it being a cycle, refused as `ern build` refuses one (`dependency_placed/3`), and the modules are installed in that order (`in_dependency_order/1`); a module whose source the session holds is its current compiled form where one qualifies, beside its source or on the load path (`current_form/4`, checked against the interfaces by `ern_build:is_compiled_against/4`), and is compiled otherwise; `:reload` brings each version so, beside the previous one, unloading nothing, and compiles again what `ern build` would compile again for it, a dependent whose forms reference a hash it changed among them (`stale_users/3`). A type of a reloaded module whose hash the reload changed moves, in what the session held before it, to the previous version's namespace, `Counter$1` (`versioned/3`): the session's own interfaces are rewritten to name it there, and the previous versions' interfaces, `#session.previous`, hold its types, constructors and members, which the checker is given beside the loaded modules' (`checked_interfaces/1`), and which reach that version's unit through `#session.units`. A previous version's type whose hash a later reload declares again goes back to the current version (`returned/3`), its previous interface losing it and dropped with its unit once it holds no type; every declaration of the session is named under `$Session` in its form and in `'$code'/0` (`?SESSION_NAMESPACE`), and a type whose hash an earlier input's type has is that type (`redeclared/2`); a holder is counted as evaluated as it binds. `:reload` compiles again each declaring input in scope whose forms reference a hash it changed, as a new version of the input, from the text and the names kept at its run (`reached_inputs/2`, `compiled_again/2`, `input_text/2`), and one that no longer compiles goes from scope with its diagnostic (`out_of_scope/3`); a reload's version names its sites under the version's namespace (`site_namespace/2`). A load evaluates each module's bindings in a process of its own that lives while the session runs (`evaluate/3`, `evaluators/0`), which `:processes` leaves out; a refused load kills what each evaluation started and those processes, erases the values the bindings stored, and leaves the units it brought loaded and in the code table, out of scope (`withdraw/2`), so that a function of one a process running before the load holds runs on; the module refused again, unchanged, makes no unit, a source compiled beside its Erlang name taking the unit a refused load made of the same code (`kept_or_fresh/5`). An input that declares or builds a function value, which the emitter's chunk says, is kept while the session runs, and any other is deleted and purged once its answer is in (`release/1`); a holder alone is collected when nothing reaches it (`collected/1`). A `let` with a pattern is checked as the block `{ let p = e; #(names) }`, and its names are held by a module with a getter each, each a binding whose hash is the input's (Appendix H). The session keeps an input's interface as compiled, with its definitions' hashes, by which a later input's forms name them. `Shift-Tab` is `documentation/1`, a name's page, or `signature/1`, a call's signature printed by `ern_types:format_call/4` in three parts, the argument at the cursor the middle one. `:doc` is `ern_page`'s `declaration/2`, `session_declaration/3` or `module_head/1`.

Outside `make test-full`, `make load` runs [`memory.md`](memory.md)'s loads: `test/ern_load.erl` runs each program under `test/fixtures/load/`, and the shell under a session it writes, through `ern_cli:ern/1` in a node of its own. `make bench` is the measuring machine: `test/ern_bench.erl` sets the operations of `test/fixtures/bench/bench.ern` beside Erlang's, `test/ern_measure.erl` every function of the library beside the host's, `test/ern_node_costs.erl` the costs between two nodes of `test/fixtures/peers/`, and `test/ern_code_costs.erl` the costs of code that crosses, writing and building the programs it measures with and starting the nodes they run on, each of which loads `test/fixtures/bench/ern_code_probe.erl`, whose functions the measuring program runs there by a compute of their names: the host's trace of the exchange's steps, the runtime's reading of the host's counts, and the host's counts of each connection's packets.
