# Style

The repository's own rules for its Erlang and its C, and where they differ from widely accepted guides: for Erlang, Ericsson's *Programming Rules and Conventions* (Eriksson, Williams and Armstrong) and Inaka's *Erlang Coding Standards & Guidelines*. What a program written in Ernest looks like is [`guide/style.md`](../guide/style.md)'s, installed with the guide; the repository's Ernest follows it too. Where the guides and this file differ, this file holds. A guide serves the reader and is not a law: a rule a test checks holds always, and where another would make the code read worse, judgment goes first. `test/ern_style_tests.erl` checks what is marked *(tested)*.

## Every language

A name in the Erlang and the C is chosen as [`guide/style.md`](../guide/style.md) says the standard library chooses one, spelled as each language spells a name, `parse_module` in Erlang, and the guide's rules of form, a function on one screen and a module with one job among them, hold for them too. The repository adds these:

- A step of indentation is four spaces, and no file holds a tab, but a Makefile *(tested)*.
- A line of code is at most 100 characters; prose in markdown may be longer *(tested)*.
- A name in a namespace shared with other code carries the repository's name: an Erlang module begins `ern` *(tested)*, an Emacs Lisp symbol `ernest-`.
- The spelling test reads every tracked file of text but a proposal under `docs/proposals/`, a vendored file, `THIRD_PARTY_LICENSES` and `LICENSE` *(tested)*. A quotation keeps its author's spelling, and `-behaviour`, `LICENSE` and `prefers-color-scheme` are names of the host's or of another system's.
- `Acc`, for what a fold carries, is an abbreviation the report writes, beside the host's the guide allows.
- A record names what it holds, as the guide says of a type: `#emit_context{}`, not `#cx{}`. A function that gives a value made so is a past participle, `armed`, `held`. Longer names make longer code, and that is accepted.
- A value changing through a function is numbered, `Env1`, `Env2`, `env1` in Ernest, and a numbered name is nothing else; past two steps the function is split.
- A comment says why and cites the report section the code implements, `%% Report §8.4: ...`, `// Report §11.2: ...`; the names say what it does.

## Erlang

For the toolchain under `erl/`.

- **Every module is `ern_<thing>`**, `<thing>` unique across the repository and not repeating its application, which its directory names; a vendored file keeps its upstream name. A module compiled from Ernest is `ern@<namespace>`, the path with `@` for `/` (report §11.1): `src/stdlib/io.ern` is `ern@io`. The log's *One Token for the Project* says why.
- **One `-export` list at the top**, in the order the functions appear *(tested)*.
- **`-spec` on every exported function** *(tested)*; a type shared between modules is a `-type` of its owner.
- **Every `receive` that can wait is named by its function under its kind**, in the module's `-receives` attributes after its `-export` list and its includes, `-receives({own_process, [loop/1]}).`, since the deadlock look reads a process that waits in the toolchain's own Erlang as one that waits as Ernest waits (report §8.6) *(tested)*. The kinds are the glossary's **Receives**. A `receive` with `after 0` waits on nothing and is named by none.
- **A shared record lives in `include/*.hrl`**, any other in its module. The only macros are the few constants that need a name.
- **Tokens and AST nodes are plain data**, records and tuples, never closures or ETS state. A value of more than three parts is a record, and so is a tuple of more than two that crosses modules: a positional tuple makes its reader count. A map whose keys are fixed is such a value, counted by its keys.
- **A precondition is `Cond orelse fail(...)` on one line**; two or more conditions are a `case`.
- **No OTP behavior for the toolchain's own processes, and no rebar3**; a callback module one of OTP's servers calls, a signal handler, is no such process. The log's *No OTP in the Toolchain* says why.
- **`make` compiles with `+debug_info -Werror`**: a warning is an error.
- **Tests are EUnit**, in `erl/<app>/test/`, or in `test/` when they span applications. A test module is `<module>_tests`, or names what it tests, `ern_grammar_tests`. A test function tests one behavior, is named after it, and has above it a comment naming what it tests: `%% report §x.y`, or a document's path.

## C

The runtime's helper, `erl/runtime/c_src/ern_exec.c`, is C99 and compiles with `-pedantic -Wall -Wextra -Werror`.

## Ernest

For every Ernest source and every Ernest block of the report and the guide. The layout is `ern format`'s (report §11.6), which `make test` holds every source to and `make format` restores, and the form and the names are [`guide/style.md`](../guide/style.md)'s, which the standard library, the shell and the examples follow, its block rule among them *(tested)*; the repository adds these, which bind its own Ernest and no program's:

- **A comment cites the report section the code implements**, `// Report §8.4: ...`, as the Erlang's does.
- **A name the report states changes only through the report**, and a new word that departs from the report's goes to the user first.

## Glossary

The names that recur across the toolchain's modules, one for each concept, in every module; the names of a program's are [`guide/style.md`](../guide/style.md)'s. A word is spelled as each language spells a name: `Descriptor` an Erlang variable, `descriptor` an Erlang function or field, an Ernest binding or parameter. The report is the authority: a concept it names takes its name. It grows as the code does, as CLAUDE.md says. A name not here is the writer's, under the rules above.

**The compiler**

- **Span**: the source a node or a diagnostic's label covers (§11.5); a token's start is its `Position`. Not `Pos` for a span.
- **Diagnostic**: an error the toolchain reports, `#diagnostic{}` (§11.5); its text is its `Message`. Not `#diag{}`, `D`, `Error`, `Msg`.
- **Env**: the names in scope as the checker reads them, the word every Hindley-Milner text uses. Not `En`, `E`. The shell's session is a `Session`, the host's variables an `Environment`.
- **TypeState**: the checker's type variables and substitution, `#type_state{}`. Not `St`, `S`.
- **Substitution**: not `S`, `Sub`, `subst`; applying one is `substitute`, not `zonk`.
- **Context**: the emitter's, `#emit_context{}`, and nothing else. Not `Cx`, `C`. The formatter's state, the descriptor builder's, a message's prefix and a source line are each named for what they hold.
- **QualifiedName**: §4.2's qualified name. Not `Q`, `QName`, `TQ`, `CQ`.
- **Namespace**: §4.2's namespace, a qualified name's prefix among it, which the AST's `namespace` field holds; beside the module's own, which the checker's env holds, a name's is the `Namespace` and the module's the `OwnNamespace`. Not `Ns`, `Prefix`, `Path`, nor `Module` for a namespace.
- **Path**: §5.6's path in a record update, `#field_set{path}`, the segments after the field's name; a file's path is a `Path`, `SourcePath`, in the build and the runner alone. The indexes through a type's arguments to a variable, which a derived `compare` follows, are a `Route`.
- **Module**: an Ernest module (§4.1); the Erlang module it compiles to is its `ErlangModule`, `ern@io`, and a build's record of one a `#build_module{}`. Not `Mod`.
- **Interface**: a compiled module's interface (§11.1), `#interface{}`. Not `Iface`, `I`.
- **Ground, Term**: §11.1's ground term, the initializer of a top-level binding whose every read is compiled to its value, `ern_emitter:ground/2`; that value is the binding's term, the interface's `terms`, a `#linked{}`'s `term`, the code table's `{term, QualifiedName, Hash}` row (`ern_code:ground/1`) and the emitter's `grounds`. Not `Constant`, `Literal`, `Inlined`.
- **Cycle, Waiting**: §4.1's cycle among modules, which the build, the runner, `Code.load` and the shell refuse in the words of `ern_build:module_cycle/1`; the modules whose load, placing or reach waits on what they use are `Waiting`, and a module met again among them is in a cycle. Not `Users`, `Walking`, `Chain`.
- **PrivateTypes**: the private types an interface carries, those its module's exported declarations name, a mailbox type an exported function receives and a type an abstract type's fields name, with those theirs name (§4.2, §11.1), the `#interface{}`'s and the checker's env's `private_types`, which `described_type/2` reads and no name resolves to.
- **Scheme**: a type scheme (§3.9), as the code has it, and beside it a declaration's requirement (§4.9), which no instance has.
- **Annotation**: a type the source writes. Not `Ann`; an AST record's `type` field holds one of the four things it holds today, each named.
- **Effect**: the `receiving` part of a function type, a mailbox type or an effect variable, or `none` where the function type receives nothing (§3.9, §6.1, Appendix H). Not `E`, `Eff`, `EffT`, `MailboxT`, nor `pure` for none.
- **Constructor**: a constructor (§3.5, §5.6); many are `constructors`. Not `Cs`, `CI`, `cons`; `cons` is `::` alone.
- **MemberOf**: the type a member belongs to, `Stack` of `fn Stack.push` (§4.8), a declaration's `member_of`; of `a.compare` (§4.9), the type variable `a`. Not `Owner`, which is a resource's process.
- **Member**: a type's member (§4.5), `compare`, `negate` or an operator; one a requirement names is a `#member{}`, and one a body writes an `#e_member{}`. Not `Method`, `Op`.
- **Requirement**: §4.9's requirement, a `fn` declaration's `needs`, its `#member{}`s; the enclosing declarations' in force are the checker's `requirement`. Not `Needs`, `Bounds`, `Constraint`, which is §3.10's equality constraint.
- **Supply**: what a requirement's member is supplied with at a use (§4.9), a `#known_member{}`, a `#required_member{}`, a `#shown_type{}`, whose `member` is `show` or `exposed`, or a service's `#service_type{}`, its message type known whole, a `#pending_member{}` until the definition ends; many are `supplies`. Not `Witness`, `Dictionary`, `Instance`.
- **Derives**: §3.5's `derives compare`, a type declaration's `derives`.
- **Restriction**: §3.9's inferred restriction; the two are `equality` and `process_only`. Not `flags`, `add_flag`, `eq`.
- **Unfixed**: §6.2's mailbox type that nothing has fixed by the end of its definition, which is `Never`, `ern_types:unfixed/2`; the mailbox types a definition's spawns and computes were given, which its end reads, are the checker's `mailboxes` (`unfixed_mailboxes/1`). Not `Open`, `Free`, `Pending`.
- **Bound**: §3.11's type bound to its node, and what binds it, which `ern_bound:binds` answers: a function, a foreign type, a resource, or an address or a reply of a bound type. Not `Local`, `Pinned`, `Sendable`.
- **Capture**: a local a lambda's body names from around it (§3.11), in the bound check; many are `captures`. Not `Free`, `Closed`, `Env`.
- **ResultType**: §4.5's result type, and "result type" in every message. Not `ret`, `Ret`, `RetT`, `R`, "return type".
- **TypeVariable**: §3.9's type variable. A record's `vars` field is named for what it holds: a scheme's `quantified`, the type state's `variables`, the checker's `locals`.
- **Descriptor**: a type's description at run time, in the emitter, the boundary and the runtime alike. Not `D`, `Desc`, `desc`; its tag for `Address(m)` is `address`, not `pid`.
- **Token**: a token, many `Tokens`, what follows one `Rest`. Not `T`, `Ts`, `Toks`, `R`; `T` and `Ts` are a type and types in a one-line scope alone.
- **Declaration, Statement, Element, Segment, Alternative**: whole words. Not `Decl`, `Stmt`, `Elem`, `Seg`, `Alt`.
- **Doc**: §2.2's doc block, and nothing else; the pretty printer's document is named for what it lays out.

**The runtime and the command line**

- **Address**: §6.5's address. Not `Addr`, `To`, `A`; an IP address is an `IpAddress`, and `Target` is `adapted`'s target (§6.5) and a link's (E.17) alone.
- **Pid**: the host's process; the Ernest value is a `Process` (E.21).
- **ProcessNumber**: §8.7's process number, the operating system's number for a running program, which `ernest.pid` holds and a signal is sent to; the file's path is a `PidFile`. Not `Pid`, which is the host's process, nor `Process`, which is E.21's.
- **Reply**: §6.6's reply. Not `Alias`, `Written`, `R`.
- **Cause**: a fault's cause (§7.3). Not `Msg`, `Text`; the trace beside it is a `Trace`. A cause that names a function the boundary alone has, a function value's (§7.4, §8.4), is a **named cause**, `ern_descriptor:named_cause()`, the text before the name and the text after it, which the boundary's `named/2` and the emitter's `named_cause/2` write the name between.
- **Trace**: §7.3's trace, the host's stack where a fault was met as text, a frame a line (E.21), `ern_rt:trace/1`, and a **failure**'s, a fault whose cause names a host error, which keeps the runtime's frames (§7.4), `failure_trace/1`; the host's stack it is written from is a `Stack`, and each of its entries a line of the trace, `trace_line/1`. Not `Frame`, which is §8.7's.
- **Reason**: §9.3's `Reason`, and nothing else. The host's exit reason is an `ExitReason`, a host's error an `Error`. Not `Raw`, `How`.
- **Site**: §6.9's spawn site, a name and its line as `ern_namespace:site_text/2` writes them, as a trace's line of Ernest code is written too (E.21). Not `At`, `Where`.
- **Ms, Deadline**: milliseconds as given (E.0 shape rule 8) and the moment they end, as the code has them; a timer's message is `deadline` in every module.
- **Look, Key**: §8.6's look for a deadlock, `ern_rt:look/0`, which the reaper makes when it has been idle a while; what it needs of a process, the process keeps in its own dictionary under the look's keys, `FOREIGN` while it is inside foreign code where its stack cannot show it (`entered_foreign/0`, `left_foreign/0`), `TIMED` while it waits with a deadline (`timed/0`, `untimed/0`) and `CALL` while it makes a call, its callee and the reply, which its end of the call and a kill read too (`pending/2`, `uncalled/0`, `killed/2`), which the look reads with the function on top of the process's stack once every process waits (`still/1`); a function that is neither a unit's nor of the toolchain's own is the **host's** there (`is_ernest/1`). Not `Mark`, which is a load's root, nor `Count`, `Flag`, `Counter`.
- **Killed**: an end the runtime gives a process from outside it, every one but the program's end, `ern_rt:killed/2`: a process of its own suspends the process, reads its `CALL` key, drops the call's records and ends it (§6.9); a `kill` of a process of another node is carried out so by that node, asked by the kill frame (§8.7). Not `Terminate`, `Exit`.
- **Monitor**: §6.9's monitor, in the reaper as elsewhere. Not `await`, `watch`, `Waiters`. The host's reference to one is a `MonitorRef`, not `Watch`, `Mon`, `MRef`, `OwnerMonitor`.
- **Runner**: §11.2's runner, the process that starts the system processes and the entry point; the launcher is `bin/ern` alone. Not `Launcher`.
- **Say**: a function that writes a line of the toolchain's own on standard error: a node's, `ern_carrier:say/1` (§8.7), the end's wait, the runtime's `say` (§8.6), and what a job decided, which `ern_build:verbose/2` gives where `--verbose` asks (§11.1, §11.2). A node's line goes to the launch's standard error process while it takes such lines and to the job's error device while none does, `ern_rt:say/2` with `ern_cli:error_line/1`. Not `Log`, `Print`.
- **SystemProcess**: a system process (§8.2, §8.4). Not `Service`, `sys`; the report's service is §6.5's and §8.7's.
- **Receives**: a module's `-receives` attributes, each a kind and the functions whose `receive` waits so (§8.6): `foreign_wait`, a wait on what the look cannot see deliver, under the `FOREIGN` key; `ernest_wait`, a wait on what the look reads, one with a deadline under the `TIMED` key; `own_process`, a wait in a process that is no program's, which the look does not read; and `answered_at_once`, a wait on an answer that comes before the look can find it waiting. Not `waits`, which named the lists the keys replaced.
- **Run**: one execution of a restarting function's `f` (§6.9), a noun, and nothing else; a launch, a running program and a test are named as such. A test case's `run` (E.24) is the verb, the function the case runs.
- **Owner**: the process that opened a resource or was given it (§6.9, E.18), and nothing else; the type a member belongs to is its MemberOf.
- **Port**: E.18's port of a socket. A host port is named for what it runs: `Helper`, `Stty`.
- **EntryPoint, EntryProcess**: the entry point and its process (§8.1, §8.6). Not `Main`.
- **Carrier**: §8.7's carrier, the host's distribution as a node runs it, `ern_carrier`; its frames go through the **Gateway**, `ern_gateway`, a worker for each peer. Not `Dist`, `Net`.
- **Holder**: the process whose address is offered as a service, which a second offer answers as `Left(holder)` (§8.7); the process that holds a source (`ern_held`) or the terminal is its `Holder` too, each in its own module.
- **Peer**: a node the configuration lists (§8.3), by its `Name` there, and by its name on the carrier, the host's `Node`, which `ern_peer` keeps beside it. Not `Remote`, `Other`. A process row's `Peer` field holds the carrier `Node` of the peer whose spawn started the process, or `none`.
- **Loss**: §8.7's loss of a peer's connection, which the gateway hands the peer's worker as `{lost, Order}`, `Order` the place among the node's moments at which the gateway learned of it, by which `ern_peer:lost/2` takes the spawns whose rows were written before it. Not `Down`, `Disconnect`, `Nodedown`, which is the host's message the gateway reads it from.
- **Idle, Taken**: the worker's ask that the gateway end it, `{idle, Node, Worker, Taken}`, made once it has run one loss and holds no kept process, the worker being one for a peer across its losses; `Taken` is the gateway's messages it has taken, which the gateway counts as it hands them (`hand/3`), and the worker ends at its `stop`.
- **Exchange**: §8.7's exchange, by which a spawn or a compute carries to a peer the definitions its function's reach names that the peer lacks, its four frames the request for a reach, the reach, the lacks and a **CodeFrame**, one definition's form, or a group's, with the identities it references and each member's name, **Sourced** form, printing and the foreign declarations its form calls, `reach_request`, `reach`, `lacks` and `code_frame`; the process of it on each node is the node's `Exchange`, `ern_exchange`. Not `Transfer`, `Sync`, `Fetch`, `Ship`, `Import`.
- **Arrival, Pool**: the unit the definitions of one exchange make on the node they arrive at, `ern_arrival`, named from the node's pool, `ern$1`, `ern$2`, the first the host holds no unit of from the exchange's count (`ern_arrival:name/1`).
- **Lacked**: what an arrival's definitions name beyond the spawned function's reach that the node lacks, each linked to one of the unit's lacked functions, `'$lacked_K'`, the unit's `lacked`, which fault naming it. Not `Stub`, `Missing`.
- **BareNode**: §8.7's bare node, `ern run --config-dir dir` with no `.erc`, which holds no definition of a program's. Not `Empty`, `Worker`, `Blank`.
- **Service, Offer, Frame**: §8.7's service as its peers name it, `{'Service', Name, Hash}`, its name and its message type's `Hash`; an offer, a service's row in `ern_offers` and its process's in `ern_offered`; a frame of the runtime's, `{ern_frame, From, Body}`, which `ern_peer:frame/2` reads, among them `{kill, Pid}`, a kill of a process of the node the frame comes to (§8.7), and `node_ends`, a node's end, which the gateway reads and says as `the peer X ended`. Not `Key`, `Registration`, `Packet`.
- **Maker**: the process that made an adapted address (§6.5), whose node applies its function, and which, while it lives, shows the address is of the launch in progress. Not `Owner`, `Creator`.
- **Launch**: one run of the runner, `run_main/3`'s, and the reference that tags it, which the runner's messages carry and an adapted address holds beside its maker, `{adapted, Function, Target, Maker, Launch}`, whose end ends the address, so that a later launch, the next run of `ern test` over a directory among them, or a later start of the node drops a message to it wherever its function would be applied, a send and a peer's frame alike (§6.5, §8.7, §11.2); the one in progress is `launch/0`'s, and what it holds, the runner, the tag, the reaper, the reporter, the arguments, `exit` and `node`, is the one row of `ern_launch`, `#launch{}`, which goes with its table at the end so that no launch erases a persistent term (the log's *The Sitting on §8.6's Bookkeeping*, its *Measured* paragraphs on the launch). Not `Run`, which is §6.9's.
- **Acting**: what stands for a row in a process of the runtime's own that runs a program's function for another, a delivery, the terminal's courier and a process kept for an adapted address whose target is on this node, `#acting{}` in its dictionary (`acting_for/1`): the process it acts for, its `recipient`, which `Process.current` answers and which owns what the function opens (§6.9, §6.5), the marks of the loads called in it, and the site of the binding they evaluate. Not `Proxy`, `Stand`, `Behalf`.
- **Kept**: the process a node keeps for an adapted address it made and a peer that sends to it, which applies the address's function to that peer's messages to the address in the order their frames came (§6.5, §8.7, §10), `ern_rt:kept/1`. Not `Applier`, which a `Down`'s process is as much (§10), nor `Relay`, `Proxy`, which is Appendix G.7's, `Adapter`.
- **Waiting**: the messages handed to a kept process and not yet applied. The gateway's worker for the peer starts the kept process as a message to the address arrives, hands it each, `{apply, Message}`, and tells it to `stop` once none waits, keeping for each a `#kept{}`, its `pid`, the worker's `monitor_ref` of it and its `waiting`, by address in the worker's `Kept`.
- **Checker**: §8.4's process in front of an address exposed to foreign code, which checks each message the foreign side sends before it reaches the process behind, one per address and mailbox type, `ern_checkers` and `ern_rt:checker_for/3`. Not `Proxy`, which is Appendix G.7's library, a proxy for a service.
- **Note**: §8.7's note of a call from another node, a row of `ern_notes` beside its row of `ern_callees`; the frame of the first is `call_waits`, of the second `call_over`, and an answer that lets a note go is `unnoted`. Not `Ticket`, `Pending`, `Registration`.
- **Compute**: §8.7's compute, a function run on a peer for its value, its frame `compute`, which is the call's first note, its answer through the caller's alias, and its end the call's second note, `call_over`; the process on the peer is the compute's **Callee**, a row beside a call's. Not `Rpc`, `Remote`, `Call`, which is §6.6's.
- **Utilization**: how busy a node is on §8.7's scale, its frame `utilization`, and the `#configuration{}`'s `utilization`, `run_queue` or `schedulers`, which says how the node measures it, and its `utilization_interval`, the milliseconds between its tellings. This node's own readings of its measures are Appendix G.4's `Utilization` library. Not `Load`, which loads code, nor `Busy`.
- **Utilizations**: the utilizations a node holds of its peers, each as the peer's last telling said it, with the moment it came and the teller's interval, in the gateway's `ern_utilizations` (`ern_peer:hold_utilization/3`, `drop_utilization/1`), which `Peer.utilizations()` answers; and the utilization a program sets with `Peer.setUtilization`, which its node tells in place of its measure (`ern_rt:set_utilization/1`, `program_utilization/0`).
- **Teller**: the process the end starts for each subscriber of `Os.termination`, which delivers the subscriber's `wrap(reply)` and waits for its answer, its end or its restart (§8.6), `tell_all/3`, `#waited_for{teller}`, held by the reaper as its deliveries are. Not `Telling`, which is §8.7's frame.
- **Telling**: §8.7's telling, the frame `{telling, Utilization, Interval}` a node sends each connected peer every `utilization-interval`, which it carries, and as a peer connects, the gateway's (`told/2`). The peer a compute that names none runs on is the one **picked** (`ern_peer:picked/0`). Not `Heartbeat`, `Gossip`, `Broadcast`.
- **Hash, Identity, Reach**: §8.7's hash of a definition, a binary of its SHA-256; a definition's identity, a hash or a qualified name with one; its reach, the definition with everything it references. Not `Digest`, `Closure`.
- **Unit, CodeTable**: a compiled module of the host's that holds definitions, and the table from each hash to its unit and function. Not `Module` for a unit.
- **Floor, CodeDigest, Cookie**: one major and minor release of `ern` on one OTP major, or a development build's digest of its own code, and the cookie that proves it. Not `Fingerprint`.
- **VersionText**: the toolchain's version text, `ern_release:version_text/0`, `-dev` marking a build that is no release. Not `Version`, which is a module's version in a session.
- **Version**: a module's version in a shell session (§11.2), counted from 1 at its first load, `versions` in the session; once a reload replaces it, the types it changed are its version's namespace's, `Counter$1`, a `VersionNamespace`, which the session's `previous` interfaces hold. A version is a **Unit** of its own, `ern@counter$2`, and each namespace's unit, where it is not the namespace's Erlang name, is held in `units`, in the shell and the emitter alike. A declaring input a reload compiles again has a version the same way, `ern@$input3$2`, its previous types under `$Input3$1`, printed as the input prints, `$Input5$1.Box`.
- **SiteNamespace**: the namespace a version's sites carry its number under, `Counter$2.service:5`, `site_namespace` in the build and the emitter, `site_namespace/2` in the shell.
- **Since, Md5**: the release a name appeared in (E.0 shape rule 6), and a unit's code as the host digests it. Not `Version` for either.
- **Spawned, Entry**: what a spawn frame names in place of a function (§8.7), the function's identity, its captures and `restarting`'s limit, `spawned()` in `ern_peer` and `spawned/2` in the emitter; a lambda's or a local fn's entry, the function of its unit that runs it over its captures, `'$N.P.entry'`, which `'$spawned'/2` calls (§11.1). Not `Closure`, `Thunk`.
- **Form**: a definition's canonical form (§11.1, Appendix H), which `ern_canonical` writes, its version `form_version`, a module's forms with their hashes and references its `Canonical`; a `#definition{}` holds a definition's form and hash as the `.erc` records them; an interface's `identities`, each definition's hash by its qualified name; a module's `references`, the other modules' definitions its forms name by hash, which the build compares (§11.1). The emitter's `Forms` are the host's abstract format, in the host's word. Not `Term`, nor `SchemeVersion`, since a **Scheme** is §3.9's.
- **FormNamespace**: the namespace a type's form holds its qualified name under, the module's own or, for a type a shell session declares, the session's one namespace, `$Session` (Appendix H, §11.2), `form_namespace` in the emitter's build and the canonical walk.
- **Sourced**: a form with the build's source woven in, `{'$at', Source, Node}` at a node, `Source` its `{Line, Column, Name}`, a `#definition{}`'s `sourced`, the emitter's input where the source is given, which `ern_canonical:stripped/1` takes out; `sourced/1` in the emitter reads a node's; the `.erc` and a code frame hold it with the locals' names left out, `{Line, Column, none}` (`ern_canonical:recorded_source/2`).
- **Recorded, Printing**: what a unit's compiled form records beside its code, `#recorded{}`: its definitions with their sourced forms, their names and their printing, what prints a type in a cause as the module writes it (§11.5), `{Namespace, Shadows}` as text, its foreign declarations with their schemes and printing, and its bindings' order, which `ern_canonical:read/1` gives, the code table keeps for a unit no file holds and `ern_code:forms/1` answers. Not `Annotated`, `Spanned`, `Chunk` for what it holds.
- **Position**: where a definition stands in its unit, its forms' order, a type taking one, then its foreign functions, by which its function is named, `'$N'` (§11.1), the interface's `positions`, `function_name/1` in the emitter; and Appendix H's positions, a group member's and a lambda's or a local fn's among its definition's, `'$N.P'` where a local fn is lifted. Not `Number`, `Index`, `Slot`, which are a local's number, a sequence's index and the shell's completion.
- **Link**: what a unit's forms reference outside it and where each is, `#link{}` (`ern_unit.hrl`), a function's `#linked{}`, its unit and its function, which `ern_compile` reads from the checker's environment for a build and from the session's interfaces for a compiled module the shell loads beside another unit of its name, and `ern_arrival` from the code table for an arrival; with the module's forms and what its build adds, the emitter's input, its `#unit{}`. A definition another unit's code can reach by its hash, a type or a function its unit exports, is **Linkable** (`ern_code:linkable/1`). Not `Env`, `Resolver`, `Imports`.
- **Placement**: how a module a load brings becomes a unit of the node's (§8.7, §11.2), `ern_code:placement/4`: `held`, a unit the node holds of the same code, `file`, its compiled form loaded as it is, or `forms`, a unit made from its forms, which `Code.load`'s `#placed{}` and the shell's `#compiled{}` record as `made`; the shell's state as it places a load's modules, each after those it uses, is its `#placing{}`. Not `Slot`, `Position`, which are the shell's completion and a definition's place in its unit.
- **Subscriber**: a process that called `Os.termination` (§8.6, E.23), waited for at the end. Not `Listener`, `Waiter`.
- **Host**: in a node's name on the carrier, the part after `@`, its key's digest as two labels, which `ern_carrier:host/1` makes and a certificate names (§8.7); in a peer's `network-address`, `host:port`, the name or address the peer is dialed at (§8.7), which `ern_node` reads and a **Machine**'s `host` gives; the runtime Ernest runs on is "the host" in prose and comments, never a variable. Not `Hostname`, `Domain`.
- **ConfigDir**: §11.3's configuration directory, `--config-dir`'s value, in the runner and the node module alike; what its `ernest.conf` says is a `#configuration{}`, and a peer it lists a `#peer{}`. Not `Dir`, `Conf`, `Config` alone.
- **Tree**: the toolchain's tree, the checkout or an installation's `lib/ernest`, which `ern_tree:tree/0` finds, and under its `build` the builds of the toolchain's own, `ern_tree:build/1`: the standard library's, the shell's and the libraries', which `ern_tree:libraries/0` lists for the load path's end. A unit of the standard library, the shell or the two libraries the shell is compiled against is the toolchain's own, which `ern_code:own_file/1` finds. Not `Root`, `Home`, `Install`.
- **LoadPath, SourceRoot, BuildRoot**: the load path, a source root and a build root (§11.1, §11.2). Not `Roots`, `Dirs`, `OutDir`, nor `Root` alone, which is a process's.
- **Root**: the process at the head of a process's spawn chain, which its row in `ern_processes` holds and `ern_rt:started_by/1` reads, so that what a shell load's evaluation started is known whatever code it runs (§11.2). Not `Spawner`, `Parent`. While `Code.load` evaluates bindings in the calling process, that process and what it starts have a **Mark** for their root, a reference, given back to the process's root as the evaluation ends (`ern_rt:rooting/0`, `rooted/2`, Appendix E.28).
- **Evaluator**: the process of the shell's own that a load or a reload evaluates a module's bindings in, which lives while the session runs (§11.2), `evaluators/0` in `ern_shell` and `evaluators()` in the shell; each is the **Root** of what its evaluation started. Not `Initializer`, `Loader`.
- **BuildsFunctions**: whether a module's code builds a function value, a fun of its own code that an expression or a supply emits and that may be held anywhere, which the emitter marks (`function_value/2`) and its interface chunk records, `builds_functions`, and by which the shell keeps an input (§11.2). Not `HasFuns`, `Closures`.
- **Calls**: the units a unit's code calls, which its `'$code'/0` lists last and its code-table row holds; with the unit itself and transitively, `ern_code:called/1`, the units a reach's bindings and foreign declarations are read in (§8.7). Not `Deps`, which are §8.5's declared dependencies.
- **Machine, Clone**: a computer the machines tools start nodes on (the log's *The Machines*), a line of `test/machines/machines.txt`, `ern_machine`: this one, `local`, whose commands run in the plain shell, or another, reached over ssh through one ssh connection held for the run, which holds a clone of the repository that only `git pull` and `make` write; a node made and run on one is an `ern_machine_node`. Not `Remote`, `Box`, `Server`.
- **Twin**: a program or a construct of the bench's written by hand in Erlang beside its Ernest, the same algorithm and no cleverness, which `make bench`'s language and programs parts time together and hold to one answer, `test/fixtures/bench/ern_*_twin.erl`. Not `Baseline`, `Reference`, which is the comparison's kept run.
- **WaitMs**: the harness's time for one wait, `ern_nodes_tests:wait_ms/0`, which bounds one step of a nodes test's and of an integration test's, a build, a run or a wait on a program, a test's limit its steps counted in it, `{waits, Count}` and `waits(Count)`, and which the programs the tests run give each of their waits, `Harness.waitMs()` under `test/fixtures/peers/` and `waitMs()` in a program a test writes.
- **Message**: a message, the Erlang variable; a mailbox type in Ernest ends in `Msg` as the guide says. Not `Msg` for the variable.

**Ernest**
