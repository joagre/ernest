# Style

The repository's own rules for its Erlang and its C, and where they differ from widely accepted guides: for Erlang, Ericsson's *Programming Rules and Conventions* (Eriksson, Williams and Armstrong) and Inaka's *Erlang Coding Standards & Guidelines*. What a program written in Ernest looks like is [`guide/style.md`](../guide/style.md)'s, installed with the guide; the repository's Ernest follows it too. Where the guides and this file differ, this file holds. A guide serves the reader and is not a law: a rule a test checks holds always, and where another would make the code read worse, judgment goes first. `test/ern_style_tests.erl` checks what is marked *(tested)*.

## Every language

A name in the Erlang and the C is chosen as [`guide/style.md`](../guide/style.md) says the standard library chooses one, spelled as each language spells a name, `parse_module` in Erlang, and the guide's rules of form, a function on one screen and a module with one job among them, hold for them too. The repository adds these:

- A step of indentation is four spaces, and no file holds a tab, but a Makefile *(tested)*.
- A line of code is at most 100 characters; prose in markdown may be longer *(tested)*.
- A paragraph of a tracked document is at most 150 words, a list item among them, which `tools/paragraphs.sh` lists at 150 and the test holds; the log, the proposals and the generated pages are left out, as the listing leaves them *(tested)*.
- A name in a namespace shared with other code carries the repository's name: an Erlang module begins `ern` *(tested)*, an Emacs Lisp symbol `ernest-`.
- The spelling test reads every tracked file of text but a proposal under `docs/proposals/`, a vendored file, `THIRD_PARTY_LICENSES` and `LICENSE` *(tested)*. A quotation keeps its author's spelling, and `-behaviour`, `LICENSE` and `prefers-color-scheme` are names of the host's or of another system's.
- `Acc`, for what a fold carries, is an abbreviation the report writes, beside the host's the guide allows.
- A record names what it holds, as the guide says of a type: `#emit_context{}`, not `#cx{}`. A function that gives a value made so is a past participle, `armed`, `held`. Longer names make longer code, and that is accepted.
- A value changing through a function is numbered, `Env1`, `Env2`, `env1` in Ernest, and a numbered name is nothing else; past two steps the function is split.
- A comment says why and cites the report section the code implements, `%% Report §8.4: ...`, `// Report §11.2: ...`; the names say what it does.
- A comment is paragraphs as a document is: a blank comment line, `%%` or `//` alone, stands between them, each says one thing, and none is past 150 words, the ceiling CLAUDE.md's *Writing* gives a document; a module's header keeps what a reader of the module needs and points at the design note for the rest, which lives there. `tools/comments.sh` lists the blocks past a hundred words for `make comments`, and the test holds them at the ceiling *(tested)*.

## Erlang

For the toolchain under `erl/`.

- **Every module is `ern_<thing>`**, `<thing>` unique across the repository and not repeating its application, which its directory names; a vendored file keeps its upstream name. A module compiled from Ernest is `ern@<namespace>`, the path with `@` for `/` (report §11.1): `src/stdlib/io.ern` is `ern@io`. The log's *One Token for the Project* says why.
- **One `-export` list at the top**, in the order the functions appear *(tested)*.
- **`-spec` on every exported function** *(tested)*, under `test/` as under `erl/`; a type shared between modules is a `-type` of its owner.
- **Every `receive` that can wait is named by its function under its kind**, in the module's `-receives` attributes after its `-export` list and its includes, `-receives({own_process, [loop/1]}).`, since the deadlock look reads a process that waits in the toolchain's own Erlang as one that waits as Ernest waits (report §8.6) *(tested)*. The kinds are the glossary's **Receives**. A `receive` with `after 0` waits on nothing and is named by none.
- **A shared record lives in `include/*.hrl`**, any other in its module. The only macros are the few constants that need a name.
- **Tokens and AST nodes are plain data**, records and tuples, never closures or ETS state. A value of more than three parts is a record, and so is a tuple of more than two that crosses modules: a positional tuple makes its reader count. A map whose keys are fixed is such a value, counted by its keys.
- **A precondition is `Cond orelse fail(...)` on one line**; two or more conditions are a `case`.
- **No OTP behavior for the toolchain's own processes, and no rebar3**; a callback module one of OTP's servers calls, a signal handler, is no such process. The log's *No OTP in the Toolchain* says why.
- **`make` compiles with `+debug_info -Werror`**: a warning is an error.
- **Tests are EUnit**, in `erl/<app>/test/`, or in `test/` when they span applications. A test module is `<module>_tests`, or names what it tests, `ern_grammar_tests`. A test function tests one behavior, is named after it, and has above it a comment naming what it tests: `%% report §x.y`, or a document's path.

## C

The runtime's helper, `erl/runtime/c_src/ern_exec.c`, is C99 and compiles with `-pedantic -Wall -Wextra -Werror`.

## Ernest

For every Ernest source and every Ernest block of the report and the guide. The layout is `ern format`'s (report §11.6), which `make test` holds every source to and `make format` restores, and the form and the names are [`guide/style.md`](../guide/style.md)'s, which the standard library, the shell and the examples follow, its block rule among them *(tested)*; the repository adds these, which bind its own Ernest and no program's:

- **A comment cites the report section the code implements**, `// Report §8.4: ...`, as the Erlang's does.
- **A name the report states changes only through the report**, and a new word that departs from the report's goes to the user first.

## Glossary

The names that recur across the toolchain's modules, one for each concept, in every module; the names of a program's are [`guide/style.md`](../guide/style.md)'s. A word is spelled as each language spells a name: `Descriptor` an Erlang variable, `descriptor` an Erlang function or field, an Ernest binding or parameter. The report is the authority: a concept it names takes its name. It grows as the code does, as CLAUDE.md says. A name not here is the writer's, under the rules above.

An entry gives the name, what it names and where the code holds it. The mechanism behind it is its component's design note's, [`design/runtime.md`](design/runtime.md), [`design/nodes.md`](design/nodes.md), [`design/code.md`](design/code.md) or [`design/shell.md`](design/shell.md), and the reasons are the log's.

**The compiler**

- **Span**: the source a node or a diagnostic's label covers (§11.5); a token's start is its `Position`. Not `Pos` for a span.
- **Diagnostic**: an error the toolchain reports, `#diagnostic{}` (§11.5); its text is its `Message`. Not `#diag{}`, `D`, `Error`, `Msg`.
- **Env**: the names in scope as the checker reads them, the word every Hindley-Milner text uses. Not `En`, `E`. The shell's session is a `Session`, the host's variables an `Environment`.
- **TypeState**: the checker's type variables and substitution, `#type_state{}`. Not `St`, `S`.
- **Substitution**: not `S`, `Sub`, `subst`; applying one is `substitute`, not `zonk`.
- **Context**: the emitter's, `#emit_context{}`, and nothing else. Not `Cx`, `C`. The formatter's state, the descriptor builder's, a message's prefix and a source line are each named for what they hold.
- **QualifiedName**: §4.2's qualified name. Not `Q`, `QName`, `TQ`, `CQ`.
- **Namespace**: §4.2's namespace, a qualified name's prefix among it, which the AST's `namespace` field holds; beside the module's own, which the checker's env holds, a name's is the `Namespace` and the module's the `OwnNamespace`. Not `Ns`, `Prefix`, `Path`, nor `Module` for a namespace.
- **Path**: §5.6's path in a record update, `#field_set{path}`, the segments after the field's name; a file's path is a `Path`, `SourcePath`, in the build and the runner alone. The indexes through a type's arguments to a variable, which a derived `compare` follows, are a `Route`.
- **Module**: an Ernest module (§4.1); the Erlang module it compiles to is its `ErlangModule`, `ern@io`, and a build's record of one a `#build_module{}`. Not `Mod`.
- **Interface**: a compiled module's interface (§11.1), `#interface{}`. Not `Iface`, `I`.
- **Constant, Ground, Term**: §4.6's constant, the initializer of a top-level binding whose every read is compiled to its value (§11.1), which the code's functions call ground, `ern_emitter:ground/2`; that value is the binding's term, the interface's `terms`, a `#linked{}`'s `term`, the code table's `{constant, Hash}` row, by the form's hash since one form is one value, with the getter of the unit that lists it (`ern_code:ground/1`, `grounded/1`), and the emitter's `grounds`; an exchange's reach crosses a constant as an identity (`ern_exchange:is_constant/1`). Not `Literal`, `Inlined`.
- **Shim, Raiseless**: E.0's shim of the `foreign fn` kind, a foreign function of the standard library's, by the host's module and function its declaration names, which the interface's and the checker's env's `shims` hold by its qualified name (`ern_typecheck:shim/2`), a `#linked{}`'s `shim` carries to a call site, and `ern_emitter:shim_call/4` calls there in place of the declaration's function (§11.1); a host function that raises nothing at the types the library declares it at is **raiseless**, `ern_emitter:raiseless/0`, called with no handler for its raise. Not `Host`, which is a node's, nor `Native`, `Bif`, `Inline`.
- **Cycle, Waiting**: §4.1's cycle among modules, which the build, the runner, `Code.load` and the shell refuse in the words of `ern_build:module_cycle/1`; the modules whose load, placing or reach waits on what they use are `Waiting`, and a module met again among them is in a cycle. Not `Users`, `Walking`, `Chain`.
- **PrivateTypes**: the private types an interface carries, those its module's exported declarations name, a mailbox type an exported function receives and a type an abstract type's fields name, with those theirs name (§4.2, §11.1), the `#interface{}`'s and the checker's env's `private_types`, which `described_type/2` reads and no name resolves to.
- **Scheme**: a type scheme (§3.9), as the code has it, and beside it a declaration's requirement (§4.9), which no instance has.
- **Annotation**: a type the source writes. Not `Ann`; an AST record's `type` field holds one of the four things it holds today, each named.
- **Effect**: the `receiving` part of a function type, a mailbox type or an effect variable, or `none` where the function type receives nothing (§3.9, §6.1, Appendix H). Not `E`, `Eff`, `EffT`, `MailboxT`, nor `pure` for none.
- **Constructor**: a constructor (§3.5, §5.6); many are `constructors`. Not `Cs`, `CI`, `cons`; `cons` is `::` alone.
- **MemberOf**: the type a member belongs to, `Stack` of `fn Stack.push` (§4.8), a declaration's `member_of`; of a requirement's `a.compare` (§4.9), the type variable `a`. Not `Owner`, which is a resource's process.
- **Member**: a type's member (§4.5), `compare`, `negate` or an operator, which no expression names, a written name that names one refused (`ern_typecheck:is_member_name/3`, which the shell's `:type` asks too); one a requirement names is a `#member{}`, and a derived compare's comparison of a field by its type's member, which the checker makes, an `#e_member{}`. Not `Method`, `Op`.
- **Requirement**: §4.9's requirement, a `fn` declaration's `needs`, its `#member{}`s; the enclosing declarations' in force are the checker's `requirement`. Not `Needs`, `Bounds`, `Constraint`, which is §3.10's equality constraint.
- **Supply**: what a requirement's member is supplied with at a use (§4.9), a `#known_member{}`, a tuple's compare, `#tuple_compare{}`, its components' supplies (§3.10), a `#required_member{}`, a `#shown_type{}`, whose `member` is `show` or `exposed`, or a service's `#service_type{}`, its message type known whole, a `#pending_member{}` until the definition ends; many are `supplies`. Not `Witness`, `Dictionary`, `Instance`.
- **Derives**: §3.5's `derives compare`, a type declaration's `derives`.
- **Restriction**: §3.9's inferred restriction; the two are `equality` and `process_only`, which a wait alone gives. Beside them the field `value_position` of `#type_variable{}` marks an effect variable that stands in a value position of a type its definition holds (`ern_types:value_positions_marked/2`), which no scheme holds. Not `flags`, `add_flag`, `eq`.
- **Unknown**: a type variable a failed definition's signature leaves open, `#type_variable{unknown}`, `ern_types:is_unknown/2`, which draws no error of its own at a use (§11.5). Not `Failed`, `Poisoned`.
- **Unfixed**: §6.2's mailbox type that nothing has fixed by the end of its definition, which is `Never`, `ern_types:unfixed/2`; the mailbox types a definition's spawns and computes were given, which its end reads, are the checker's `mailboxes` (`unfixed_mailboxes/2`). Not `Open`, `Free`, `Pending`.
- **Bound**: §3.11's type bound to its node, and what binds it, which `ern_bound:binds` answers: a function, a foreign type, a resource, or an address or a reply of a bound type. Not `Local`, `Pinned`, `Sendable`.
- **Capture**: a local a lambda's body names from around it (§3.11), in the bound check; many are `captures`. Not `Free`, `Closed`, `Env`.
- **ResultType**: §4.5's result type, and "result type" in every message. Not `ret`, `Ret`, `RetT`, `R`, "return type".
- **TypeVariable**: §3.9's type variable. A record's `vars` field is named for what it holds: a scheme's `quantified`, the type state's `variables`, the checker's `locals`.
- **Descriptor**: a type's description at run time, in the emitter, the boundary and the runtime alike. Not `D`, `Desc`, `desc`; its tag for `Address(m)` is `address`, not `pid`.
- **Token**: a token, many `Tokens`, what follows one `Rest`. Not `T`, `Ts`, `Toks`, `R`; `T` and `Ts` are a type and types in a one-line scope alone.
- **Declaration, Statement, Element, Segment, Alternative**: whole words. Not `Decl`, `Stmt`, `Elem`, `Seg`, `Alt`.
- **Doc**: §2.2's doc block, and nothing else; the pretty printer's document is named for what it lays out.
- **Fence**: a fenced code block of a doc block (§2.2), as CommonMark fences it, `#fence{}` (`ern_fence.hrl`), which `ern_parser:fenced/1` finds and the formatter and `ern test` read; its `language` is `ernest` for an example.

**The runtime and the command line**

- **Address**: §6.5's address. Not `Addr`, `To`, `A`; an IP address is an `IpAddress`, and `Target` is `adapted`'s target (§6.5) and a link's (E.17) alone.
- **Pid**: the host's process; the Ernest value is a `Process` (E.21).
- **ProcessNumber**: §12.5's process number, the operating system's number for a running program, which `ernest.pid` holds and a signal is sent to; the file's path is a `PidFile`. Not `Pid`, which is the host's process, nor `Process`, which is E.21's.
- **Reply**: §6.6's reply. Not `Alias`, `Written`, `R`.
- **Cause**: a fault's cause (§7.3). Not `Msg`, `Text`; the trace beside it is a `Trace`. A cause that names a function the boundary alone has, a function value's (§12.3, §8.4), is a **named cause**, `ern_descriptor:named_cause()`, the text before the name and the text after it, which the boundary's `named/2` and the emitter's `named_cause/2` write the name between.
- **Trace, Frame**: §7.3's trace, the host's stack as text, a frame a line (E.21), `ern_rt:trace/1`, and a **failure**'s, a fault whose cause names a host error (§7.4), `failure_trace/1`; the host's stack it is written from is a `Stack`, each of its entries written as a frame of the trace by `trace_line/1`, the frame a waiting process waits in among them (`waiting_frame/1`, §12.4), and an example's trace is read back as its frames (`ern_examples:frames/2`). A frame between nodes is §12.6's, the other meaning, the runtime's own (**Service, Offer, Frame**), which the carrier's modules send and read.
- **Fault, Met**: the runtime's record of a fault, `#fault{}` (`ern_rt.hrl`): its cause, its trace, the site of the callee a `callForever` carried it from and the name of the peer a compute carried it from (§6.6, §8.7), and the moment it was met (E.21), which `ern_rt:met/3` makes of a host error, a throw of the runtime's among them, and a process's row holds from its end to its report (`ended_with/2`); the host's term of that end is §12.2's `{ern, fault, Cause, Trace}`, which carries the cause and the trace alone. Not `ExitReason` for the record, nor `Error`.
- **Reason**: §9.3's `Reason`, and nothing else. The host's exit reason is an `ExitReason`, a host's error an `Error`. Not `Raw`, `How`.
- **Site**: §6.9's spawn site, a name and its line as `ern_namespace:site_text/2` writes them, as a trace's line of Ernest code is written too (E.21). Not `At`, `Where`.
- **Ms, Deadline**: milliseconds as given (E.0 shape rule 8) and the moment they end, as the code has them; a timer's message is `deadline` in every module.
- **Look, Key**: §8.6's look for a deadlock, `ern_rt:look/0`, and the look's keys in a process's own dictionary: `FOREIGN` (`entered_foreign/0`, `left_foreign/0`), `TIMED` (`timed/0`, `untimed/0`) and `CALL`, a call's callee and reply (`pending/2`, `uncalled/0`), which the look reads with the function on top of the process's stack (`still/1`); a function that is neither a unit's nor of the toolchain's own is the **host's** there (`is_ernest/1`). What each key marks, and who reads it, is the runtime's note's. Not `Mark`, which is a load's root, nor `Count`, `Flag`, `Counter`.
- **Expected**: a process `Test.faults` started, whose fault the test's answer carries, marked in its row's last field as it begins (`ern_rt:expected/1`, which `test.ern` declares), so that the reaper reports its fault to no job and tells no subscriber (E.21, E.24). Not `Judged`, `Quiet`.
- **LeftWaiting**: the lines of the processes a deadlock left waiting, a group of one site and one waiting frame a line, kept beside the process it faults and taken by its report (`ern_rt:left_waiting/1`, §12.4, §11.2). Not `Waiting`, which is a cycle's modules.
- **Killed**: an end the runtime gives a process from outside it, every one but the program's end, `ern_rt:killed/2`, which a kill frame asks of another node (§6.9, §12.6); its steps are the runtime's note's *A call, a restart, a kill*. Not `Terminate`, `Exit`.
- **Delivery**: a process of the runtime's own that carries one message to a recipient, a `Down`, an alarm, a fault's report or a subscriber's telling, with a row of `ern_deliveries` while it is on its way (`counted_link/3`, `delivered/2`), ended with its recipient's restart or end (`abandoned/1`) and waited for by the shell's end (`wait_for_deliveries/0`) (§6.9, §11.2). Not `Courier`, `Sender`.
- **Monitor**: §6.9's monitor, in the reaper as elsewhere. Not `await`, `watch`, `Waiters`. The host's reference to one is a `MonitorRef`, not `Watch`, `Mon`, `MRef`, `OwnerMonitor`. A **service monitor**, §6.9's, `ern_rt:monitor_service/2`, is a monitor the reaper holds as `#monitor{service = true}`, which a restart tells too (`delivered_restart/2`), a restart of a process of another node by the frames `restarted` and `watchers_told` (`ern_rt:peer_restarted/2`, **Asked**), each answer through an alias of the restarting process's once every delivery has ended (`told_once_delivered/2`); not `Service`, which is §8.7's.
- **Runner**: §11.2's runner, the process that starts the system processes and the entry point; the launcher is `bin/ern` alone. Not `Launcher`.
- **Say**: a function that writes a line of the toolchain's own on standard error: a node's, `ern_carrier:say/1` (§12.5), the end's wait, the runtime's `say/2` (§8.6), and what a job decided, `ern_build:verbose/2`, where `--verbose` asks (§11.1, §11.2); `ern_cli:error_line/1` is the job's device for such a line. A process that must not wait for standard error, the gateway, the check of a peer, a reload, **says later**, `ern_carrier:say_later/1`, `ern_rt:say_later/2`, through the process `ern_say_later`, which a launch's end and the job's wait for (`wait_for_later/0`). Not `Log`, `Print`, `Async`.
- **SystemProcess**: a system process (§8.2, §8.4). Not `Service`, `sys`; the report's service is §6.5's and §8.7's.
- **Receives**: a module's `-receives` attributes, each a kind and the functions whose `receive` waits so (§8.6): `foreign_wait`, a wait on what the look cannot see deliver, under the `FOREIGN` key; `ernest_wait`, a wait on what the look reads, one with a deadline under the `TIMED` key; `own_process`, a wait in a process that is no program's, which the look does not read; and `answered_at_once`, a wait on an answer that comes before the look can find it waiting. Not `waits`, which named the lists the keys replaced.
- **Run**: one execution of a restarting function's `f` (§6.9), a noun, and nothing else; a launch, a running program and a test are named as such. A test case's `run` (E.24) is the verb, the function the case runs.
- **Owner**: the process that opened a resource or was given it (§6.9, E.18), and nothing else; the type a member belongs to is its MemberOf.
- **Port**: E.18's port of a socket. A host port is named for what it runs: `Helper`, `Stty`.
- **EntryPoint, EntryProcess**: the entry point and its process (§8.1, §8.6). Not `Main`.
- **Carrier**: §12.5's carrier, the host's distribution as a node runs it, `ern_carrier`; its frames go through the **Gateway**, `ern_gateway`, and a worker for each peer. Not `Dist`, `Net`.
- **Dialed**: the host a dial dials, which the dialing process records in its dictionary, `ern_carrier:dialing/1`, as the port map answers, and which the check of the answering certificate reads, `dialed/0` (§12.5). Not `Target`, `Remote`.
- **Holder**: the process whose address is offered as a service, which a second offer answers as `Left(holder)` (E.27); the process that holds a source (`ern_held`) or the terminal is its `Holder` too, each in its own module.
- **Peer**: a node the configuration lists (§8.3), by its `Name` there, and by its name on the carrier, the host's `Node`, which `ern_peer` keeps beside it. Not `Remote`, `Other`. A process row's `Peer` field holds the carrier `Node` of the peer whose spawn started the process, or `none`.
- **Loss**: §8.7's loss of a peer's connection, which the gateway hands the peer's worker as `{lost, Order}`, `Order` the moment the gateway learned of it, and `ern_peer:lost/2` runs; what it ends is the nodes' note's *A loss*. Not `Down`, `Disconnect`, `Nodedown`, which is the host's message the gateway reads it from.
- **Idle, Taken**: the worker's ask that the gateway end it, `{idle, Node, Worker, Taken}`, `Taken` the gateway's messages it has taken, which the gateway counts as it hands them (`hand/3`); when it asks is the nodes' note's *The gateway and its workers*.
- **Exchange**: §12.7's exchange, its four frames `reach_request`, `reach`, `lacks` and `code_frame`, a **CodeFrame** one definition's form, or a group's, with what crosses beside it; the process of it on each node is the node's `Exchange`, `ern_exchange`, and what it carries is the code's note's *The exchange*. Not `Transfer`, `Sync`, `Fetch`, `Ship`, `Import`.
- **Arrival, Pool**: the unit the definitions of one exchange make on the node they arrive at, `ern_arrival`, named from the node's pool, `ern$1`, `ern$2` (`ern_arrival:name/1`).
- **Lacked**: what an arrival's definitions name beyond the spawned function's reach that the node lacks, each linked to one of the unit's lacked functions, `'$lacked_K'`, the unit's `lacked`. Not `Stub`, `Missing`.
- **BareNode**: §8.7's bare node, `ern run --config-dir dir` with no `.erc`, which holds no definition of a program's. Not `Empty`, `Worker`, `Blank`.
- **Service, Offer, Frame**: §8.7's service as its peers name it, `{'Service', Name, Hash}`, its name and its message type's `Hash`; an offer, a service's row in `ern_offers` and its process's in `ern_offered`; a frame of the runtime's, `{ern_frame, From, Body}`, which `ern_peer:frame/2` reads, the seventeen the runtime's note's *Nodes* lists, `{kill, Pid}`, `node_ends`, and a restart's `{restarted, Alias}` and `{watchers_told, Alias}` among them. Not `Key`, `Registration`, `Packet`.
- **Asked**: §8.7's restart across nodes, its two frames among the seventeen: the restart's ask of each other node with a process that monitors the restarting one (`ern_rt:watching_nodes/0`), the frame `{restarted, Alias}` to that node's gateway, which `ern_peer:restart_told/1` sends and answers as the alias and the watch of the gateway, the restart's `Asked`; and that node's answer, the frame `{watchers_told, Alias}`, sent by the `Answer` that `ern_rt:peer_restarted/2` calls once every delivery has ended, and the restarting node's gateway hands to the alias as `{watchers_told, Alias}`, a shape no call's wait takes, for `ern_peer:watchers_told/1`. Not `Told`, `Tellings`, nor a telling, which is the utilization's frame (**Telling**).
- **Maker**: the process that made an adapted address (§6.5), whose node applies its function. Not `Owner`, `Creator`.
- **Launch**: one run of the runner, `run_main/3`'s, and the reference that tags it, which the runner's messages carry and an adapted address holds beside its maker, `{adapted, Function, Target, Maker, Launch}` (§6.5, §8.7, §11.2); the one in progress is `launch/0`'s, and its main row of `ern_launch` is `#launch{}`, its `runner`, `tag`, `reaper`, `stderr`, `reporter`, `arguments`, `exit` and `node`. What its end does to an address is the nodes' note's *Addresses*. Not `Run`, which is §6.9's.
- **Acting**: what stands for a row in a process of the runtime's own that runs a program's function for another, a delivery, the terminal's courier and a process kept for an adapted address whose target is on this node, `#acting{}` in its dictionary (`acting_for/1`): its `recipient`, the process it acts for, the marks of the loads called in it, and the site of the binding they evaluate (§6.5, §6.9). What the recipient stands for there is the runtime's note's. Not `Proxy`, `Stand`, `Behalf`.
- **Kept**: the process a node keeps for an adapted address it made and a peer that sends to it, `ern_rt:kept/1` (§6.5, §12.6, §10); how it applies that peer's messages is the nodes' note's *Addresses*. Not `Applier`, which a `Down`'s process is as much (§10), nor `Relay`, `Proxy`, which is Appendix G.7's, `Adapter`.
- **Handed**: the messages handed to a kept process and not yet applied, a `#kept{}`'s `handed`; the worker for the peer holds a `#kept{}` for each address, its `pid`, its `monitor_ref` and its `handed`, in its `Kept`. Not `Waiting`.
- **Checker**: §8.4's process in front of an address exposed to foreign code, which checks each message the foreign side sends, one per address and mailbox type, `ern_checkers` and `ern_rt:checker_for/3`. Not `Proxy`, which is Appendix G.7's library, a proxy for a service.
- **Note**: the note of a call from another node, a row of `ern_notes` beside its row of `ern_callees`, its frames `call_waits` and `call_over`; an answer that lets a note go is `unnoted`. When each goes is the nodes' note's *Calls and computes across nodes*. Not `Ticket`, `Pending`, `Registration`.
- **Compute**: §8.7's compute, a function run on a peer for its value, its frame `compute`; the process on the peer is the compute's **Callee**, a row beside a call's. Not `Rpc`, `Remote`, `Call`, which is §6.6's.
- **Utilization**: how busy a node is on §12.8's scale, its frame `utilization`, and the `#configuration{}`'s `utilization`, `run_queue` or `schedulers`, how the node measures it, and its `utilization_interval`. This node's own readings of its measures are Appendix G.4's `Utilization` library. Not `Load`, which loads code, nor `Busy`.
- **Utilizations**: the utilizations a node holds of its peers, each its peer's last telling, in the gateway's `ern_utilizations` (`ern_peer:hold_utilization/3`, `drop_utilization/1`), which `Peer.utilizations()` answers; and the utilization a program sets with `Peer.setUtilization` (`ern_rt:set_utilization/1`, `program_utilization/0`).
- **Teller**: the process the end starts for each subscriber of `Os.termination` (§8.6), `tell_all/3`, `#waited_for{teller}`. Not `Telling`, which is §8.7's frame.
- **Telling**: E.27's telling, the frame `{telling, Utilization, Interval}` a node sends each connected peer every `utilization-interval`, the gateway's (`told/2`). The peer a compute that names none runs on is the one **picked** (`ern_peer:pick/0`). Not `Heartbeat`, `Gossip`, `Broadcast`.
- **Hash, Identity, Reach**: §8.7's hash of a definition, a binary of its SHA-256; a definition's identity, a hash or a qualified name with one; its reach, the definition with everything it references. Not `Digest`, `Closure`.
- **Unit, CodeTable**: a compiled module of the host's that holds definitions, and the table from each hash to its unit and function. Not `Module` for a unit.
- **Floor, CodeDigest, Cookie**: one major and minor release of `ern` on one OTP major, or a development build's digest of its own code, and the cookie that proves it. Not `Fingerprint`.
- **VersionText**: the toolchain's version text, `ern_release:version_text/0`, `-dev` marking a build that is no release. Not `Version`, which is a module's version in a session.
- **Version**: a module's version in a shell session (§11.2), counted from 1 at its first load, `versions` in the session; once a reload replaces it, the types it changed are its version's namespace's, `Counter$1`, a `VersionNamespace`, which the session's `previous` interfaces hold. A version is a **Unit** of its own, `ern@counter$2`, held in `units` where it is not its namespace's Erlang name, in the shell and the emitter alike; a declaring input a reload compiles again has a version too, `ern@$input3$2`, its previous types under `$Input3$1`. How a reload brings it is the code's note's *Units, placement and versions*.
- **SiteNamespace**: the namespace a version's sites carry its number under, `Counter$2.service:5`, `site_namespace` in the build and the emitter, `site_namespace/2` in the shell.
- **Since, Md5**: the release a name appeared in (E.0 shape rule 6), and a unit's code as the host digests it. Not `Version` for either.
- **Spawned, Entry**: what a spawn frame names in place of a function (§12.6), the function's identity, its captures and `restarting`'s limit, `spawned()` in `ern_peer` and `spawned/2` in the emitter; a lambda's or a local fn's entry, the function of its unit that runs it over its captures, `'$N.P.entry'`, which `'$spawned'/2` calls (§11.1). Not `Closure`, `Thunk`.
- **Form**: a definition's canonical form (§11.1, Appendix H), which `ern_canonical` writes, its version `form_version`, a module's forms with their hashes and references its `Canonical`; a `#definition{}` holds a definition's form and hash as the `.erc` records them; an interface's `identities`, each definition's hash by its qualified name; a module's `references`, the other modules' definitions its forms name by hash. The emitter's `Forms` are the host's abstract format, in the host's word. Not `Term`, nor `SchemeVersion`, since a **Scheme** is §3.9's.
- **FormNamespace**: the namespace a type's form holds its qualified name under, the module's own or, for a type a shell session declares, the session's one namespace, `$Session` (Appendix H, §11.2), `form_namespace` in the emitter's build and the canonical walk.
- **Sourced**: a form with the build's source woven in, `{'$at', Source, Node}` at a node, `Source` its `{Line, Column, Name}`, a `#definition{}`'s `sourced`, which `ern_canonical:stripped/1` takes out and `sourced/1` in the emitter reads; as the `.erc` and a code frame hold it, `ern_canonical:recorded_source/1`, and with a session's lines, `session_source/2`.
- **Recorded, Printing**: what a unit's compiled form records beside its code, `#recorded{}`: its definitions with their sourced forms, their names and their printing, what prints a type in a cause as the module writes it (§11.5), its foreign declarations with their schemes and printing, and its bindings' order, which `ern_canonical:read/1` gives and `ern_code:forms/1` answers. Not `Annotated`, `Spanned`, `Chunk` for what it holds.
- **Position**: where a definition stands in its unit, by which its function is named, `'$N'` (§11.1), the interface's `positions`, `function_name/1` in the emitter; and Appendix H's positions, a group member's and a lambda's or a local fn's among its definition's, `'$N.P'` where a local fn is lifted. Not `Number`, `Index`, `Slot`, which are a local's number, a sequence's index and the shell's completion.
- **Link**: what a unit's forms reference outside it and where each is, `#link{}` (`ern_unit.hrl`), a function's `#linked{}`, its unit and its function, which `ern_compile` and `ern_arrival` make; with the module's forms and what its build adds, the emitter's input, its `#unit{}`. A definition another unit's code can reach by its hash, a type or a function its unit exports, is **Linkable** (`ern_code:linkable/1`). Not `Env`, `Resolver`, `Imports`.
- **Placement**: how a module a load brings becomes a unit of the node's (§8.7, §11.2), `ern_code:placement/4`: `held`, a unit the node holds of the same code, `file`, its compiled form loaded as it is, or `forms`, a unit made from its forms, which `Code.load`'s `#placed{}` and the shell's `#compiled{}` record as `made`; the shell's state as it places a load's modules is its `#placing{}`. Not `Slot`, `Position`, which are the shell's completion and a definition's place in its unit.
- **Subscriber**: a process that called `Os.termination` (§8.6, E.23), waited for at the end. Not `Listener`, `Waiter`.
- **Host**: in a node's name on the carrier, the part after `@`, its key's digest as two labels, which `ern_carrier:host/1` makes and a certificate names (§12.5); in a peer's `network-address`, `host:port`, the name or address the peer is dialed at (§12.5), which `ern_node` reads and a **Machine**'s `host` gives; the runtime Ernest runs on is "the host" in prose and comments, never a variable. Not `Hostname`, `Domain`.
- **ConfigDir**: §11.3's configuration directory, `--config-dir`'s value, in the runner and the node module alike; what its `ernest.conf` says is a `#configuration{}`, and a peer it lists a `#peer{}`. Not `Dir`, `Conf`, `Config` alone.
- **Tree**: the toolchain's tree, the checkout or an installation's `lib/ernest`, which `ern_tree:tree/0` finds, and under its `build` the builds of the toolchain's own, `ern_tree:build/1`, the libraries' listed by `ern_tree:libraries/0`. A unit of the standard library, the shell or the two libraries the shell is compiled against is the toolchain's own, which `ern_code:own_file/1` finds. Not `Root`, `Home`, `Install`.
- **LoadPath, SourceRoot, BuildRoot**: the load path, a source root and a build root (§11.1, §11.2). Not `Roots`, `Dirs`, `OutDir`, nor `Root` alone, which is a process's.
- **Root**: the process at the head of a process's spawn chain, which its row in `ern_processes` holds and `ern_rt:started_by/1` reads (§11.2). Not `Spawner`, `Parent`. While `Code.load` evaluates bindings in the calling process, that process and what it starts have a **Mark** for their root, a reference (`ern_rt:rooting/0`, `rooted/2`, Appendix E.28).
- **Evaluator**: the process of the shell's own that a load or a reload evaluates a module's bindings in (§11.2), kept in `ern_shell`'s table under `evaluators`; each is the **Root** of what its evaluation started. With the input that runs, they are the shell's **own** processes beside its chain, `ern_shell:own/0`, which the shell's launch gives the runtime (`#launch{}`'s `own`) and `Process.live()` leaves out (`ern_rt:processes/0`). Not `Initializer`, `Loader`.
- **BuildsFunctions**: whether a module's code builds a function value, a fun of its own code that may be held anywhere, which the emitter marks (`function_value/2`) and its interface chunk records, `builds_functions` (§11.2). Not `HasFuns`, `Closures`.
- **Calls**: the units a unit's code calls, which its `'$code'/0` lists last and its code-table row holds; with the unit itself and transitively, `ern_code:called/1` (§8.7). Not `Deps`, which are §8.5's declared dependencies.
- **Machine, Clone**: a computer the machines tools start nodes on (the log's *The Machines*), a line of `test/machines/machines.txt`, `ern_machine`: this one, `local`, or another, reached over ssh, which holds a clone of the repository; a node made and run on one is an `ern_machine_node`. Not `Remote`, `Box`, `Server`.
- **Twin**: a program or a construct of the bench's written by hand in Erlang beside its Ernest, the same algorithm and no cleverness, which `make bench`'s language and programs parts time together and hold to one answer, `test/fixtures/bench/ern_*_twin.erl`. Not `Baseline`, `Reference`, which is the comparison's kept run.
- **Step**: a step of a test, each wait the harness runs, a node's line, its end, what it said, a command's or a bare `erl`'s run, a build, and a terminal session's expect and its end, which the harness's own wait functions take as they run it (`ern_nodes_tests:step/1`) against the test's count, `{waits, Count}`, which `nodes_test/2` and `counted_test/2` set and read at the test's end. Not `Stage`, nor `Wait`, which is what waits for a node's end.
- **WaitMs**: the harness's time for one wait, `ern_nodes_tests:wait_ms/0`, which bounds a step, in which a test's limit is counted, and which the programs the tests run give each of their waits, `Harness.waitMs()` under `test/fixtures/peers/` and `waitMs()` in a program a test writes.
- **Message**: a message, the Erlang variable; a mailbox type in Ernest ends in `Msg` as the guide says. Not `Msg` for the variable.

**Ernest**

The names are [`guide/style.md`](../guide/style.md)'s, with the spellings its glossary refuses; one met in the repository's Ernest is corrected to the guide's name. Beside them, the names that recur across the shell's modules:

- **cursor**: the place in the line being typed, in `Shell`, `Shell.Editor`, `Shell.Region` and `Shell.Complete`. Not `at`.
- **serial**: the number the shell gives an input, which its outcome carries, in `Shell` and in its front end, `ern_shell`'s `Serial`. Not `run`, `n`.
- **color**: whether the shell colors what it says, a `Markdown.Output`, in `Shell` and `Shell.Style`.
- **rows**: the rows the live region's tail is given, which `:set rows n` sets, in `Shell` and `Shell.Region`: the setting, the region's field, `SetRows` and `rowsSized`. Not `height`, `outputRows`.
- **typedWord**: the word typed before the cursor, which completion completes, in `Shell` and `Shell.Complete`.
