Library

A page holds a module's opening, then its declarations, each with its type and its own description and examples. Where Ernest is installed, man Ernest.List shows the same page at the terminal.

The standard library

  • PreludeThe names every module has without writing a module's name.
  • BoolOperations on Bool, the type of true and false.
  • BytesSequences of bytes, as a file or a socket holds them.
  • CharCharacters: one Unicode scalar value each.
  • ClockThe time, alarms, and the wait for a time.
  • CodeA node's code after its start: a compiled module loaded by the program, a module's definitions by their hashes, and the processes running a function.
  • EitherOperations on a value or the cause of its absence, Either(e, a): Right(a), the value, or Left(e), the cause.
  • FloatFloating-point numbers, always finite.
  • ForeignValues from foreign code: asking what a Term is, and making one.
  • FsFiles and directories.
  • IntIntegers of any size.
  • IoPrinting, and reading standard input.
  • ListLists: values in order, the same type throughout.
  • MapFinite maps from keys to values, the prelude's type Map(k=, v).
  • OptionalOperations on a value that may be absent, Optional(a): Some(a) or None.
  • OrderedMapMaps whose entries are kept in the order of their keys, the order of the key type's compare.
  • OrderedSetSets whose elements are kept in order, the order of their type's compare.
  • OsThe host: the program's command line, its environment and exit status, and other programs run from it.
  • PathFile system paths: building them, and taking them apart.
  • PeerOther nodes: a service offered to this node's peers, found on a peer, a process started on one, a function run on one for its value, and how busy each is.
  • ProcessProcesses as values: telling them apart, and seeing what the runtime runs.
  • RandomPseudo-random numbers, drawn from a seed the program carries.
  • SetFinite sets: each element once, in no order.
  • StringText: Unicode strings, held as UTF-8.
  • SupervisorA group of processes, restarted together when one of them faults.
  • TcpTCP connections: listening for them, making them, and moving their bytes.
  • TerminalThe terminal read key by key, its size, and the columns text takes on it.
  • TestTests, which ern test runs.

The libraries

  • AnsiStyles and cursor movement for text written to a terminal.
  • Base64Bytes written as text in the base 64 encoding of RFC 4648, and the text read back as the bytes.
  • CryptoThe SHA-1 digest of bytes, and bytes from the host's strong random source.
  • EtsTables that live in the runtime, outside any one process.
  • HttpHTTP/1.1's messages as RFC 9112 writes them: a request's or a response's head read from bytes or from a socket, the body after it, and a head and a body written, with RFC 9110's dates and status phrases.
  • JsonJSON text, read into a value and written from one, as RFC 8259 defines it, by the host's json module.
  • MarkdownMarkdown documents, read and laid out as text for a terminal or as a manual page.
  • ProxyA proxy for a service a peer offers: one address for the service across its end and its return.
  • TimeThe civil calendar: the date and the time of day of a time, in UTC, and the time of a date and a time of day.
  • UtilizationHow busy this node is, by the host's measures: the processes waiting to run, the schedulers' time, and the processor, the memory and the disks the host's services watch.

ern, the toolchain and its shell, is the report's §11, which man ern shows.
