The tour

The Importance of Being Ernest, a Trivial Comedy for Serious People

Ernest in an evening: one program, a counter, grown through eight chapters from a process with a typed mailbox to the same counter on a node started with none of its code, moved to new code there. It is for the programmer who has used a functional language and will read neither the report nor the guide first. Every rule the tour meets is the guide's, Programming in Ernest, or the deployment guide's where the operator's world is met, and the tour names the section, or the report's where no guide states the rule. What the program has just done that your language cannot, the tour says where it happens, naming the claim of Why Ernest it meets.

An hour to read, and about three to do along, with ern installed as the README says and five terminals: your own, the shell's, from chapter 2 one for each of two nodes, and in chapter 8 one for a shell attached to a node. Each chapter is a change to the program, then what was typed and what was printed, then a few sentences.

The directories tour/1/ to tour/8/ hold the program as it stands at the end of each chapter, each a program of its own, so a chapter's build and tests run from its directory alone. Work in a directory of your own, make the nodes' directories in it, and copy a chapter's files into it as the chapter begins. From chapter 2 on the shell you started runs to the end: the sessions of chapters 2 to 8 are one session, chapter 8's attached shell beside it, so a reader who starts at chapter 5 types chapters 2 to 4 first.

  1. 1. The counter

    a process with a typed mailbox, and a wrong message and a wrong mailbox refused

  2. 2. Two bare nodes

    the same counter on a node that holds none of its code

  3. 3. The client

    a function that reads a line, and a quiet reload

  4. 4. A fault

    a process ended, a restart that keeps the address, a watcher told

  5. 5. Per key

    an abstract type with a requirement, a test, a deadlock found, and a protocol refused across versions

  6. 6. The door

    the message by which new code will reach the counter

  7. 7. Work anywhere

    a host question checked at the crossing, and work placed on whichever node has room

  8. 8. The fix

    the counters moved to new code with their tallies kept, foo's from a shell attached to it, and a node's end
