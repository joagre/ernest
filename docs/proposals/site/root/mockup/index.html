Typed processes, on the Erlang runtime

Ernest is a functional language for concurrent programs. A process receives messages of one type, which the compiler checks every send against, and a process started on another node brings its code along. Functions and processes are the whole language, and a report of three files defines it. Why it is so is the whole argument.

What Ernest adds

  1. The mailbox in the function's type. Every process receives messages of one type, which a function that receives names in its own type and a process's address carries.
  2. Code known by its hash. A function or a type is known by a hash of its definition, not by the name of the module it stands in.
  3. A distribution built for a WAN. A node lists its peers in a file, each by name, public key and address, accepts a connection only from a key it lists, and opens one TLS connection to a peer when it first needs it.
  4. Abstract types and requirements. A type declared abstract keeps its constructor to its own module, so the representation can change and no caller knows.
  5. A deadlock is found. A program in which every process waits for a message none can send ends with a fault and a trace under ern run and ern test, where the host would wait forever.
  6. Little else. Functions and processes are the whole language, with one way to do each thing.

For programs written in it

Ernest is for programs written in it from the start: a server, a service spread over machines, a tool. A program reaches Erlang's libraries through declarations that give them Ernest types. A counter, its mailbox in the type of the loop it runs:

type CounterMsg = Inc(Int) | Get(Reply(Int))

fn count(total : Int) : Unit receiving CounterMsg =
    receive {
        Inc(amount) ->
            count(total + amount)
      | Get(reply) -> {
            answer(reply, total);
            count(total)
        }
    }
$ ern shell
Ernest 0.9.0, session 1. :help for the commands, :quit to leave.
> let counter = spawn(fn() = count(0))
counter : Address(CounterMsg)
> send(counter, Inc(5))
> Address.call(counter, Get, 1000)

> send(counter, "five")
