Start a process on another node, and its code goes with it

The node is sent the code it lacks, and nothing of the program is installed there first. Ernest is a functional language for concurrent programs, on the Erlang runtime. It is for programs written in it from the start, a server, a service spread over machines, a tool, and it reaches Erlang's libraries through declarations that give them Ernest types. Why Ernest is made so is the whole argument.

What Ernest adds

  1. Code goes where it runs. A process started on another node brings its code along, and a module keeps every version it has had: each function is known by a hash of its definition, not by the module it stands in.
  2. The mailbox in the function's type. Every process receives messages of one type, which a function that receives names in its own type and a process's address carries.
  3. A distribution built for a WAN. A node lists its peers in a file, each by name, public key and address, accepts a connection only from a key it lists, and opens one TLS connection to a peer when it first needs it.
  4. A deadlock is found. A program in which every process waits for a message none can send ends with a fault and a trace under ern run and ern test, where the host would wait forever.

A counter on another node

The counter's code is typed into the shell, and foo is a second node beside it that has none of that code:

type CounterMsg = Inc(Int) | Get(Reply(Int))

fn count(total : Int) : Unit receiving CounterMsg =
    receive {
        Inc(amount) ->
            count(total + amount)
      | Get(reply) -> {
            answer(reply, total);
            count(total)
        }
    }
$ ern shell --config-dir a
Ernest 0.9.0, session 1. :help for help.
> let far <- Peer.spawn("foo", fn() = count(0), 5000)
the peer foo connected
far : Address(CounterMsg)
> send(far, Inc(5))
> Address.call(far, Get, 1000)
Some(5) : Optional(Int)
