A functional language on BEAM

Typed mailboxes. Code by its hash. Built for a WAN.

Ernest puts the types of ML, which Gleam made ordinary on the Erlang runtime, and Unison's small core with its code known by its hash on Erlang's processes, with a distribution built for a WAN. Start with the tour, read the guide, or open the report.

The mailbox in the type

A process receives one type of message, and the function it runs says which. Every send is checked against the mailbox it reaches.

type CounterMsg = Inc(Int) | Get(reply : Reply(Int))

fn count(total : Int) : Unit with CounterMsg =
    receive {
        Inc(amount) -> count(total + amount)
      | Get(reply = reply) -> {
            answer(reply, total);
            count(total)
        }
    }

let counter = spawn(fn() = count(0));
send(counter, Inc(5));
send(counter, "increment")   // refused: expected CounterMsg, found String

What to look for

The mailbox in the function's type
A function that receives says which type, and every send and receive is checked against it.
Code known by its hash
A module has every version it has had; a spawn carries its code to a peer that lacks it, so a bare node can run anything.
A distribution built for a WAN
Peers listed by key, one TLS connection when needed, no mesh and no port mapper.
Little else
Two concepts, five principles, one way for each thing, and a report of three files.
