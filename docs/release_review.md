# The review before a release

What a release runs to be ready, and nothing else. Between releases a change runs `make test` before the commit that closes its plan item (CLAUDE.md, *Tests*). The plan says when a review runs; each finding is fixed, planned, or dropped, and the commit messages say which. A full review, every reader over the whole of its area, runs seldom, as [`full_review.md`](full_review.md) says.

1. **A fresh clone builds and passes:** `git clone`, then `make` and `make test`, in a directory of its own. `make test` installs into a scratch prefix and from the release archive, and runs from there (`installation_test_`, [`install.md`](../proposals/install/install.md)).
2. **Six machines:** `make dialyzer`; `make sanitize`, the helper in C under Clang's analyzer and the sanitizers; `make load`, the loads of [`memory.md`](memory.md); `make service`, a program started, stopped and started again by the host's service manager, whose launchd checks, written for macOS in MVP 2.99b's item 10, run on the first Mac at hand and until then the release's notes say they have not; `make sections`, which names a section of the report no test cites, and names only a section of a milestone not yet built, which that milestone's item names; and `make bench`, three runs with the machine idle, the median of each row's ratio to Erlang's no worse than the rows the log last recorded, which the log's entry for this review then holds.
3. **The readers** of [`full_review.md`](full_review.md), run as it runs them, with its briefs:
   - **The report:** K and P, the cold reader and the principles, as one reader.
   - **A newcomer:** N, with a program no earlier newcomer wrote.
   - **The code:** C, E and S as one reader, over what changed in `erl/`, `stdlib/`, `shell/` and `libs/` since the last release, or since the last full review where that is later.
   - **The guide:** U, when a rule of the report changed since the last release, over the sections of the guide that teach what changed.
   - **The argument:** the report's reader, when a rule [`soundness.md`](soundness.md) covers changed since the last release, over the argument's paragraphs for those rules beside the report's sections: every step that does not follow from the rule it cites.
4. **The findings:** a defect is fixed, or planned in a milestone; clarity is fixed where it is cheap, and otherwise dropped.
5. **The release:** `VERSION` set to the release's version; every module of `stdlib/` and `libs/` that appeared since the last release, and every exported declaration that did, ending its doc block with its own `since` (Appendix E.0 shape rule 6, whose shape and versions `make test` holds); the pages `make pages` writes into `man/`, committed with the release; the notes; the tag; and the archive `make release` writes, `ern-VERSION.tar.gz`, published beside it. The notes list none of the changes (the log's *A Release Carries No History*). They say what the release is, by its milestone in the plan; that until 1.0 a release may refuse a program the previous release accepted (the plan's MVP 3.9), and that the release's report is what holds; where what changed is read, the report's diff between the last release's tag and this one's, `git diff v0.2.0 v0.3.0 -- report/` for 0.3.0, and why, the log's entries since the last release; what the review did not run; and the newcomer's program.

**The models.** Two models serve a review, the most advanced there is and the one below it, as [`full_review.md`](full_review.md)'s *The models* says. The machines need none. The report's reader runs on the most advanced, since it judges rules against §0, reads cold for what a builder would guess, and reads the argument for a step that does not follow; the newcomer, the code's reader and the guide's run on the one below. Of the findings, a design question or a sentence of the report takes the most advanced, and a named fix and the release itself the one below.
